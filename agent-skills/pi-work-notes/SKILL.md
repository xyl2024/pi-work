# pi-work-notes

Pi Work 的「笔记」面板是一块全局的个人笔记板（不绑定任何项目或会话）：就是磁盘上的一堆普通 Markdown 文件。**没有专门的笔记工具**，你直接用 `read` / `write` / `edit` / `grep` / `glob` / `bash` 操作这些文件即可。

## 笔记在哪里

- 根目录：`~/.pi-work/user-notes/`（展开即 `/home/<user>/.pi-work/user-notes/`）。
- 如果环境里设置了 `PI_WORK_DATA_DIR`，根目录是 `$PI_WORK_DATA_DIR/user-notes/`。不确定时先 `bash: echo "${PI_WORK_DATA_DIR:-$HOME/.pi-work}/user-notes"` 确认真实路径，再用绝对路径操作。
- 内容形态：任意层级的文件夹 + `.md` 文件。**只有 `.md` 与文件夹会被笔记面板展示**：
  - 以 `.` 开头的文件/目录不可见；
  - `<名字>.assets/` 是笔记的图片附件目录，不可见。
- 笔记文件名规则（面板侧校验）：不能包含 `/`、`\`、`:`，不能是 Windows 保留名（`con`/`prn`/`aux`/`nul`/`com1-9`/`lpt1-9`），名字总长不超过 255 字节。中文、空格、`-`、`_` 都可以用。

典型结构：

```
~/.pi-work/user-notes/
├── 随手记.md
├── pi work.md
└── 项目/
    ├── 想法.md
    └── 想法.assets/        # 想法.md 的图片附件（面板隐藏）
        └── 1737000000000-diagram.png
```

## 图片与附件

- 图片放**同级**的 `<笔记名>.assets/` 目录里，引用时用相对于当前笔记所在目录的路径：

  ```markdown
  ![架构图](./想法.assets/1737000000000-diagram.png)
  ```

- 不要写绝对路径、`file://` 或 `/api/notes-file?...`。`https://` 外链可以直接用。
- 面板上传图片时会自动落到 `<stem>.assets/`；你一般不需要自己往里写文件，只在用户明确要求"把这张图插进笔记"时，用 `cp` 把图片复制进对应 `.assets/` 目录再写引用。
- **不要把二进制内容塞进 `.md`**（不要 base64 内联图片）。

## 硬性规则

1. **改之前先读**。任何修改前先 `read` 目标笔记，确认当前内容和标题层级；笔记是用户手写的，不要凭记忆或猜测重写。
2. **优先 `edit` 局部修改**，不要用 `write` 整篇覆盖。整篇覆盖只用于：用户明确要求重写，或新建笔记时写入初稿。
3. **新建笔记**：直接 `write` 一个新 `.md` 文件即可（父目录不存在就先建目录）。文件名用能表达内容的短标题；不确定时先问用户，不要用 `未命名.md` 批量制造垃圾文件。
4. **删除要极其克制**。默认不删任何笔记/文件夹；只有用户明确说删除时才能删。删一篇笔记时必须**同时删掉同级的 `<stem>.assets/`**，否则会留下孤儿附件。
5. **改名/移动不要用 `mv`**。直接 `mv foo.md bar.md` 不会带走 `foo.assets/`，笔记里的图片引用会**静默失效**。需要改名或移动时：告诉用户在笔记面板里用「重命名 / 移动到」完成（面板会同步搬运附件目录）；如果用户坚持要你用命令行做，就必须把 `<stem>.assets/` 一起 `mv` 过去，并检查笔记正文里的相对引用路径是否需要同步修改。
6. **不要碰**点开头的文件/目录、`.assets/` 内部已有文件（除插入图片外）、以及 `~/.pi-work/` 下的其它任何目录（会话、数据库、配置都不是你的操作对象）。
7. **grep / glob 要限定 `.md`**。直接对整个笔记目录做 grep 会扫进 `.assets/` 里的图片二进制，既慢又刷屏。例如按内容找笔记时用 `grep -rn --include='*.md' "关键词" ~/.pi-work/user-notes`。
8. 一次不要写入特别大的内容（比如把几 MB 的日志整段塞进笔记）。长内容先问用户要不要拆成多篇。

## 用户在面板里可能同时在编辑

- 面板是**客户端自动保存**：编辑后约 600ms 写盘；`Cmd/Ctrl+S` 立即保存。
- 面板**不会自动感知**你的磁盘改动：你写完文件后，用户面板里可能仍显示旧内容，直到他手动刷新/切走再切回。可以在回复里顺带提一句"面板切一下就会看到新内容"。
- 反向风险更大：如果用户面板里有**未保存的编辑**，你的写入会被面板随后的自动保存覆盖（后者胜）。所以：修改用户**当前正在编辑**的笔记前，在回复里提醒一句"如果你面板里还有没保存的改动，先保存一下，否则会被我这边的写入覆盖"。
- 保存失败/内容对不上时，先 `read` 一次磁盘真实内容再判断，不要假设面板显示的就是磁盘内容。

## 常见任务示例

- **追加一条记录**：`read` 目标笔记 → `edit` 在末尾追加一段（保持标题层级与既有格式一致）→ 回一句"已追加到 xxx.md"。
- **新建一篇**：`write ~/.pi-work/user-notes/2026-02-14 会议纪要.md`，用一级标题 + 正文起稿。
- **查找**：先按文件名 `glob "**/*关键词*.md"`，再按内容 `grep -rn --include='*.md'`；找到后 `read` 确认再回答。
- **整理**：先用 `glob` 列出全部 `.md`，读几篇确认风格，改动前把计划告诉用户；涉及改名/移动就请用户在面板里操作。
- **汇总**：把多篇笔记的要点合并成一篇新笔记时，只读需要的文件，不要无脑读整个目录。
