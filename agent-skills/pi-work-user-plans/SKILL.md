# pi-work-user-plans

Pi Work 的「计划」面板是用户自己的个人计划清单（不绑定任何项目或会话，也不是给 agent 用的任务列表）：就是磁盘上的一堆普通 Markdown 文件。**没有专门的计划工具**，你直接用 `read` / `write` / `edit` / `grep` / `glob` / `bash` 操作这些文件即可。

一条计划 = 一个 Markdown 文件。**时间锚点只写在文件名里**（这是唯一真值），frontmatter 只记完成状态与时间戳，正文是备注。

## 计划在哪里

- 根目录：`~/.pi-work/user-plans/`（展开即 `/home/<user>/.pi-work/user-plans/`）。
- 如果环境里设置了 `PI_WORK_DATA_DIR`，根目录是 `$PI_WORK_DATA_DIR/user-plans/`。不确定时先确认真实路径，再用绝对路径操作：

  ```bash
  echo "${PI_WORK_DATA_DIR:-$HOME/.pi-work}/user-plans"
  ```

- 布局（**只有 `inbox/` 与 `YYYY-MM/` 目录会被面板读取**）：

  ```
  <数据根>/user-plans/
  ├── inbox/<标题>.md                  # 收件箱：还没排期（无锚点）
  ├── YYYY-MM/YYYY-MM-DD-<标题>.md     # 日锚点
  ├── YYYY-MM/YYYY-MM-DDW-<标题>.md    # 周锚点，日期 = 该周周一
  └── YYYY-MM/YYYY-MM-M-<标题>.md      # 月锚点
  ```

- 日 / 周 / 月锚点的文件都放在**锚点所属月份**的目录里；周锚点跨月时归属到**周一所在的月份**（如 9/28 周覆盖 9/28–10/4，文件放 `2026-09/`）。
- 点开头的文件 / 目录不可见（面板的原子写临时文件也以 `.` 开头，不用管）。
- 只认 `.md`。根目录下散落的 `.md`（不属于 `inbox/` 或 `YYYY-MM/`）会落进面板的「待整理」区；未知目录、非 `.md` 文件则被完全忽略。

## 文件名 = 锚点 + 标题

标题是**文件名前缀之后的部分**（去掉 `.md`），frontmatter 里**没有** `title` 字段：

| 形态 | 例子 | 含义 |
| --- | --- | --- |
| `inbox/<标题>.md` | `inbox/修水管.md` | 无锚点，收件箱 |
| `YYYY-MM/YYYY-MM-DD-<标题>.md` | `2026-09/2026-09-15-去办居住证.md` | 日锚点：那天做 |
| `YYYY-MM/YYYY-MM-DDW-<标题>.md` | `2026-09/2026-09-28W-整理书架.md` | 周锚点：那一周（周一–周日）做 |
| `YYYY-MM/YYYY-MM-M-<标题>.md` | `2026-09/2026-09-M-读完一本书.md` | 月锚点：那个月做完 |

规则：

- `W` / `M` 标记必须紧跟在日期后面、用 `-` 连接标题（`2026-09-28W-整理书架.md`、`2026-09-M-读完一本书.md`），**不能丢标记、不能加空格**。
- 周锚点的日期必须是**那一周的周一**，不是周内任意一天；跨月周按周一算归属月（所以「8 号那周」如果周一在 9 月，就放 9 月目录）。
- 目录名必须等于锚点所属月份，否则文件会进「待整理」（例如 `2026-09/2026-09-M-…` 里写 `2026-10` 是错的）。
- 标题里不能有 `\ / : * ? " < > |`（会破坏路径）；有这些字符时替换成 `-`。标题别超过约 80 个字符。
- 同目录下不要有重名文件，也**不要**用 `mv -f` 覆盖别人：先确认是不是同一条计划，否则换一个能区分的标题，或问用户。
- 中文、空格、`-`、`_`、`.` 都可以出现在标题里。

## frontmatter 三字段契约

只有这三个字段，正文是备注（纯文本 / Markdown）：

```markdown
---
done: false
created_at: 2026-09-14T22:03:11+08:00
done_at:
---

顺路去银行取号，带上身份证和租房合同。
```

- `done`：`true` / `false`（小写）。
- `created_at`：新建时写入的本地带时区时间戳；已经存在的文件不要改它。
- `done_at`：完成时写入，取消完成时清空（`done_at:` 留空）。
- 时间戳格式形如 `2026-09-14T22:03:11+08:00`（带明确的时区偏移）。**别自己编时间**，用命令取本机当前时间：

  ```bash
  date +%Y-%m-%dT%H:%M:%S%:z
  ```

- 不写 `title`，也不写任何日期字段——日期只在路径里，写进 frontmatter 就制造了「谁是真值」的矛盾。
- 面板解析很宽容（缺 frontmatter 视为未完成、未知字段忽略、畸形值只报「待整理」），但**不要利用宽容去写畸形文件**；写就写标准形态。

## 改期 / 排期必须移动或重命名文件

锚点唯一真值在路径里，所以**改期 = 移动 / 重命名文件**，`edit` 改不了文件名：

```bash
# 本周 → 某个具体日子（同目录改名）
mv ~/.pi-work/user-plans/2026-09/2026-09-28W-整理书架.md \
   ~/.pi-work/user-plans/2026-09/2026-09-30-整理书架.md

# 收件箱 → 某个月（跨目录，先建目标月份目录）
mkdir -p ~/.pi-work/user-plans/2026-10
mv ~/.pi-work/user-plans/inbox/读完一本书.md \
   ~/.pi-work/user-plans/2026-10/2026-10-M-读完一本书.md

# 取消锚点 → 放回收件箱
mkdir -p ~/.pi-work/user-plans/inbox
mv ~/.pi-work/user-plans/2026-09/2026-09-15-去办居住证.md \
   ~/.pi-work/user-plans/inbox/去办居住证.md
```

- 用 `mv` 移动时 `created_at`、备注、完成状态都原样带走，不需要也不应该再改 frontmatter。
- 只改 frontmatter 里的日期 / 只改正文写一句「改到 10 月」**不算改期**，面板不会理它。
- 改期后不要再往正文或 frontmatter 补写日期。

## 常见任务

- **新建一条**：`write <数据根>/user-plans/<目标目录>/<文件名>`，frontmatter 用 `done: false` + `created_at`（当前时间），正文放备注（可空）。目标目录不存在就先 `mkdir -p`。默认锚点由用户说的时间决定；用户没说时间就放 `inbox/`。
- **标记完成**：`read` 目标文件 → `edit` 把 `done: false` 改成 `done: true`，并把 `done_at: 2026-09-14T22:03:11+08:00`（空行占位的 `done_at:` 补上时间）。取消完成则反向（`done: true` → `false`、清空 `done_at`）。
- **写 / 改备注**：`edit` 只动 frontmatter 之后的正文，保持 frontmatter 不变。
- **查找**：按文件名 `glob "**/*关键词*.md"`（限定在 user-plans 下），或按内容 `grep -rn --include='*.md' "关键词" <数据根>/user-plans`；找到后 `read` 确认再回答。
- **删除**：只有用户明确要求删除某条计划时才 `rm` 那个文件。

## 查「今天该做什么」

不要整个目录乱读——**读本月目录 + 上月目录 + 收件箱**就够了（上月目录是必须的：跨月的周锚点可能落在上个月目录里）：

```bash
ROOT="${PI_WORK_DATA_DIR:-$HOME/.pi-work}/user-plans"
TODAY=$(date +%F)                       # 用户的本地日期
THIS_MONTH=$(date +%Y-%m)
LAST_MONTH=$(date -d "$(date +%Y-%m-01) -1 month" +%Y-%m 2>/dev/null || date -v-1m +%Y-%m)
ls "$ROOT/$THIS_MONTH" "$ROOT/$LAST_MONTH" "$ROOT/inbox" 2>/dev/null
```

然后按文件名读出来判断归属：

- `YYYY-MM-DD-标题.md`：日锚点，只有日期 = 今天才是「今天」。
- `YYYY-MM-DDW-标题.md`：周锚点，文件名日期是周一；今天在 [周一, 周一+6] 之内就属于「本周」（若今天落在该周的周一前，就是未来）。
- `YYYY-MM-M-标题.md`：月锚点，文件名月份 = 本月才是「本月」。
- `inbox/标题.md`：还没排期。
- 不打算把「过期未完成」当回事：过期只是一条提示，**永不自动改期**；也不要替用户把它们挪到今天，除非用户明确要求。

## 硬性规则

1. **改之前先读**。任何修改前先 `read` 目标文件，确认当前锚点（文件名）、完成状态与备注；计划是用户自己写的，不要凭记忆重写。
2. **只动用户明确要求的那一条**。不要顺手批量改期、补齐 frontmatter、重排目录或"整理"用户的计划。
3. **不改写不符合约定的文件**（面板里的「待整理」）。遇到文件名不合语法、目录放错、frontmatter 畸形的文件：只把路径与问题报告给用户，让他在面板里处理；**不要**自动修复，否则会把仅存的信息丢掉。面板对这类文件的写入也会被拒绝（422），不要试图绕过。
4. **删除极其克制**。默认不删任何计划；只有用户明确说删时才删对应的那一个文件。
5. **不要碰** `user-plans/` 以外的 `~/.pi-work/` 内容（会话、笔记、数据库、配置都不是你的操作对象）。
6. **grep / glob 要限定 `.md`** 并限定在 `user-plans/` 下，避免扫进注释、临时文件或其它目录。
7. **面板不会自动感知你的磁盘改动**：你写完文件后，用户面板里可能还是旧内容，直到他手动刷新或切走再切回。可以在回复里顺带提一句"面板刷新一下就能看到"。
8. **反向风险更大**：如果用户面板里有**未保存的编辑**，你的写入可能被面板随后的自动保存覆盖（后者胜）。改用户正在编辑的那条计划前，在回复里提醒一句"如果你面板里还有没保存的改动，先保存一下"。
9. 保存失败 / 内容对不上时，先 `read` 一次磁盘真实内容再判断，不要假设面板显示的就是磁盘内容。
