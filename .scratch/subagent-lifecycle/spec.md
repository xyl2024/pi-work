# 子代理生命周期工具

Category: enhancement
Status: ready-for-agent

## Problem Statement

父 agent 目前只能通过 spawn_subagent 创建子代理并同步等待结果，无法通过工具列出已有子代理会话、查看任务状态与详情、重新等待或复用子会话继续委派。长任务让一次工具调用与子代理任务的生命周期绑定，等待超时、实际执行是否停止和记录状态容易混淆。用户还需要一个可靠的父会话总停止入口，避免遗漏后台或排队中的子任务。

## Solution

将工具改名为 subagent，以 spawn、list、get、wait、continue、cancel 六种动作管理当前父会话的直属子代理。子代理会话承载可复用上下文，每次委派产生独立任务，对应一个回合；等待与执行分别管理。spawn 和 continue 默认等待 15 分钟，到期返回标识与当前状态，子任务继续执行，之后可以查询或再次等待。

父会话停止会级联停止所有未结束子任务；父回合正常结束和关闭会话标签页不会停止后台任务。用户可查看、手动继续和停止子会话，所有入口遵循相同的任务管理、归属校验与并发规则。

## User Stories

1. As a 父 agent, I want 通过 subagent 的 spawn 动作选择子代理档案并委派任务, so that 专门的子代理能够独立完成工作。
2. As a 父 agent, I want 创建后默认等待 15 分钟, so that 大多数任务能在一次工具调用内返回结果。
3. As a 父 agent, I want 缩短等待时间或设置为零立即返回, so that 我可以在子任务执行期间处理其他工作。
4. As a 父 agent, I want 等待超时返回任务标识和真实状态, so that 我能继续跟进且不会误以为任务失败。
5. As a 父 agent, I want 列出当前会话的直属子代理会话及其最新任务摘要, so that 我能找回已经启动的工作。
6. As a 父 agent, I want 按状态筛选并分页查询列表, so that 大量历史不会占满上下文窗口。
7. As a 父 agent, I want 按任务标识查看状态、时间、错误与输出, so that 我能判断某次委派的结果。
8. As a 父 agent, I want 按会话标识查看最新任务与分页任务历史, so that 我能理解多次委派的关系。
9. As a 父 agent, I want 查看近期工具活动, so that 我能判断任务正在推进还是需要干预。
10. As a 父 agent, I want 分页读取对话记录与完整结果, so that 摘要不足时我能进一步检查。
11. As a 父 agent, I want 输出截断有明确标记及后续读取方式, so that 我不会把不完整内容当成完整结果。
12. As a 父 agent, I want 对同一任务再次 wait, so that 我能在此前等待超时后继续获得最终结果。
13. As a 父 agent, I want 对已完成任务的 wait 立即返回其结果, so that 无需再次执行任务。
14. As a 父 agent, I want 在已有子会话中 continue 并获得新的任务标识, so that 我能复用其上下文跟进工作。
15. As a 父 agent, I want 继续时保留旧任务的结果与状态, so that 任务历史不被覆盖。
16. As a 父 agent, I want 忙碌子会话拒绝 continue 并明确返回 busy, so that 不会意外插话、排队追加或启动重叠回合。
17. As a 父 agent, I want 成功、失败、取消或中断后的子会话都能显式继续, so that 我可以根据历史调整后续指令。
18. As a 父 agent, I want 按任务标识取消某次任务, so that 迟到的取消请求不会误停后续任务。
19. As a 用户, I want 父会话停止同时停止全部未结束子任务和排队任务, so that 一个总停止操作能覆盖当前委派工作。
20. As a 用户, I want 父回合结束后仍能停止全部后台子任务, so that 后台任务不会失去控制入口。
21. As a 用户, I want 有后台子任务时仍能正常发送新输入, so that 子任务不会占住父会话输入能力。
22. As a 用户, I want 关闭会话标签页时后台子任务继续, so that 界面开合不会意外取消工作。
23. As a 用户, I want 删除父会话时取消其未结束子任务, so that 不会遗留无人管理的工作。
24. As a 用户, I want 停止中和已取消清楚区分, so that 我知道执行是否已经真正停止。
25. As a 用户, I want 查看、停止和手动继续子会话, so that 我可以直接参与跟进。
26. As a 用户, I want 手动继续与父 agent 委派遵守同一忙碌检查和总停止规则, so that 双方操作不会互相冲突。
27. As a 用户, I want 子会话继续使用创建时确定的档案配置, so that 编辑档案不会悄悄改变已有子代理行为。
28. As a 用户, I want 重启后中断任务明确标为中断且不自动重放, so that 文件修改或外部操作不会意外重复执行。
29. As a 父 agent, I want 重复提交同一请求不会重复启动任务, so that 重试不会造成重复工作。
30. As a 用户, I want 超额任务按顺序排队且全局并发有上限, so that 子代理不会无限消耗资源。
31. As a 用户, I want 排队时间与实际运行时限分开计算, so that 排队不会提前耗尽任务执行时间。
32. As a 用户, I want 无人能回答的子代理提问及时失败, so that 任务不会无限挂起。
33. As a 用户, I want 既有工具选择迁移到新工具名且历史消息仍可查看, so that 升级后仍能使用子代理能力并阅读旧记录。
34. As a 用户, I want 查询与控制仅作用于当前父会话的直属子代理, so that 不会误操作其他会话的任务。

## Implementation Decisions

- 工具命名为 subagent，不注册 spawn_subagent 兼容入口；旧名称的实际调用不再接受。已有会话工具选择与子代理档案中的旧名称在加载时迁移为新名称；历史工具消息不重写，继续支持展示。迁移不能意外启用子代理递归委派。
- 六种动作使用按动作区分的参数结构及校验，返回可供模型读取的明确文本与结构化详情。未开始执行前即分配稳定任务标识；排队时子会话标识可以尚未存在。
- spawn 保留档案名称、任务描述与输入语义；list 查询当前父会话的直属子代理会话摘要，支持状态筛选和分页，避免同一会话因多任务历史重复成多项。
- continue 用 session_id 定位会话；wait/cancel 用 task_id 定位任务；get 支持按任一标识查询。按会话查询可分页读取任务历史；结果和对话记录也支持有界读取。所有动作从调用上下文确定父会话并校验归属，不能信任调用方自报父会话标识。
- 子代理任务模块统一拥有任务生命周期、调度、继续、等待、取消及持久化对账。工具、用户手动继续、父会话停止与删除均经过同一管理规则；工具等待结束不移除任务执行管理或释放仍在执行的槽位。
- 复用既有回合执行 module 和会话获取/复用 seam，不重新复制事件订阅与回合结束判断。遵循既有 ADR：agent_settled 才表示完整回合结束，agent_end 不单独作为完成依据。
- spawn/continue 默认等待 900000 毫秒，允许更短等待和零等待。等待超时只结束观察，不失败任务、不取消执行、不销毁执行管理；wait 具有同样的有界等待语义。返回任务当前状态及等待是否到期，区分等待超时与任务运行超时。
- 持久化区分子代理会话、任务历史和创建时配置快照，支持同一子会话多个顺序任务。独立保存每项任务的输入、结果、错误、时间及结束原因，旧任务不因 continue 被覆盖。迁移保持旧任务和父子关联可读，幂等且向后兼容已有数据。
- 可观察状态应区分排队、创建、执行、停止中与各终态；中断与失败/取消可区分。查询以受管理执行与持久化记录对账，不只依赖可能过期的数据库 running 值。
- 全局最多 4 个执行中子任务，超额 FIFO 排队。任务执行时限来自子会话创建时保存的档案快照，每次 continue 重新计时；排队不计入执行时限，计入工具调用等待时间。
- 同一子会话只能有一个未结束任务，包括已排队和停止中任务。continue 忙碌时返回 busy，不隐式排队输入、打断或引导当前回合。
- 父回合正常结束、浏览器断开或关闭会话标签页不取消子任务；运行实例的空闲回收不能被当作用户总停止，也不能使子任务失去管理。
- 用户在父会话点击停止时，停止父回合并级联停止所有未结束直属子任务，包括队列中任务。父会话删除也取消子任务。总停止开始后暂时拒绝新的 spawn/continue，包括用户手动继续；停止完成后允许显式委派。
- 父回合已结束但仍有未结束子任务时，保留正常输入并提供独立的停止全部子任务入口。父回合执行时原停止按钮承担总停止语义；命令面板等同类入口保持一致。
- 取消进入停止中，确认回合已停止才进入已取消并释放会话及槽位。仅销毁 wrapper 或发出 abort 不等于确认停止；运行时限到期同样不能只改记录而放任底层执行。无法确认停止时必须保持可观察的真实状态，不虚报终态。
- 已完成且结果落地的任务不被迟到取消覆盖。重复取消安全；取消精确定位任务，不影响会话中的后续任务。状态更新需处理完成、取消及超时竞争，终态与结果不被重复事件覆盖。
- spawn/continue 支持同一请求重试去重，包括跨入口的请求归属校验；去重至少不能依赖单次工具等待的内存生命周期。实现选择具体请求标识形式，但不能把内容相同的两次主动委派自动合并。
- 服务退出不承诺子任务继续，重启后对无法确认仍执行的非终态任务标记中断；不自动重放输入。保留上下文和历史，可显式 continue，但不承诺恢复任意命令内部断点。
- 子会话继续使用创建时确定的系统提示词、工具集、模型、推理强度及运行时限快照；编辑或删除档案不自动重配置已有子会话。冷启动同样恢复受限配置，不能提升工具能力或权限。
- 子代理保持其身份，不继承父会话完全访问模式。按既有交互闸门规则处理权限，需确认而无人可回答的操作快速拒绝；用户提问快速返回明确错误。手动继续不转成普通用户会话，也不自动提升权限；用户仍能按既有界面规则显式调整该子会话权限模式。
- 子代理禁止递归委派，不因工具重命名、配置迁移或冷启动而绕过限制。可查询与控制范围仅限当前父会话的直属子代理。
- 复用现有子代理列表、活动详情与工具调用展示能力，调整数据契约、SSE/快照或轮询，使后台及继续任务状态保持可见。用户文案沿用国际化机制；共享类型保持客户端/服务端依赖隔离。
- UI 或通用会话输入对已知子会话的手动继续必须进入相同任务管理，不能直接投递未跟踪回合。任务历史应能识别手动提交输入，并可被父 agent 查询。
- 第一版不向父会话自动注入完成消息或启动父回合；UI 可自行更新状态，父 agent 通过查询或等待取得结果。

## Testing Decisions

- 主要测试 seam 是 subagent 工具的六动作外部接口：通过真实工具执行与上下文驱动任务管理，使用可控的回合执行 adapter 替代真实模型请求，持久化使用临时数据根。断言返回结果、可查询状态、历史和执行是否仍存活，不断言私有容器、内部调用次数或函数拆分。
- 复用既有回合执行 seam 驱动事件，不新增另一套执行完成判断。参考现有 turn-orchestrate、turn-reuse、turn-outcome 测试中的可控会话与结束事件；证明 agent_end 后仍可继续重试/压缩，直到 settled 才完成。
- 验证默认 15 分钟和显式零等待、等待超时任务继续、多次 wait、完成后 wait 立即返回及运行时限独立；使用可控时钟，不实际等待 15 分钟。
- 验证同会话多任务、结果历史不覆盖、busy、全局 4 并发、FIFO、排队取消、排队不耗运行时限及每次 continue 独立计时。
- 验证单任务取消、父会话总停止及删除、停止期间并发 spawn/continue、停止中不释放槽位、迟到取消与完成竞争；证明不存在“记录已取消但回合仍在执行”的假成功。
- 验证取消等待与任务取消分离，父回合正常结束、标签页关闭或运行实例回收不丢失后台任务管理；父回合已结束时总停止仍能找到子任务。
- 验证任务标识稳定、重复提交去重、重复事件安全、服务重启对账标中断且不重放，冷启动继续保持原配置。重开临时持久化存储模拟重启，不使用真实用户目录。
- 验证每种定位动作的归属校验、非法参数、分页/截断、完整结果读取、错误与部分输出；参考 subagents-api 与 subagent-activity 的外部响应测试。
- 验证子代理身份、禁止递归、权限确认与提问快速失败；参考 interaction-gates 和 subagent-profiles 测试，不依赖等待无人回答的实际超时。
- 补充配置迁移的行为测试：旧选择映射为新工具、旧调用名不可执行、历史展示可读、迁移幂等、既有档案及任务不丢失。参考 subagent-profiles-store 和 subagent-block-state 测试。
- 除主要工具 seam 外，仅补必要入口契约测试：用户手动输入不得绕过任务管理；父会话停止端到端到达总停止；REST 活动与列表反映同一任务状态。通过真实 Request 驱动服务端入口或复用既有隔离接口测试，避免为每个内部 module 重复同一生命周期测试。
- UI 验收覆盖父回合运行时总停止、父回合结束后独立停止全部入口、后台任务不占发送按钮、旧/新工具卡片及多任务历史展示。规格阶段不启动服务；实现验证遵守仓库不得擅自启动 UI 测试的约定，未执行的人工检查须明确说明。
- 测试仅使用临时或项目约定的隔离数据，绝不访问真实用户会话/配置/数据库；进程内测试跳过实例启动。实现完成至少执行相关 TypeScript 或 ESLint 检查，以及针对上述生命周期行为的测试，不运行会覆盖共享构建目录的日常生产构建。

## Out of Scope

- spawn_subagent 旧名称的可执行兼容入口。
- 子代理递归委派、跨父会话查询或控制、转移父子归属。
- 向执行中任务插话、steer、自动排队追加输入或强制接管替换当前回合。
- 自动完成通知注入父会话、自动唤醒父 agent 或重复投递结果。
- 重启后自动恢复执行、自动重试有副作用的任务、命令内部断点恢复。
- 停止时回滚文件或外部操作、保证杀死任意脱离管理的后台进程。
- 将子代理权限确认或提问转交父会话，自动继承父权限或由 agent 提升权限。
- 对既有子会话动态套用档案修改、多进程分布式调度、公平队列或新增 token/费用预算系统。
- 无关的回合模块重构及对其他调用方改变超时/取消语义。

## Further Notes

- 本规格来自已经逐轮确认的设计访谈；用户明确将默认等待改为 15 分钟，要求父会话停止级联全部子任务，并拒绝旧名称兼容。
- 采用项目既有回合、子代理档案、子代理任务和子代理会话术语。遵守回合执行统一 seam 与 agent_settled 终态原则、既有子代理交互规则以及新生命周期 ADR；新需求只改变子代理等待和生命周期所有权，不默默改变调度任务/频道等其他调用方。
- 代码梳理发现 wrapper 销毁不保证底层回合停止，因此不能把 destroy 当作停止已完成的证据；实现必须验证实际终止。
- 旧数据若没有完整创建时配置快照，只能恢复能可靠确定的受限配置；缺失且会影响安全执行的配置应明确报错，不能悄悄套用当前已变更的档案或扩大能力。
- 具体分页上限、参数格式和内部 schema 由实现按既有约定选择，必须保持本规格的外部语义。可在 API 调用方、工具选择、提示词及历史卡片中全面检查旧名称引用。
- 本地 tracker 的 spec 即本文件，已标 ready-for-agent。当前任务仅产出规格，未授权本轮直接实施功能，也未运行功能测试。
