# 04: 单任务取消与父会话总停止

Category: enhancement
Status: done

**What to build:** 父 agent 可取消指定任务；用户点击父会话停止时停止父回合和所有未结束子任务。即使父回合已结束，用户仍有独立的停止全部子任务入口。

**Blocked by:** 01: 改名为 subagent，打通创建与独立等待.

**Status:** done

- [x] cancel 仅按 task_id 作用于直属子任务，重复取消安全，不能误停该子会话后来启动的任务。
- [x] 排队任务取消后不再启动；执行中任务先进入停止中，确认回合停止后才进入取消终态并释放槽位和会话。
- [x] 完成结果已落地时，迟到取消不能覆盖终态和结果；并发完成/取消/超时不导致重复释放或假终态。
- [x] 用户父会话停止级联取消所有未结束子任务（含队列），父会话删除也取消；普通等待到期和父回合正常结束不触发总停止。
- [x] 总停止开始后临时拒绝新的 spawn；后续 continue 及手动继续也须复用此规则。停止完成后可显式重新委派。
- [x] 父回合运行时原停止入口执行总停止；父回合已结束且仍有未结束子任务时提供独立停止全部入口，不占用发送按钮，同类命令入口一致。
- [x] 界面区分停止中与已取消，不承诺回滚已发生操作或终止任意脱离管理的进程，用户文案遵循国际化机制。
- [x] 测试覆盖后台任务总停止、排队取消、停止与创建竞争、停止中槽位占用、迟到取消、父删除和再次委派；使用真实入口契约验证父停止能到达统一任务管理。

## 实现备注

- 工具新增 `action: "cancel"`，只接受 `task_id`，归属复用 `getSubagentTaskForParent`；排队任务直接 `cancelled`，执行中任务进入 `stopping`，只有回合确认后才写终态并释放槽位。返回文本按实际结果区分「已停止中/已排队取消/已是终态未改动」，并提示用 `wait` 确认。
- 任务管理新增 `stopAll(parentSessionId)` 与 `isStopping(parentSessionId)`：先进入停止窗口再逐行停止所有未结束任务，包含队列和本进程未管理的非终态行；最后一个任务结束后自动解除窗口，期间 `spawn` 直接拒绝（错误文案明确）。`continue`/手动继续尚未实现，后续入口复用同一 `isStopping`/`spawn` 规则即可。
- 父会话停止：`rpc-manager` 的 `abort` 命令先 `stopAllSubagentTasksForParent` 再 abort 父回合，因此输入框停止按钮、命令面板 Stop agent 等所有 `abort` 入口一致级联；子代理会话自身的 abort（单任务取消/运行时限）不当作父会话总停止。父会话删除在 `deleteSession` 内调用同一 helper（仅删除触发，关标签/回收 wrapper 不触发）。两个入口都走 `getExistingSubagentTaskManager`，不会因为一次停止而创建任务管理或触发启动对账。
- 新增 `POST /api/sessions/[id]/subagents/stop-all` 供父回合已结束时使用，同样复用 `stopAllSubagentTasksForParent`；子代理会话浮层在存在未结束任务且父回合已结束时显示「全部停止」，父回合运行时仍由原停止按钮承担总停止，不占用发送按钮。状态沿用「停止中 / 已取消」国际化文案，停止中的任务卡片继续显示实时面板。
- `cancel` 结果的 `waitExpired`（非终态时）复用既有「任务超出本次工具调用」契约，让卡片继续跟踪停止中的任务；迟到取消始终先判终态、不写行。
- 测试 `tests/unit/subagent-cancel.test.ts` 用真实工具接口 + 真实任务管理 + 脚本化回合 adapter + 临时数据根覆盖：执行中取消的两阶段确认、排队取消不启动、停止中占槽、完成竞争保留结果、迟到/重复取消、越权与参数校验、父会话总停止（含拒绝新 spawn 与停止后重新委派）、命令 `abort` 真实入口、REST stop-all 与 `deleteSession` 真实入口。脚本化回合/子会话/时钟抽到 `tests/unit/support/subagent-runtime.ts`，与任务、等待套件共用，避免第三份复制。
- 未执行人工 UI smoke（仓库约定不擅自启动服务）：浮层按钮位置、停止中/已取消配色与文案仅通过类型检查与静态审查确认。
