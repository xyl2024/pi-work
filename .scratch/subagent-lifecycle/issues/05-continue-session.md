# 05: 在已有子会话中继续委派

Category: enhancement
Status: ready-for-agent

**What to build:** 父 agent 用 session_id 在已有子代理会话中继续委派，保留上下文和每次任务历史；新的任务可像首次创建一样查询、等待和停止。

**Blocked by:** 02: 查询子代理会话、任务详情与结果; 04: 单任务取消与父会话总停止.

**Status:** ready-for-agent

- [ ] continue 接受 session_id 和新输入，为一次新回合创建独立 task_id；不覆盖旧输入、结果、错误或时间。
- [ ] 成功、失败、取消或中断后的空闲子会话可显式继续；已排队、创建中、执行中或停止中的任务使会话 busy，不自动追加排队输入、打断或 steer。
- [ ] 新任务默认等待 15 分钟，支持零等待及缩短等待，与 spawn 的独立等待及后台管理语义一致。
- [ ] 每轮重新计算执行时限，使用子会话创建时快照中的模型、推理强度、提示词、工具及运行时限；档案编辑或删除不自动影响已有会话。
- [ ] 继续产生的任务进入全局调度，可通过既有 list/get 查询；旧任务结果仍稳定可读，可被 wait/cancel 精确定位。
- [ ] continue 校验直属归属并受父总停止入口约束，停止期间拒绝新任务，不能提升权限或启用递归。
- [ ] spawn/continue 提供请求标识去重，相同请求重试返回已有任务；不同主动请求即使内容相同也不合并，请求标识不能被用于跨父会话读取/控制。
- [ ] 去重记录不依赖单次工具等待内存生命周期；迁移已有记录幂等，为重启后去重保留依据。
- [ ] 外部测试验证多轮历史、busy 竞争、独立时限、配置保持、停止门控与重复请求去重，不测试私有内部容器。
