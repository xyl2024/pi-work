# 04: 翻译与自动起名纳入逐调用查询

**What to build:** 翻译和自动起名的模型调用，无论是否关联持久化会话，都能落库并通过现有逐调用 API 查询三个指标。直接调用复用统一采集规则，同时保持流式翻译和一次性结果读取行为。

Blocked by: 01 — 主聊天调用的三个指标可查询

Status: ready-for-agent

- [ ] 从实际翻译入口发起受控流式调用后，业务方继续按原有顺序收到完整输出，审计 API 可查询唯一一条记录及准确的首尾输出时间与最终 TPS。
- [ ] 从实际自动起名入口发起一次性调用后，原有结果读取、命名与返回行为保持一致；审计 API 可查询唯一一条正常完成记录及指标。
- [ ] 来源标识为直接调用，调用用途明确区分翻译和自动起名；有真实会话关联时保留，无持久化会话时明确表达缺失，不虚构持久化会话或使用伪造会话 ID。
- [ ] 无会话关联的调用包含在未指定会话筛选的列表和 total 中；指定会话时只返回实际关联记录。结果排序、分页和 nullable 指标遵循 01 的契约。
- [ ] 通过统一模型运行时入口采集，不能因为无磁盘会话不加载扩展而漏记；同时不破坏其不加载工具、项目扩展或项目上下文的既有隔离保证。
- [ ] 同一结果既经过流读取又经过最终结果读取时，只记一次，不额外遍历抢占模型流、不漏掉最后输出、不重复触发请求或累加用量。
- [ ] 保持取消信号、超时和资源释放行为；新增性能记录不将辅助调用意外加入既有费用汇总统计。
- [ ] 设置中的模型连接测试不产生本功能的业务性能记录，既有连接诊断返回行为保持一致。
- [ ] 通过受控 SDK、实际直接调用入口或最高可行工厂、真实临时 SQLite 和真实 Request 验证两类调用到查询的完整链路，并验证无会话关联及连接测试排除。
- [ ] 不依赖 02 或 03；完成匹配范围的 TypeScript、ESLint 和受控测试，不使用真实模型或用户数据，不启动服务，不改 UI。
