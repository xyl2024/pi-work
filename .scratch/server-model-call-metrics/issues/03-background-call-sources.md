# 03: 子代理、定时任务与频道调用可按来源识别

**What to build:** 子代理、定时任务和频道/微信入口触发的模型调用，使用与主聊天相同的三个指标口径，并通过审计 API 保留正确的来源、用途和会话关联。共享主聊天路径的业务入口也必须从实际调用工厂验收，不能仅以包装器测试推定已覆盖。

Blocked by: 01 — 主聊天调用的三个指标可查询

Status: ready-for-agent

- [ ] 子代理、定时任务、频道和微信现存业务入口触发的每次正常模型调用，都能在逐调用 API 查询到对应指标、服务商、模型和实际会话关联。
- [ ] 子代理与定时任务保留各自来源；频道/微信用途与普通聊天可区分。来源和用途分别表达，新来源不会在映射时被静默归为用户聊天。
- [ ] 通过已有后台回合执行与会话工厂接入同一模型运行时采集边界，不为各入口另写计算公式或依赖回合耗时推导模型耗时。
- [ ] 一次助手工具调用前的模型请求和工具执行后的新模型请求产生两条独立记录，模拟的工具等待时间不进入两次模型调用的耗时。
- [ ] 后台调用与主聊天或其他后台调用同时进行时，可按会话筛选得到正确记录，未筛选查询不遗漏后台调用，分页 total 与行数一致。
- [ ] 不改变既有回合等待彻底结束、截止时间、取消、会话获取/销毁、消息投递及工具权限语义；调用结束不被误当作整个回合结束。
- [ ] 使用受控 SDK 驱动实际入口或最高可行服务端工厂，配合临时 SQLite 和真实 Request 查询，以参数化样本验证各业务来源、用途、指标及工具前后调用划分。
- [ ] 既有 Token 审计费用和次数不重复，新增业务归属不会无意扩大费用汇总范围。测试不触发真实定时任务、消息发送或后台监听。
- [ ] 不依赖 02 的实现细节，复用 01 已公开的终态与 nullable 契约；完成匹配范围的 TypeScript、ESLint 和受控测试，不访问用户数据或擅自启动服务。
