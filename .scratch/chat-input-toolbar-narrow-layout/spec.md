# 输入工具栏窄布局自适应

Status: ready-for-agent

## Problem Statement

对话输入区底部那条工具栏（`BottomToolbar`：新建、上传、模型、项目、上下文环、思考级别、工具、盾牌、通知、更多）是一行不换行的 flex，所有分组都是 `flex: 0 0 auto`，没有任何一个元素会收缩。

一旦宽度不够——最常见的情况是会话侧栏和右侧面板同时打开，聊天列被挤到 500px 上下——工具栏不会「挤」，而是直接**向右溢出并被裁掉**：最右边的「更多」按钮、通知按钮、盾牌按钮点不到，也看不见。用户不知道它们还在，只知道「工具没了」。

聊天列本身有 `maxWidth: 820 + margin: auto` 的 gutter，所以「窄」既可能是窗口窄，也可能是两个侧栏把会话列挤窄。任何基于 viewport 的断点都量不准真正的约束。

## Solution

让工具栏**按容器实测宽度自动分级收缩**：宽度够就全展开，不够就按固定优先级逐级降信息密度，最后把次要控件收进「更多」菜单。

收缩是「保住可点击」优先，不是「保住文字」优先：

- 先牺牲可截断的**模型名**（220 → 160 → 120 → 只留图标）
- 再牺牲**项目名**（只留图标，完整路径进 Tooltip）
- 再牺牲**上下文环的读数**（只留环，数字进 Tooltip）
- 再牺牲**工具 / 思考级别的文字标签**（只留图标）
- 最后把**思考级别、工具、项目**收进「更多」菜单

三条硬约束：

- **永不横向滚动**，**永不换行**。溢出是靠降级解决的，不是靠滚动条。
- **上下文环（≈20px）和上传按钮永远保留**——前者是「上下文快满了」的唯一常驻信号，后者藏起来等于功能消失（不是所有用户知道还能拖拽/粘贴）。
- 常态下「更多」菜单**外观与行为完全不变**，只有真的被收进去的项才出现。

## User Stories

1. 作为一个同时打开会话侧栏和右侧面板的用户，我想工具栏上的每个按钮都还能点到，这样我不用为了点「更多」去关掉一个面板。
2. 作为一个窗口较窄的用户，我想工具栏自己变紧凑，而不是被裁掉，这样我不知道有功能被藏起来这件事不会发生。
3. 作为一个刚刚把侧栏拖宽的用户，我想工具栏在宽度恢复后自动展开回文字标签，这样我不用刷新页面。
4. 作为一个在窄布局里看模型按钮的用户，我想先看到模型名被压短、再被换成 Provider 图标，这样我至少还能确认用的是哪个模型。
5. 作为一个只看到 Provider 图标、不确定是哪个模型的用户，我想悬停看到完整模型名和它的元数据，这样压缩没让我丢失信息。
6. 作为一个把模型名 hover 到底的用户，我想那个元数据 Tooltip 不会横向溢出屏幕，这样它在窄容器里仍然可读。
7. 作为一个项目名被换成图标的用户，我想悬停看到完整 cwd 路径，这样我知道当前在哪个项目。
8. 作为一个上下文快满了的用户，我想那个小环永远在，这样我任何时候都能一眼看到余量。
9. 作为一个想看具体上下文数字的用户，我想在紧凑态下标仍然悬停出完整百分比与 token 数，这样紧凑态没削掉数据。
10. 作为一个想把「工具」按钮上文字省掉的场景，我想它变成齿轮图标但仍然一点就开选择弹窗，这样压缩没有改变交互。
11. 作为一个把思考级别换成图标的用户，我想图标颜色仍然编码当前级别，这样我不用 hover 也知道档位。
12. 作为一个极窄情况下（< 400px）的用户，我想工具、思考级别、项目被收进「更多」，这样我仍然能改它们，只是要多点一次。
13. 作为一个在极窄情况下打开「更多」的用户，我想只看到那几条被收进来的项，这样菜单不会突然长出几倍长度。
14. 作为一个宽度正常（≥ 700px）的用户，我想「更多」菜单和今天一模一样，这样这个改动对我透明。
15. 作为一个在 700px 边界附近轻微拖动的用户，我想工具栏不会来回跳档，这样它不会闪。
16. 作为一个用中文界面的用户，我想阈值留出中文标签比英文宽的余量，这样中文界面不会比别人更早触发收缩。
17. 作为一个偏好看到完整文字的用户，我想收缩只在真的塞不下时才发生，这样我不会在 680px 这种「其实还行」的宽度上就被 icon 化。
18. 作为一个在流式输出中的用户，我想收缩逻辑与 `isStreaming` 无关地生效，这样流式状态下（思考级别变成只读徽章、工具按钮消失）工具栏不会出现第三种奇怪的布局。
19. 作为一个没有会话的草稿用户，我想那条通知频道按钮出现时工具栏也照常降级，这样新会话场景没有单独的溢出 bug。
20. 作为一个用键盘操作的用户，我想 icon-only 的按钮仍然是可聚焦的按钮且带 `aria-label`，这样屏幕阅读器还念得出它是什么。
21. 作为一个用平板/无 hover 设备的用户，我想不看 Tooltip 也能从图标本身认出这些按钮，这样我没有被逼着去找鼠标。
22. 作为一个维护者，我想「宽度 → 布局」这条规则是一个纯函数，这样我可以直接给它写单元测试，而不用在浏览器里拖宽度。

## Implementation Decisions

### 分级规则是一个纯函数（唯一 seam）

新增 `lib/shared` 下的纯模块，导出布局解析器与阈值常量。它是本功能唯一被自动化测试的东西，也是「宽度 → 界面长什么样」的唯一定义处。

由原型论证后定下的形状（决定了整个特性的可测性，故内联）：

```ts
type CollapsedItem = "thinking" | "tools" | "cwd";

type ToolbarLayout = {
  tier: 0 | 1 | 2 | 3 | 4 | 5;
  /** null = 模型按钮只留 ProviderIcon */
  modelLabelWidth: number | null;
  cwdLabelVisible: boolean;
  contextBarCompact: boolean;
  toolsLabelVisible: boolean;
  thinkingLabelVisible: boolean;
  buttonGap: number;
  collapsed: CollapsedItem[];
};

function resolveToolbarLayout(
  width: number,
  prev: ToolbarLayout | null,
): ToolbarLayout;
```

`prev` 入参承载迟滞：往紧的方向**立刻**发生（`width < T` 就降档），往松的方向必须越过 `T + 24` 才升档。没传 `prev` 时按无迟滞直接求值（首帧、SSR、测试用）。

### 阈值表（容器内容宽度，非 viewport）

| tier | 区间 (px) | 收缩动作 |
| --- | --- | --- |
| 0 | ≥ 700 | 全展开，等于今天的行为 |
| 1 | 620–700 | 模型名 `maxWidth` 220 → 160 |
| 2 | 540–620 | 模型名 → 120；项目名 → icon-only |
| 3 | 470–540 | 模型 → icon-only；上下文条只留环 |
| 4 | 400–470 | 工具、思考级别 → icon-only；按钮 gap 6 → 2 |
| 5 | < 400 | 思考级别 / 工具 / 项目收进「更多」 |

「全 icon」地板实测约 340–360px，这就是 tier 5 存在的理由：只做到「全 icon 就收手」在双面板打开的真实场景下仍然溢出。

### 宽度测量

新增一个通用的容器宽度 hook（ref + `ResizeObserver` + 内置迟滞缓冲），但**只由 `BottomToolbar` 内部消费**。`tier` / `ToolbarLayout` 不外泄到 `ChatInput`——`ChatInput` 的 prop 已经 30+ 个，且目前只有工具栏关心这件事。将来输入行若需要同一条规则，再提升。

### 收缩优先级与硬底线

优先级（最先牺牲 → 最后牺牲）固定为：模型名 → 上下文读数 → 项目名 → 工具标签 → 思考级别标签 → 收进「更多」。

硬底线：上下文环与上传按钮任何档位都不隐藏；`新建`、`盾牌`、`更多`本身是 icon-only 按钮，不参与降级。不接受横向滚动，不接受换行。

### 受影响模块

- `lib/shared`：新增布局解析器纯模块（阈值常量 + `resolveToolbarLayout`）。
- 客户端 hooks：新增通用容器宽度 hook。
- `components/chat/chat-input/BottomToolbar.tsx`：接上布局计划，用**自解释的局部布尔**（`showModelName`、`showCwdName`、`compactContext` …）而不是到处散布 `tier >= 2`。不做全量「元素配置数组」重构——各元素渲染差异太大（模型按钮带 Tooltip + Modal，工具按钮带 Modal），抽象收益低于可读性损失。
- `components/chat/MoreMenu.tsx`：从「无 props 的 store 消费者」变成接一个可选的 `collapsed?: Partial<Record<CollapsedItem, ReactNode>>`（或等价形状）。新增第三个视图 `"collapsed"`，与现有 `"main"` / `"channels"` 并列；只在有被收进来的项时才渲染入口。**没有传 `collapsed` 时行为必须与今天完全一致**，包括「items 为空就 `return null`」的判空逻辑——但判空要改成「main items 与 collapsed items 都为空的才返回 null」，否则极窄 + 无会话头部动作时菜单会消失。
- `components/sessions/CwdPicker.tsx`：新增一个「隐藏文字标签、只留图标」的 prop。它已有 `disabled` / `maxWidth` / `hideTrigger` / `dropdownDirection`，这次只加一档，不动既有语义。
- 模型按钮的 Tooltip `maxWidth`：从硬编码 420 改为 `min(420, 容器宽度 - 24)`。只改这一处调用点，**不改 `Tooltip` 组件本身**（那是全局影响）。

### 交互与可访问性

icon-only 态靠已有的 `Tooltip` + `aria-label` 补偿（这些按钮本来就有，不需要新增 key）。不做长按揭示、不做常显小字：Pi Work 是桌面为主的 Web UI，为平板做一套常显标签是过度设计，且在桌面会误触。

思考级别换成图标后，图标的**颜色**继续编码当前级别（现有 `THINKING_LEVEL_COLOR`），这样不 hover 也能读出档位。

### 国际文案

不新增用户可见文案，除「更多」菜单 `collapsed` 视图可能需要的条目标题——优先复用既有 key（如 `Tools`、`Thinking level`），确实没有的再按 `useI18n` / `lib/shared/i18n-dict/` 机制补。阈值已按中文标签更宽留了约 10px 下界余量。

## Testing Decisions

**唯一 seam：`lib/shared` 里的 `resolveToolbarLayout` 纯函数。**

好的测试只断言「给定宽度（与上一帧布局），用户看到的是哪种布局」这一外部行为，不断言 JSX 结构、不断言组件内部 state、不断言渲染次数。这是本特性里唯一值得自动化、也唯一能脱离浏览器验证的边界；把它做成纯函数正是为了让这条规则可测。

必须覆盖：

- 每一档的区间中点给出预期的完整 `ToolbarLayout`（不只是 `tier` 数字）。
- 每档边界的 ±1px（699/700、619/620、539/540、469/470、399/400）。
- 迟滞单调性：`700 → 690 → 710 → 695` 这样一串输入下，`tier` 不出现在同一宽度上来回跳（恢复必须越过 `T + 24`）。
- 不传 `prev` 时的行为与传入等价的 `prev` 一致（无迟滞求值路径不偏离）。
- 硬底线不变式：任何 `width` 值下上下文环与上传按钮都不被标记为隐藏。

Prior art：`tests/unit/` 下已有大量「直接 import `lib/shared` 纯模块、不发请求」的单元测试（如 `panel-tabs.test.ts`、`context-composition.test.ts`、`subagent-profiles.test.ts`），本测试同一形态。

**不做**：不写 DOM/快照测试，不启服务跑 UI 测试（AGENTS.md 明确禁止擅自启动服务做 UI 测试）。视觉与手感由人手在浏览器里拖宽度验证，覆盖：双面板全开、单面板、无面板、中文/英文、流式与非流式、有/无通知频道按钮。

改动后至少跑 `tsc --noEmit` + 改动文件的 ESLint。

## Out of Scope

- `ChatWindow` 的 820px gutter 与聊天列 maxWidth 逻辑。
- `AskUserQuestionsPanel` 等复用 `ChatInput` 的窄卡片场景（它走的是 `hideToolbar`，本身没有这条工具栏）。
- 输入行（textarea + 发送/停止按钮）：实测 textarea 是 `flex: 1`、发送按钮 `flexShrink: 0`，本身已能自适应，不需要改。
- `Tooltip` 组件本身的视口 clamp（只在模型按钮这一处调用点做最小修正）。
- 横向滚动、换行布局作为替代方案。
- 平板/触屏专属的标签揭示交互。
- 会话侧栏、右侧面板、右侧按钮列的窄布局（各自是独立课题）。

## Further Notes

- 六个档位的阈值是拍出来的，不是算出来的。它们依据的是各元素的实测宽度（模型 220 / 项目 160 / 上下文条 ≈75 / 工具与思考 ≈31 / 圆钮 32）与「全 icon 地板 ≈340–360px」，并给中文标签留了余量。真实拖宽度时若发现某档触发得太早或太晚，**改阈值表，不要改分级结构**——规则本身（优先级顺序、迟滞、硬底线）应当稳定。
- `isStreaming` 会改变工具栏内容（思考级别变只读徽章、工具按钮消失、模型/Cwd disabled）。分级规则只吃宽度，不吃流式状态，避免出现「第三种布局」。
- 已知遗留观察点（不在本次范围，但值得记一笔）：`CwdPicker` 的 `maxWidth` 是 prop 而模型按钮的 `maxWidth` 是内联硬编码，两者形状不一致；本次让它们都能接收动态值，本身算是顺手抹平了一处不一致。
