# 设置面板：一个设置分区一页

`Status: done`

## Problem Statement

设置弹窗现在是一条长滚动流：10 个设置分区首尾相接铺在同一列里，左侧导航只是滚动锚点，点一下把正文滚到对应位置。想改一个东西，得先滚过一堆不相干的分区，或者盯着导航猜「UI Sounds 现在离我多远」。分区之间用 24px 间距和分组大标题分隔，但它们终究是同一条流，滚动位置是全局的：滚到 Append System Prompt 之后，切去看 UI Sounds，再切回来，你落在了别处。

用户要的是「一页一件事」：点左边的分区，右边只出现那个分区。

## Solution

设置弹窗改成「左侧导航 + 右侧单页内容」。左侧按设置分组列出全部设置分区，点一个分区只渲染那一页；分组是导航里的小标题，永远不可点击。每次切页从页首开始。

带待保存项的分区在导航里挂一个小圆点，切走时先确认；没保存的改动不会静默蒸发。

## User Stories

1. 作为用户，我想点左侧导航直接切到某个设置分区，而不是让正文滚过去，这样我不用在一堆不相关的内容里找位置。
2. 作为用户，我想在任意时刻只看到一页设置内容，这样我读到的每一条都属于同一个主题。
3. 作为用户，我想让左侧导航用分组小标题把 10 个分区归成 5 组，这样我能按「个人 / 外观 / Agent / 集成 / 开发者」的心智模型找东西。
4. 作为用户，我想让分组小标题不可点击，这样我不会去点一个没有内容的按钮。
5. 作为用户，我想让当前页在导航里有明确的选中态，这样我知道自己在哪。
6. 作为用户，我想在每页正文顶部看到这一页的名字，这样光看内容区也能确认自己没走错。
7. 作为用户，我想让页头只保留「Settings」和关闭按钮，这样页头不会和正文标题打架。
8. 作为用户，我想在切页之后从页首开始读，这样「切到 X 页」的落点是可预测的。
9. 作为用户，我想让待保存项所在的分区在导航里带一个小圆点，这样我一眼能看出哪里还有没落盘的改动。
10. 作为用户，我想在点开一个有未保存改动的分区时被问一句「要丢弃未保存的改动吗」，这样我不会因为一次点击丢掉写了一半的提示词。
11. 作为用户，我想在丢弃并跳转之后，关窗时不再被同一个问题问第二次，这样确认只发生一次。
12. 作为用户，我想让「未保存改动」的确认只有一种形态（和关窗时同一个弹窗），这样它不会看起来像两套不同的机制。
13. 作为用户，我想在没有任何未保存改动时自由切页，不被任何提示打扰。
14. 作为用户，我想在点当前已经打开的分区时不弹任何确认（即使它有未保存改动），因为那不是一次导航。
15. 作为用户，我想让设置弹窗记住我上次停在哪一页，这样下次打开设置能回到我上次正在调的地方。
16. 作为用户，我想在没有任何记录、或记录的值已经不合法（比如那页被下线了）时，默认落到 Profile，这样记住上次位置不会把设置打开成一个空白页。
17. 作为用户，我想让弹窗比现在宽一些，这样写提示词那页的文本框不至于窄得难受。
18. 作为用户，我想让弹窗在窄屏上不再撑出视口，这样小窗口里也能用。
19. 作为用户，我想让切页是瞬时完成的，不要淡入动画，这样我知道点了之后立刻就能操作。
20. 作为用户，我想让设置的保存语义完全不变（开关当场落盘、文本要显式保存），这样这次改造不会改变我改配置的方式。
21. 作为用户，我想让关窗时的「Discard unsaved changes?」文案保持不变，这样我不会以为保存规则变了。
22. 作为用户，我想让 Developer 分组仍然待在导航最底部并保持次级视觉，这样调试工具不会跳到我日常用的分区中间。
23. 作为用户，我想让子代理的编辑界面仍然是一个独立的编辑弹窗，这样在 Subagent settings 页里点 New / Edit 的行为和现在一样。
24. 作为用户，我想让导航里的按钮都能被 Tab 聚焦、被读屏软件读出当前页，这样键盘和辅助技术都能用。
25. 作为用户，我想在导航里看到分区名本身（`Profile`、`Right-side buttons`、`UI Sounds`…），不要图标，这样这一栏保持紧凑。
26. 作为用户，我想在任何一页都能用同一个 × 和「点背景关闭」退出设置，不被分页状态影响。
27. 作为维护者，我想让「加了一个设置分区但忘了实现那一页」在类型检查阶段就报错，这样信息架构不会悄悄漂移。
28. 作为维护者，我想让导航顺序和注册表顺序始终是同一个事实，这样两边不会各自为政。
29. 作为维护者，我想让「哪些分区可能有未保存改动」写在类型里，这样新增待保存页时漏接上报会被编译器抓到。

## Implementation Decisions

**注册表（`components/settings/registry.ts`）形状不变。** `SETTINGS_GROUPS` / `SETTINGS_SECTIONS` / `sectionsForGroup` / `SETTINGS_SECTION_IDS` 保持现状：section 仍然是 `{ id, labelKey, group }`，数组顺序仍然是导航顺序。不改字段名、不引入「页」这一层新类型 —— 坏掉的只有注释里「滚动定位」那层隐含语义，词汇不需重命名。

**导航状态就是分区 id。** 选中态从「拼出来的 DOM id 字符串」变成 `SettingsSectionId`。IntersectionObserver、`scrollIntoView`、`data-settings-section` 锚点体系整体删除。导航项保持真 `<button>`，激活项用 `aria-current`（值从 `"true"` 改为语义更准确的 `"page"`）。

**`SettingsSection` 从锚点壳改造成页壳。** 它现在唯一做的事是挂 `data-settings-section` 加 `topGap`/`bottomGap` 间距，分页后在正文里已无对应物。改造为「一页的外壳」：渲染该页标题（来自 registry 的 `labelKey`）+ 可选描述 + 统一内容区内边距。10 个分区组件的改动是「去掉包裹、内容直接返回」，而不是每处重写。页标题不 sticky，只有弹窗页头 sticky。

**页渲染改成按 id 索引的映射。** 现在的 `renderSection(id)` 是一个 `switch`，靠源码扫描测试兜底；改成以 `SettingsSectionId` 为键的页映射，缺页直接编译失败。`tsc --noEmit` 变成「信息架构完整」的第一道关。

**未保存改动的 key 收紧成类型。** 待保存项上报的 key 由裸 `string` 收紧为一个从 `SettingsSectionId` 派生的联合（当前是 `profile` / `append-system` / `network-proxy`），让「哪些页可能有未保存改动」由类型列出。顺带把 Append System Prompt 那个内联写死的 `(key: string, dirty: boolean)` prop 类型换成已有的 `DirtyReporter`。

**「能不能离开这一页」下沉为纯判定。** 在已有未保存改动注册模块里增加一个选择器：给定当前脏 key 集合 + 目标分区 → 「可以走」或「先确认，脏的是这个 key」。目标等于当前页时永远「可以走」。React 组件只负责把「先确认」翻译成 `window.confirm` 并决定下一步。清理单个 key 复用注册模块已有的 `saved` action（语义即「这个 key 不再脏」），不加新 action。

**丢弃后必须显式清脏。** 用户确认丢弃并跳转时，在卸载该页之前把那个 key 从脏集合里清掉，否则关窗会二次确认一个根本不存在的改动。

**「未保存改动」只有一种确认形态。** 关窗确认现在是 `window.confirm`；切页确认也用同一个 `window.confirm`、同一句文案。不为切页另造 Save / Discard / Cancel 内联条。

**记住上次停留的分区。** localStorage 存一个分区 id，键名走既有 `pi-work:` 前缀风格。读写照仓库已有的「极小 storage 模块」惯例：可注入 storage、写失败静默、读到不认识的值返回空、空则回落 Profile。校验必须对着注册表做，不能信任存量值。

**弹窗尺寸。** 宽度从 880 提到 960，并加 `min(960px, calc(100vw - 32px))` 兜底；高度仍是 70vh。内容区不再做「宽页/窄页」双宽度，所有页统一吃满内容列 —— 切页时横向跳变比文本框窄更刺眼。

**切页无过渡动画。** 内容区按当前页重挂，滚动容器的位置天然回到顶部，不额外记录/恢复每页滚动位置。

**Developer 分组保持次级语气。** Toast Test 仍排在导航最底部、仍用次级文字色，不做隐藏开关。

**保存语义一事不动。** 即时生效项与待保存项的划分、`PUT /api/settings` 只送变更 key 的约定、关窗确认文案，全部保持原样；本次改动不碰保存路径。

**子代理编辑器不动。** 它仍是嵌套的独立编辑弹窗，本轮不改造成第三级页，但 Subagent settings 页按「列表页 + 右上 New」的样子排，为后续收编留路。

**导航不加图标、不加键盘快捷键。** 靠文字和间距即可；快捷键（`⌘1–9` / `↑↓`）会与 AppShell 的会话标签切换争位，本轮不做。

**文档。** 新增一篇 ADR 记录「设置分区就是页」这个决定（信息架构不可逆、有真实取舍、脱离上下文会费解），并更新 `CONTEXT.md` 里「设置分区」「设置分组」两条定义 —— 它们现在都把分区描述成「侧栏导航与滚动定位的单元」。不新增「设置页」这个同义词，术语仍用「设置分区」。

## Testing Decisions

好测试的标准沿用本仓库既有立场：只测纯 module 的外部行为，不测 React 组件、不测 DOM、不引入 jsdom。判定逻辑下沉成纯函数，组件只做接线 —— 接线的正确性靠人工清单，这是 `ADR-0003` 对「设置模态自身无浏览器测试基建」的既定策略。

要测的三处，全部是已有 seam 或已有惯例的极小扩展：

1. **未保存改动注册模块**：能否离开某页的判定（无脏 → 可以走；目标就是当前页 → 可以走；其他页脏 → 先确认且指出哪个 key；多页同时脏 → 只拦被点的那个），以及「清掉单个 key」不影响到其它 key。先例：`tests/unit/settings-unsaved.test.ts`（同一个纯 reducer 的单元测试）。
2. **设置注册表**：保留「id 唯一 / 每页有合法分组 / 每组非空 / 导航顺序 == 声明顺序 / Developer 只有一个」这些不变量；**删掉**「扫描源码找 `<SettingsSection id>`」那条守卫，因为它依附的锚点体系消失了，改由「页映射覆盖注册表全集」承担 —— 后者同时被类型检查强制，测试只需再断言一次映射键集合与注册表 id 集合相等。先例：`tests/unit/settings-registry.test.ts`、`tests/unit/models-config-pages.test.ts`（页栈当纯数据测）。
3. **上次停留分区的 storage 模块**：往返一致、存储不可用时返回空、存量值不认识时返回空。先例：`lib/client/last-used-model.ts` 那套「可注入 storage + 静默失败」的形状（当前无同名单测，本模块应补最小一份）。

不新增 seam，不新增测试基建。弹窗自身的接线由人工 smoke 覆盖：切遍 10 页、脏页圆点、脏页拦截、丢弃后关窗不再二次确认、窄视口不溢出、子代理编辑弹窗照常开合。

## Out of Scope

- 把设置变成真路由页（`/settings/…`）、深链、前进后退。
- 窄屏下把左侧导航折叠成横向 tab 或抽屉 —— 本次只补弹窗宽度的 `min()` 兜底。
- 切页过渡动画、每页滚动位置记忆、键盘快捷键、导航图标。
- 把子代理编辑器改造成第三级页。
- 改动保存语义、接口契约、服务端任何东西。
- 收编右侧面板里那批已经是分页形态的视图（Models config / MCP / Skills / Scheduled tasks / Channels）。

## Further Notes

动手前需要先确认两件事：Append System Prompt 与 Subagent settings 两页没有隐藏的跨页耦合（比如页面卸载时触发的副作用），以及 `data-scroll-wide` 的滚动条皮肤在切页后是否还落在正确的滚动容器上。

本次改造会顺带删掉一整层「用 DOM 属性当信息架构」的机制（`data-settings-section` + IntersectionObserver + `scrollIntoView`），这是它最大的收益：导航的事实从此只存在于注册表里。
