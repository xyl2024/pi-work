# 会话级权限模式（完全访问 / 确认危险命令）

Status: done

Tickets: `issues/01` … `issues/05`（见 `.scratch/permission-mode/issues/`）

## Problem Statement

Pi Work 的**危险命令确认网**是一张全局的、进程级的网：`~/.pi-work/config.yaml` 里的用户规则 + 平台内置规则集，每次 agent 调用 shell 工具时在 `tool_call` 钩子上过一遍，命中就停下来等用户在三值决定（allow once / allow similar / deny）里选一个。它有两条替代路径：手改配置关掉用户规则（内置集仍在，见 ADR-0020），或者在弹窗里点一次「本次会话允许同类」——而这后一条的粒度是**一条规则名**，不是「这个会话不用再问我」。

于是有一个稳定的场景撞在上面：用户已经信任这个会话了——他在自己的机器上、在熟悉的仓库里、刚看完 agent 要干的那几件事，接下来半小时只是 `git status`、`pytest`、`rm -rf .venv`、`npm test` 这类他自己也会敲的东西。他没想降低安全要求，他只是不想为第 17 条命令再点一次「允许一次」；点「本次会话允许同类」又不够，因为那记的是规则粒度，换一条规则又要问。pi CLI 本身没有这层确认，所以从 CLI 迁过来的用户第一反应就是「这玩意怎么一直在弹」。

现在没有任何办法表达「这个会话我授权到底」，除非去改全局配置——而那是个比弹窗更重的动作，且对所有会话、所有频道、所有定时任务同时生效。

## Solution

在**对话输入区**加一个会话级的**权限模式**开关，两档：

- **确认危险命令**（`confirm`，默认，等于今天的行为）
- **完全访问**（`full_access`）：本会话内命中危险命令规则时不再中断询问，命令直接执行。

完全访问是**每个会话**的事，不是全局配置：改它不影响别的会话、不影响频道、不影响定时任务。它由**人**在界面上打开（工具栏盾牌按钮或命令面板），点击即生效、无二次确认；打开后输入区描边与按钮转红，会话标签页与侧栏行挂红色盾牌徽章，Tooltip 写清它放过了什么、没放过什么。

它**不**放过**自保护**：`pkill node`、`kill $PPID`、`fuser -k <本服务端口>/tcp`、`shutdown` 这类会杀掉本服务进程的命令仍然是硬拦截，无提示、无豁免、不可配置——因为那一条不是「命令危险」，而是「把承载所有会话、SSE 流、终端与后台循环的进程干掉」。

它也不改弹窗里那三值的语义、不改规则配置页、不给 agent 任何感知或影响这个模式的路径。

## User Stories

1. 作为一个已经在自己的仓库里跟 agent 干活的用户，我想把一个会话改成完全访问，这样我不用为每一条 `rm -rf`、`pytest`、`git clean` 点一次允许。
2. 作为一个只改了此刻这个会话的用户，我想别的会话、频道会话和定时任务会话仍然是确认模式，这样我的授权不会意外扩散到我看不见的地方。
3. 作为一个打开完全访问的用户，我想看到输入区的按钮和边框变红，这样我知道下一次危险命令不会弹窗。
4. 作为一个打开完全访问的用户，我想在 Tooltip 里读到它到底放过了什么、没放过什么，这样我不会以为它把我的机器整个交出去了。
5. 作为一个在完全访问会话里干过活的用户，我想在会话标签页和侧栏行看到红色盾牌徽章，这样我关掉再打开这个会话时不会忘了它还在那个状态。
6. 作为一个关掉再打开会话的用户，我想完全访问仍在那儿（而不是被静默重置），这样我不用每次重开会话都重新设一遍。
7. 作为一个新开会话的用户，我想新会话一律回到确认模式，这样「我没设过，它怎么不问我就跑了」不会发生。
8. 作为一个切换工作目录的用户，我想权限模式不跟着 cwd 走，这样同一目录下的新会话不会继承上一个会话的授权。
9. 作为一个点错了的用户，我想再点一次就切回确认模式，且不需要二次确认，这样关掉它和打开它一样便宜。
10. 作为一个切回确认模式的用户，我想之前在完全访问期间发生的「本次会话允许同类」不残留，这样我切回来时不会发现某些规则莫名其妙不再问我。
11. 作为一个点开完全访问的用户，我想正在等待我确认的那条命令仍然在等我，这样一次点击不会替我批准一条我还没看的命令。
12. 作为一个看弹窗的用户，我想完全访问期间的命令不再产生新的弹窗，这样我预期中的「别再问我」是真的。
13. 作为一个在完全访问会话里敲命令的用户，我想 agent 尝试 `pkill node` 时仍然被拦下，这样我的一次误操作不会带走整个服务端（所有会话、终端、定时任务、频道循环）。
14. 作为一个被自保护拦下的用户，我想看到一句直白的理由是「这会杀掉 Pi Work 的服务进程」，这样我不会反复找那个不存在的开关。
15. 作为一个用 ⌘K 的用户，我想在命令面板里切换权限模式，这样这个开关不必只藏在一个小图标上。
16. 作为一个用户，我想命令面板里的这一条只在有会话时出现，这样草稿上不会出现一个不生效的开关。
17. 作为一个用户，我想完全访问的开关**不**出现在斜杠命令、工具或任何 agent 可达的路径上，这样给我发微信消息的陌生人无法用一句话把闸门关掉。
18. 作为一个用户，我想 agent 不知道自己处在哪个模式（它会照常报告「这条命令需要确认」之类的预期），这样它不会把「现在是完全访问」当成一个可以劝我切换的论据。
19. 作为一个在频道会话里干活的用户，我想完全访问只在我显式打开的那个会话里生效，冷启动不会自动继承，这样无人值守的路径不会悄悄变成无确认。
20. 作为一个在子代理里跑命令的用户，我想子代理会话默认仍是确认模式，且它们的命中仍会快速拒绝而不是等一个没人答的弹窗，这样子代理不会卡住。
21. 作为一个用户，我想在侧栏里的会话徽章和工具条按钮上看到同一个状态，这样两处不会打架。
22. 作为一个用中文界面的用户，我想这个开关的按钮、Tooltip、徽章、命令面板条目都是中文，这样它和输入区其他控件一致。
23. 作为一个用键盘的用户，我想切换后焦点不丢，这样我可以直接接着输入。
24. 作为一个排查问题的维护者，我想权限模式落在一个可读的、按会话隔离的文件里，这样我能看出某个会话为什么没弹窗。
25. 作为一个接手代码的维护者，我想「完全访问」放过什么、不放过什么的顺序只在一个地方决定，这样我不用在两个分支里对齐语义。
26. 作为一个维护者，我想这个决定有 ADR 记录并明确取代 ADR-0020 里「内置规则不得整体关闭」那一段，这样下一个人再问「能不能加个总开关」时有得引用。
27. 作为一个维护者，我想 `CONTEXT.md` 里有「权限模式」的词条、且「自保护」词条注明它在完全访问下仍不放行，这样词汇和实现不会漂移。
28. 作为一个维护者，我想覆盖旧数据的兼容：没有侧车文件的会话读出来就是确认模式，这样升级不会改变任何既有会话的行为。

## Implementation Decisions

### 边界（ADR-0021，取代 ADR-0020 的「整体可关闭」那一段）

- 新的不变量措辞：**闸门在每一处，除非有个「人」在「某一处」显式声明他清楚代价；自保护例外。**
- ADR-0021 必须点名 ADR-0020 里被取代的那段（「让内置规则逐条可停用或整体可关闭…收回的是『闸门一定在』这条唯一的不变量」），并说明为什么会话级豁免不构成同一条滑坡：它是 per-session 的、由人点出来的、可见常驻的、默认关闭的，且不改变全局规则集的语义。
- 完全访问的放过范围：**只放过危险命令规则的命中**。自保护在任何模式下都硬拦。
- 完全访问 **不** 放过：自保护、`PermissionDialog` 的三值语义、子代理会话的快速拒绝（它在确认模式下才被走到）、任何非 shell 工具的判定（今天也只有 shell 会进闸门）。
- 命名：短标签「完全访问」，英文 `Allow full access`；另一档「确认危险命令」，英文 `Confirm dangerous commands`。Tooltip 必须带边界说明（英文形如「Everything except self-protection runs without asking」）。

### 状态与作用域

- 权限模式是**每个会话一份**，随 `AgentSessionWrapper` 存活。
- 持久化到**侧车文件**：`~/.pi-work/session-permission-mode/<session-id>.json`，内容是 `{"mode": "confirm" | "full_access", "updatedAt": "..."}`。形状照 `session-tools` / `session-notify` 这两个既有侧车（原子 tmp+rename 写、文件名限安全字符集、`~/.pi-work` 数据根、`PI_WORK_DATA_DIR` 覆盖）。
- 读回时机：会话启动（`startRpcSession`）时读，缺失即 `confirm`。
- **没有**全局默认、没有按 cwd 记忆、新会话不继承上一个会话。改默认值的入口一概不做。
- 不写会话 JSONL：JSONL 是 pi 的私有格式，我们只往里写 pi 自己定义的 entry 类型。

### 判定顺序（唯一的一处）

- 现有的唯一顺序点（`evaluateDangerousCommand`，它此前就明确承担「先自保护、后规则匹配」的职责）扩一个模式参数，成为唯一的分叉点：`confirm` 下行为不变；`full_access` 下**自保护仍然先判定并返回硬拦截**，命中规则则视为 `none`。
- `AgentSessionWrapper` 的工具调用钩子只把当前模式传进去，不再自己分叉。钩子里的非 shell 早退保持不变。
- 挂起的闸门在模式切换瞬间**不动**：切换只影响之后的工具调用。切到完全访问时不自动批准任何待决请求，切到确认模式时也不取消或拒绝任何待决请求。

### 会话级备忘（「本次会话允许同类」）

- 完全访问期间不查、不写备忘（判定根本不进闸门，因此天然如此）。
- 切回确认模式时**清空**备忘：这是同一层「本会话的授权」被撤销时的连带撤销，避免出现「切回确认后某些规则仍静默不问」。

### 协议（会话事件与 RPC，ADR-0007 的类型清单）

- 新会话事件 `permission_mode_changed`，载荷 `{ mode }`，照 `thinking_level_changed` 的模子接入：事件联合类型、归约后的类型清单、归约分支（写进会话运行时状态）、重放白名单按它的语义决定（它是活事件，不是回放事件）。
- 会话运行时状态新增一个字段承载它，客户端由它驱动按钮、描边、徽章与命令面板状态。
- `get_state` 快照回传当前 `permissionMode`，否则重挂载后客户端只能等一次事件。
- 新 RPC 命令 `set_permission_mode`，载荷 `{ mode }`；服务端校验取值、写侧车、更新 wrapper、回事件。未知值按「不认识的命令参数」处理，不得默认当成 `full_access`（ADR-0008 记的那条「未知决定等价于放行」的坑不要在这里重演）。

### 界面

- **工具栏按钮**：常驻在工具选择按钮右侧，图标按钮，未激活为中性色、激活为红色；点击即切换；带 Tooltip（短标签 + 边界说明）。沿用工具条既有的图标按钮 + Tooltip 写法。
- **输入区**：激活时输入容器描边转红。这是「下一次不会弹窗」的唯一常驻提醒。
- **徽章**：会话标签页与会话侧栏行各一枚红色盾牌，跟状态同步。
- **命令面板**：新增一条「切换到完全访问 / 切换到确认危险命令」，仅在有当前会话时出现，走同一变更路径。
- **不给**斜杠命令入口、不给 agent 工具、不把模式注入系统提示词；agent 完全不知道这个状态。
- 文案进权限相关的那份 i18n 子字典（与 `PermissionDialog` 同一份），因为这是同一个权限语义的延伸；不进输入区那份。
- 切换后焦点留在触发元素上，键盘操作不丢焦点。

### 文档

- 新增 ADR-0021（措辞见上）。
- `CONTEXT.md` 新增词条**权限模式（Permission mode）**，`_Avoid_`: 别再叫它「权限」「授权」「yolo」；明确它不是**危险命令规则**（那是网本身），不是**自保护**（那不可关），也不是**交互闸门**（那是等待状态）。
- `CONTEXT.md` 的**自保护**词条补一句：即使会话处于完全访问也不放行。
- 顺手修正 `CONTEXT.md` 的**交互闸门**词条：它写的第二种形态「一次代价高的建索引」在代码里已不存在（ADR-0011 删除 codegraph 时漏改），`runPermissionGate` 全仓只有一个调用点。

## Testing Decisions

好的测试只看**外部行为**：给定一条命令和一种模式，判定结果是什么；给定一次模式切换，会话级备忘还剩什么；给定一条事件，客户端状态变成什么。不测按钮的 CSS、不测内部方法调用次数、不为了断言而在生产代码里加钩子。

复用既有缝隙，不新增跨层缝隙：

- **判定矩阵**（唯一新增的缝隙，且是既有的最高点）：危险命令判定函数加模式参数后，覆盖 `{confirm, full_access} × {自保护命中, 用户规则命中, 内置规则命中, 不命中}` 四类组合，重点钉 `full_access + 自保护 = 仍然硬拦截`。同文件里既有针对自保护和规则匹配的用例，照它们的写法扩。
- **会话级备忘**：复用交互闸门的既有测试，覆盖「切回确认模式后备忘清空」与「待决闸门在切换时不被自动批准」。
- **会话事件归约**：复用会话事件的既有测试，覆盖新事件分支把模式写进运行时状态、以及未知/缺字段时不崩。
- **侧车读写**：照 `session-notify-binding` 与工具选择侧车的既有测法，覆盖缺失文件→`confirm`、往返一致、非法 mode 值不被信任、文件名不安全时拒绝。
- **RPC 参数校验**：未知 mode 值不被当成 `full_access`，可直接测服务端处理函数，照 `dangerous-commands-route` 这类 API 契约测试的写法。

不启动服务、不做 UI 自动化测试。

## Out of Scope

- 全局或按 cwd 的默认权限模式。
- 斜杠命令 / agent 工具 / 环境变量形式的开关。
- 让自保护可豁免，哪怕在完全访问下。
- 在聊天里给被放行的危险命令加「已跳过确认」标注（状态本身已由红边与徽章承担）。
- 改变 `PermissionDialog` 的三值决定，或加第四种「本会话内全部允许」按钮。
- 改变规则配置页与 ADR-0020 里已经定下的规则集语义。
- 顺手抽取公共的 per-session 侧车模块（`session-names` / `session-tools` / `session-notify` 已有三份同形实现）：本次按最小改动再加第四份同形实现，抽取另开议题。
- 权限模式的审计日志（命令原文本来就在会话 JSONL 的工具调用里）。
- 频道、定时任务侧的任何新逻辑（它们只是「某个会话」而已）。

## Further Notes

- 完全访问把**服务端进程自身**暴露给了 agent 的一部分动作，这是本次改动最实质的风险，也是为什么自保护被单独留下来：pi CLI 被杀只死一个终端，Pi Work 服务端被杀会带走所有会话、SSE 流、终端 WebSocket、定时任务循环与频道循环。
- 「不给 agent 感知」这一条是有意的：把一个「现在没人看着」的信号写进上下文，等于给 prompt injection 提供了一个可优化的目标。
- 频道入站消息是外部可控内容，这是「开关只由人点」这条约束的真实来源，不是洁癖。
- 已知的既有坑，不要在新代码里重演：交互闸门对决定载荷不做校验，未知字符串等价于放行（ADR-0008 记录）。新的 RPC 参数校验必须显式枚举合法值。
