# 02: 会话级完全访问真的不弹窗了

**What to build:** 一条完整的路径。用户在对话输入区把**当前会话**切到完全访问，之后这个会话里 agent 命中危险命令规则时不再中断询问，命令直接执行；再点一次切回确认模式，弹窗恢复。全程不影响任何其它会话。

同一条路径上还要成立三件事：**自保护在两种模式下都仍然硬拦**（`pkill node`、`kill $PPID`、`fuser -k <本服务端口>/tcp`、`shutdown` 这类会杀掉本服务进程的命令，无提示、无豁免）；**切回确认模式时，完全访问期间本会话记下的「本次会话允许同类」一并撤销**；**切换瞬间已经挂起的确认弹窗不动**——切到完全访问不自动批准任何待决请求，切回确认也不取消或拒绝任何待决请求。

这一票交付的是可用而不是好看：按钮只要能切、状态只要对得上就够了，红边、徽章与 Tooltip 边界文案留给 04。

模式必须**只由人**改动：不给斜杠命令入口、不给 agent 工具、不把当前模式注入系统提示词，agent 完全不知道这个状态。RPC 参数要显式枚举合法值，未知值不得被当成完全访问（不要重演「未知决定等价于放行」那个既有坑）。

## Comments

- 分叉点唯一：`evaluateDangerousCommand(command, mode)` 里先自保护、再判模式、最后匹配规则
  （`mode === "full_access"` 直接返回 `none`）；`tool_call` 钩子只把 `wrapperRef.current?.permissionMode`
  传进去，自己不分叉。判定矩阵在 `tests/unit/permission-mode.test.ts`：两模式 × 自保护 / 用户规则 /
  内置规则 / 不命中，外加「模式省略 = confirm」「未知模式 = confirm」两条。
- 模式住在 wrapper 上（`_permissionMode`），构造时从侧车读回；`get_state` 回传 `permissionMode`，
  新事件 `permission_mode_changed` 走 ADR-0007 的类型清单 + 归约分支（未知值不移动状态），
  新 RPC `set_permission_mode` 用 `isPermissionMode` 显式枚举，未知值抛错且不改当前状态。
- 切回确认模式时 `gates.clearSessionMemo()`；切换不动待决闸门（有一条测试专门盯「切换前后 pending
  仍然 pending，且只有用户能决定它」）。备忘本身有测试：`allow_similar` 后同规则不再问；切走再切回
  确认后同一规则重新弹窗。
- 界面这一票只做到「能切、状态对得上」：`BottomToolbar` 一枚盾牌按钮，点击即切换、无二次确认；
  `ChatWindow` 把 `permissionMode` 从 `useAgentSession` 传下去，并把它注册进 `AgentControls`
  （命令面板后面那一票用）。
- 自保护的拒绝文案补上了直白理由：`The command was blocked by self-protection: <reason>…`。原文案只有
  「被拦下了」，用户问「为什么」时它不算答案；这一条同时被 `dangerous-commands.test.ts` 的源码级
  守卫钉住。
- **未完成的两条 smoke 需要人点一下**（本次没有擅自起服务跑 UI）：把当前会话切到完全访问 → 让 agent 跑一条
  命中规则的命令（应直接执行、无弹窗）→ 切回确认危险命令 → 同一条命令应重新弹窗；然后在完全访问下
  让 agent 跑一条会杀服务进程的命令，应被拦下且理由里出现具体说明而不是只有「被拦下了」。
