# 05: 守——名字约束与超时字段

**What to build:** 让「配错」在保存前就被挡住，而不是变成一个安静的错误。名字重复、或与内置规则同名，保存被拒并指出冲突对象——因为**规则名就是会话级「总是允许」的备忘键**，重名会让一次放行同时放过两条规则，也会让确认弹窗显示的名字和用户以为的那条对不上。超时改成页面上可编辑的数值；非法值被拒绝，而不是静默回落到默认值（静默回落是手改配置文件时代的妥协，有界面之后就是在替用户猜）。

**Blocked by:** 03（写——新增一条规则，保存即生效）

**Status:** done

- [x] 名字重复、与内置规则同名时保存被拒，错误文案指出冲突的是哪一条
- [x] 阻断项的判定顺序固定：名字为空 → 名字重复 → 与内置冲突 → 正则为空 → 正则编译失败 → 超时越界（一次只报一个）
- [x] 超时可在页面上编辑，越界或非数值被拒绝而不是静默回落默认值
- [x] 测试：纯模块覆盖冲突名、撞内置名、超时越界三个阻断项及其顺序；接口覆盖冲突名返回 400
- [x] 「接受灾难性回溯（ReDoS）风险、不做静态分析」这个决定写成代码注释，不留成沉默

## Comments

- 阻断项模型：`lib/shared/dangerous-commands-draft.ts` 的 `DangerousRuleProblem` 改成判别联合——
  行级问题带 `index`（页面标红哪一行），超时是 `{ kind: "timeout" }`，不再用 `-1` 这种哨兵值，
  读它的三处（页面、编辑器、写路由）因此都不需要知道「负 index 是什么意思」。
- 判定顺序在 `dangerousRulesDraftProblem()` 里逐条集中：空名（全表）→ 表内重名 → 撞到表外名字
  （编辑器传进来的其它行）→ 撞内置名 → 空正则 → 编译失败 → 超时。每条都是先扫完全表再进下一条，
  所以报的是「下一个该修的东西」，不是「下一行」。
- 重名的报法：表内重名报**后出现的那一行**并带上 `conflictIndex`（先占用的行），文案是
  「第 3 条规则：名称“rm”已被第 1 条规则占用。」；编辑器的单行校验由页面把其它行以
  `takenRules: { name, index }[]` 传进来，所以行号也是用户看到的行号，而不是「另一条规则」。
- 撞内置名的来源不是第二份规则表：写路由用 `defaultDangerousRuleNames(process.platform)`
  （`lib/shared/dangerous-commands.ts`），页面用 `GET /api/dangerous-commands` 已在列的
  `builtins`，两边都是同一份生效集。
- 超时：页面上是可编辑的文本框（`Confirmation timeout (ms)`），范围
  `DANGEROUS_RULE_TIMEOUT_MIN_MS`(1s) ～ `DANGEROUS_RULE_TIMEOUT_MAX_MS`(24h)。输入框保留原始文本，
  草稿里存解析后的数值（解析失败为 `NaN`），所以 `abc` / 空 / `500` / `90000000` 都会被拦下并
  在字段下方说明，而不是静默改回默认值。写路由同样拒绝越界值（400），磁盘不动。
- 读路径故意保持宽松（`lib/server/config.ts` 不变）：手改出来的越界值仍会被加载和使用，页面把它报成
  阻断项直到改好——和「手改坏正则不会消失、只是被标红并拒绝保存」是同一条先例，理由写在超时常量上方
  的注释里。
- 整数没有强制：范围检查就够（`NaN`/`±Infinity` 天然落到范围外），`1500.5` 这类值无害，不额外造约束。
- ReDoS：`dangerous-commands-draft.ts` 顶部注释写明「不做静态分析、不做运行时超时」及其威胁模型理由
  （命令串通常 <1KB；能改配置的人本来就能改规则）。
- 测试：`tests/unit/dangerous-commands-draft.test.ts` 新增重名（含 `conflictIndex`）、编辑器的
  `takenRules`、撞内置名、六条判据的完整顺序（含「空名压过重名」「重名压过撞内置」）、超时上下界
  与越界；`validateDangerousRulesWrite` 新增重名 / 撞内置 / 超时越界。`tests/unit/dangerous-commands-api.test.ts`
  走真实 HTTP 覆盖重名 400、撞内置名 400、超时写入成功 + 越界 400 且磁盘保持上一次写入值。
  全量 `pnpm test` 108 文件 / 1369 用例通过；`tsc --noEmit` 与 eslint 干净。
- 代码审查（Standards + Spec 两轴）后收敛：`-1` 哨兵换成判别联合；写路由的「超时」判据走同一条
  `dangerousRulesDraftProblem`（原来另写一遍，且一旦命中会读到 `rules[-1]` 并落进错误分支）；
  编辑器补上行号；表内重名与表外重名各自一个扫描函数，不再共用会报错行的循环；超时字段在没有草稿时
  跟随磁盘值，避免出现「陈旧输入框 + 新基线」；去掉整数约束与对应的文案。
- 人工 smoke（未做，交给 06 统一过）：改一条规则的名字撞内置名 → 保存被拒并指出是哪条；把超时改成
  `abc` / `0` → 字段标红且保存按钮按下无效；改成 `60000` → 保存成功并立刻生效。
