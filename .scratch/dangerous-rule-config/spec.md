# 危险命令规则的可视化配置

Status: ready-for-agent

## Problem Statement

危险命令规则是 Pi Work 唯一一张「agent 想跑灾难性命令时先停一下问人」的确认网，但它今天只有一个入口：手改 `~/.pi-work/config.yaml`。这带来三个具体的难受之处。

第一，**门槛错配**。会写 YAML、会写正则的人本来就不太需要这张网；真正需要它的人和它之间的距离是两件毫不相干的技能。

第二，**写错了没有反馈**。配置只做形状校验，正则编译失败要到匹配那一刻才被跳过并记一行服务端日志。用户以为配上了，实际上那条规则从来没生效过，而这一点在界面上完全看不出来。

第三，**现状不可见**。用户看不到平台内置的那套规则（9 条 bash、Windows 上另有 6 条 PowerShell），也不知道自己那份配置清空之后闸门仍然在。于是「我把规则清空了，所以它不会再拦我了」成为一个很自然、又完全错误的推断；同理，试一条命令时得到的「没有命中」也可能只是内置集之外的那几条自保护红线在起作用——而自保护根本不在这个配置项的语义范围内。

## Solution

在设置弹窗里新增一页**危险命令**（属于 Agent 分组），把这张确认网摊开成三块：

- **你的规则**——可增删改、可上下移动的可编辑列表，每条是名字 + 正则 + 是否忽略大小写；保存前全量编译，任何一个字段或正则不合法都会被指出来并拒绝提交。
- **内置规则**——按当前平台算出来的那一套，只读展示，附带一句「清空上面的列表不会关掉这些」。
- **试一条命令**——输入一条命令，得到三档结果之一：不可配置的硬拦截（自保护）、命中某条规则（标明是你的还是内置的）、不命中。判定走服务端，和真实拦截走同一份生效集。

保存即生效，不需要新建会话；页面里不该出现任何相反暗示。

## User Stories

1. 作为一个不写 YAML 的用户，我想在设置里直接加一条危险命令规则，这样我不用去翻配置文件。
2. 作为一个不会写正则的用户，我想看到内置规则长什么样，这样我能照着改出一条自己的规则。
3. 作为一个写了坏正则的用户，我想在保存时就被拒绝并看到是哪一条哪一处错了，这样我不会以为它生效了而其实没有。
4. 作为一个写了空正则的用户，我想被明确拒绝（并被告知空正则匹配一切、等于每条命令都弹窗），这样我不会意外把确认网变成噪音源。
5. 作为一个想给规则起名的用户，我想在名字重复、或与内置规则同名时被拦住，这样我不会因为一次「总是允许」而同时放行两条规则。
6. 作为一个调整规则的用户，我想把某条规则上移或下移，并且看到「顺序只影响命中时显示和记忆的规则名」这句说明，这样我知道顺序不是没意义的装饰。
7. 作为一个用户，我想在改完规则后点一次保存就生效，这样我不用重启服务、也不用新建会话来验证。
8. 作为一个用户，我想在切到别的设置页或关掉设置弹窗时被提醒有未保存的规则改动，这样我不会丢掉刚写的一半。
9. 作为一个用户，我想调整「等用户确认多久算超时」，这样长时间没人应答的场景下不会每次都干等五分钟。
10. 作为一个用户，我想在页面上看到当前平台的全部内置规则，这样我知道哪些灾难性命令已经有人兜底了。
11. 作为一个用户，我想在新装机器上什么都不配就有兜底（而不是先有一条静默的空白），这样我不会因为从没配过而以为闸门关着。
12. 作为一个把用户规则清空的用户，我想看到「内置规则仍在生效」这句话，这样我不会把清空误读成关闸。
13. 作为一个用户，我想试一条命令，看看它会不会触发确认，这样我在写规则时能立刻验证而不是靠猜。
14. 作为一个用户，我想在试命令的结果里区分「会弹确认」和「直接被硬拦」，这样我不会把两者当成一回事。
15. 作为一个用户，我想知道命中的是我自己的规则还是内置规则，这样我能判断该改哪一边。
16. 作为一个用户，我想知道命中的是哪一条规则名，这样我能对得上确认弹窗里显示的名字。
17. 作为一个 Windows 用户，我想在内置规则列表里看到 PowerShell 那一套，这样我知道 `Remove-Item -Recurse -Force` 也在网里。
18. 作为一个 Linux/macOS 用户，我不想在列表里看到根本用不上的 PowerShell 规则，这样这页不会被与我的机器无关的内容塞满。
19. 作为一个用户，我想删掉某条规则，这样误报的规则可以立刻下线。
20. 作为一个用户，我想知道自保护拦下的那种命令为什么在页面上改不了，这样我不会反复找开关。
21. 作为一个用户，我想在页面里看到「这是确认不是拦截」这件事，这样我不会期待 agent 的命令被直接杀死。
22. 作为一个在子代理里跑命令的用户，我想知道子代理的命中会立刻被拒绝而不是弹出无人应答的确认，这样我不必困惑于子代理为什么卡住。
23. 作为一个用中文界面的用户，我想这页的全部文案（含错误提示、测试结果三档、空列表说明）都是中文，这样它和设置里其他页保持一致。
24. 作为一个用户，我想这页和其他设置页长得一样（页标题、说明、保存按钮三态、未保存提示），这样我不用学第二套交互。
25. 作为一个维护者，我想「规则能不能被关掉」这件事有 ADR 记录，这样别人再提「加个总开关」时我有得引用。
26. 作为一个维护者，我想校验逻辑是一个纯模块，这样我不启动服务也能测遍所有错误分支。
27. 作为一个维护者，我想写通路的 HTTP 契约可测，这样「坏正则返回 400 而不是 200」这种约定不会漂移。

## Implementation Decisions

### 边界（ADR-0020）

- 可配：**危险命令规则**的用户规则列表 + 「等确认多久算超时」。
- 只读：当前平台的**内置规则集**。不提供逐条停用，也不提供整体关闭——内置集是 floor，不是默认值；清空用户规则不等于关掉闸门。
- 不出场：**自保护**。连只读列表都不放。它一旦出现在设置页，无论标不标只读，都会被读成「将来能关」。这一页只在「试一条命令」的结果里承认它存在。
- 动作不变：本轮只有「确认」。不引入每条规则可选「直接拒绝」，也不引入全局严格模式。三值决定（allow once / allow similar / deny）原样保留。
- 作用域：全局。不做 per-cwd、不做 per-session。规则集与超时都是进程级事实。

### 页面

- 位置：设置弹窗，**Agent** 分组，分区 id `dangerous-commands`，标签文案 `Dangerous commands`（中文「危险命令」）。id 与共享模块同名，避免「页面叫什么」和「代码里叫什么」成为两件事。
- 排布：上半「你的规则」（列表 + 右上新建）、中间「内置规则」（只读）、下半「试一条命令」。保存按钮在页尾，与其它待保存项页面一致。
- 列表行显示：名字、正则原文（等宽字体、超长截断）、忽略大小写开关的可读状态、上移/下移、删除、编辑。列表顶部一行提示说明顺序的唯一语义。
- 编辑形态：新建与编辑都开一个独立的弹层编辑器（与子代理编辑器同形），因为一条规则要放名字、正则、大小写开关和行内错误，行内编辑会与排序按钮打架。
- 用户规则为空时，列表位置显示一句说明：没有自定义规则，且以下内置规则仍在生效。
- 保存控件复用已有的三态保存按钮与「未保存」提示；本页属于**待保存项**（自由文本按用例归入显式保存），并纳入设置弹窗的未保存改动登记（否则切页/关窗不会提醒）。
- 保存失败沿用既有乐观更新 + 回滚。
- 页面文案全部进设置用的 i18n 字典；权限确认弹窗那一份词汇表不动，因为测试结果的标签是这一页的东西，不是闸门的公共词汇。

### 写通路（API 契约）

- 新增一条独立路由承载这个配置项的读写，**不**并入 `PUT /api/settings` 的 owned-key 机制。理由：owned key 的语义是「客户端持整份配置、diff 出变更的顶层键」，而这一页要的是**服务端算出来的生效集**（含平台分叉与编译结果），形状对不上；且独立写口在仓库里已有先例。
- 写入是读-改-写整份配置：服务端读出磁盘配置，只替换这个配置项，写回。客户端不持有整份配置。
- 读用两条：用户规则与超时随现有的 `GET /api/settings` 一起下发（它本来就返回整份配置）；新增的 `GET` 只补客户端拿不到的部分——平台与内置集，外加**用户规则里编译失败的那几条**。
- 契约形状（本文只钉字段语义，不钉实现）：

  ```ts
  // GET 生效集
  { platform: string,
    builtins: { name: string; pattern: string; ignoreCase?: boolean }[],
    invalidUserRules: { name: string; error: string }[] }

  // PUT 保存（整组替换；服务端在写盘前编译全部正则）
  { rules: { name: string; pattern: string; ignoreCase?: boolean }[],
    timeoutMs: number }

  // POST 试一条命令
  // 请求 { command: string }
  // 响应三选一，且一定同时带上规则来源
  { kind: "self_protected"; reason: string }
  | { kind: "matched"; ruleName: string; source: "user" | "builtin"; selfProtectionReason?: string }
  | { kind: "none" }
  ```

  关于 `matched` 上那个可选字段：自保护与规则可能同时成立，真实行为是自保护先赢（硬拦）。为了不让测试结果与真实行为分叉，两个同时成立时返回的就是 `self_protected`（自带自保护的理由），`matched` 不会出现这个字段——02 落地时按此收敛，契约里的 `matched` 只有规则名与来源（见 issue 02 的 Comments）。

### 校验（保存前的唯一门槛）

- 一次只报**一个**阻断项，按固定顺序：名字为空 → 名字重复 → 名字与内置冲突 → 正则为空 → 正则编译失败 → 超时越界。先后顺序固定是为了错误文案可预测、可测。
- 名字必须非空、规则之间唯一、且不与内置规则同名。理由是规则名就是会话级「总是允许」的备忘键——重名会把两条规则合并成一次放行。
- 正则 `trim()` 后为空一律拒绝：`new RegExp("")` 编译通过且匹配一切，存进去等于每条命令都弹确认。
- 超时必须是有限正数；不合法即阻断项，而不是静默回落到默认值（静默回落是 yaml 手改时代的妥协，UI 上有义务说出来）。
- 灾难性回溯（ReDoS）**明确接受**，不做静态分析、不做运行时超时：命令串通常不到 1KB，而能改这份配置的人本来就能改规则本身。这个「接受」要写成代码注释，不留成沉默的决定。

### 试一条命令

- 判定在服务端。自保护那一档需要本进程的 pid 与监听端口，客户端算不出来；而一档在服务端、一档在客户端会长出两份「什么叫命中」的真相。
- 判的是**生效集**，不是正在编辑的那一条正则。所以这个输入框在页级，不在编辑器里。
- 结果三档文案：不可配置的硬拦截 / 命中规则（附来源标签：你的规则、内置规则）/ 不命中。
- 空命令直接视为「不命中」，不发请求。

### 生效时机

- 保存即生效。匹配发生在每次工具调用的钩子里，配置读取按文件 mtime + size 失效，规则编译结果按「平台 + 规则内容」做缓存键。页面里不出现任何「需新建会话」的提示，也别在代码里改成会话级快照。

### 文档

- 已落地的：ADR-0020（危险命令规则可配、floor 与自保护不可配）、术语表补两条词条（危险命令规则、自保护）。
- 实施时若发现实现与 ADR-0020 冲突，先改 ADR，不要在代码里另立一套。

## Testing Decisions

好的测试只断言外部行为：给一组输入，断言返回的判定/状态码/响应体；不断言内部调用了哪些函数、不 mock 依赖袋、不为覆盖率断言实现细节。三处缝合（已与维护者确认）：

1. **共享纯模块（新增，主缝）**——一个 draft/校验模块，形状照仓库里已有的同类模块：把「服务端状态 + 当前平台」转成可编辑草稿、算出那唯一一个阻断项、算出要提交的请求体、以及上移/下移。全部纯函数，vitest 直接 import，不启动服务、不用 cookie。这是错误分支的主战场：空名、重名、撞内置名、空正则、坏正则、超时越界、移动边界。
2. **隔离实例的 HTTP 缝（复用现成做法）**——GET 生效集、PUT 往返（写后 GET 一致，测试结束恢复原状）、坏正则 400 且磁盘未被改写、名字冲突 400、`POST /test` 三档结果各一条。先例是设置接口那份测试的「快照 → 可逆改动 → 断言 → 恢复」写法。
3. **既有纯匹配器测试不动**——匹配器契约（内置集内容、平台分叉、用户规则在前、首个命中胜）已经在测，本次不改匹配语义，所以不加断言；设置注册表的一致性测试会自动覆盖新分区 id（注册了分区却没实现页会编译失败）。

**不覆盖**：React 页的接线（列表渲染、编辑器弹层、保存按钮三态、切页提醒）。这与 ADR-0019 的既定立场一致——组件接线走人工 smoke，纯模块与接口走自动化。

人工 smoke 清单（实施完成后手过一遍）：新增一条规则 → 保存 → 在真实会话里跑一条匹配的命令 → 确认弹窗出现且规则名对得上；把这条规则的正则改坏 → 保存被拒且页面标红；清空全部用户规则 → 页面出现「内置仍在生效」；输入 `pkill node` → 测试框落在「硬拦截」而不是「不命中」；有未保存改动时切页/关窗 → 提醒出现。

## Out of Scope

- 每条规则可选「直接拒绝」（block）或全局严格模式。这是权限模型扩张，需单独一篇 ADR。
- 内置规则的逐条停用或整体关闭。
- 自保护规则的可见化、可配化。
- per-cwd 或 per-session 的规则作用域（会牵动配置读取签名、缓存键，以及 ADR-0009 记录过的读-改-写丢更新问题）。
- 会话级「总是允许」备忘的可视化、撤销或持久化。
- 结构化预设式规则编辑（不让人碰正则）。
- 拖拽排序（只做上移/下移）。
- 静态 ReDoS 分析、正则运行时超时。
- 每条规则独立超时。
- 危险命令规则的导入/导出。

## Further Notes

- 这一页真正的新价值是**「试一条命令」+「保存前编译」**：它们把「配了但没生效」从沉默变成可见。列表编辑本身只是把 YAML 搬到界面上；如果时间紧，先做这两块也说得通。
- 术语上，「命令拦截规则」这个说法会被这张网的实际行为打脸：它不拦，它问。真正拦的是自保护。文案与代码注释都应统一到「危险命令规则 / 确认」与「自保护 / 拦截」这两组词上，别让用户在页面上看到第三种说法。
- 顺手项（不属于本 spec 的验收）：仓库的安全边界清单里列了危险命令确认，却没列自保护这个更硬的模块，值得补一句。
