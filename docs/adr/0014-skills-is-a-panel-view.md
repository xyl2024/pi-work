# 技能是面板视图，且它是即时生效项

技能（浏览 SKILL.md 目录、启用/禁用、从 skills.sh 搜索并安装）此前是一个占满屏幕的 860px 模态框，从左下角头像的悬浮菜单或命令面板打开，内部靠组件本地状态在三件事之间切换：按来源分组的技能网格、单个技能的 SKILL.md 与附属文件、从 skills.sh 搜索并安装的添加页。它在多处站不住脚：查看某个技能到底往系统提示里写了什么，正是要对着会话与工具输出核对的时候，遮罩一挡就什么都对不上；技能不在设置弹窗里，而是一个平级的独立模态，入口只能从命令面板或头像菜单进入；网格 / 详情 / 添加三件事靠组件内部状态切换，进得去出不来，没有「返回上一级」；安装是流式的，关掉模态就丢进度；而模型配置已经是右侧按钮列上的面板视图（ADR-0012），技能是同一类「配置型工具」却还活在全屏模态里。

**我们决定**把技能变成右侧按钮列上的一个**全局按钮**，点开后作为**面板视图**出现在右侧面板：

- 面板身份就是面板注册表里的一条 kind / 右栏按钮 id（同一个字符串，也是写进用户 `config.yaml` 的持久化键）：默认可见、`sessionBound: false`，声明顺序排在模型配置之后、对话树之前。左下角头像菜单的入口删除；命令面板条目由注册表生成（复用既有的 "Open skills" 词条与中英文 keywords），手写的那条命令随实现一起删除。按钮、面板标签条、命令面板共用同一个扳手 glyph，符合注册表的既有不变式。
- 面板内部是**页栈**（根页的分组技能网格，外加两个都直接挂在根页下的同级页：详情页的 SKILL.md 正文与附属文件、添加页的搜索与流式安装日志），每级都是全宽页面加返回控件，返回的永远是根页，栈深不超过两级；而不是把 860px 的双栏塞进窄栏。Esc 的语义是退一级页栈，退到根页再按才走面板标签的关闭规则。附件在详情页内联展开，不升级成页栈的下一级。
- 页栈位置、列表缓存与安装进度活在面板视图之外的模块级 store（`lib/client/skills-panel.ts`，迁移后为 `createPanelViewStore` 的一个 adapter）：**收起面板、切标签都不算离开**，不丢进度、不闪 loading；只有关闭该面板标签时才可能丢弃，安装仍在进行中时先确认一次。右栏 descriptor 的 badge 钩子接上「安装进行中」角标，面板收起时仍然可见。

**这次只换容器、不改保存语义。** 技能的启用/禁用继续是**即时生效项**：点一下开关就直接写入 Pi Work 按工作目录分桶的禁用清单（`config.yaml` 的 `disabled_skills`，键是 cwd、值是文件路径），没有草稿、没有保存栏、没有未保存改动角标。被 SKILL.md frontmatter 锁定的技能仍由服务端拒绝启用并给出原因，客户端把它呈现为「被技能本身锁定」而不是普通的关闭状态。

本文不复述打开 / 激活 / 收起 / 关标签这套面板规则，它们是 ADR-0002 的标签条状态机；技能只是它的一个新成员。参照对象是 ADR-0012「模型配置是面板视图而不是模态框」：容器那条路（全局按钮、内容跟 cwd 走、模块 store 保活）完全一致，但保存语义刻意分道扬镳；下面把这两件事各写清一次。

## 为什么它与模型配置不同：即时生效项 vs 待保存项

两个面板同为「配置型工具」，却在保存语义上刻意分工，这是全程最容易反推错的一点，尤其当评审认为「应该和模型配置一致」时。

模型配置走 ADR-0009 的**待保存项**：字段是 provider 列表、Base URL、API Key、OAuth 这类自由文本与密钥，改动先停在本地，靠一条固定保存栏整份写入 `~/.pi/agent/models.json`。技能的启用/禁用是一个开关，输入形态在 ADR-0009 里就属于**即时生效项**：它没有「改了一半」的中间态，一个布尔值写入后立刻就是盘上的事实，再补一条保存栏只是把「点一下」变成「点两下」，还会凭空造出一份可能与盘上不一致的本地状态。ADR-0009 按输入形态给保存动作分档；技能面板只是照做。因此它的关标签守卫只有「安装进行中」一个判据（`lib/shared/skills-close.ts`）——`dirty` 在这里根本不存在。

## 为什么是全局按钮、内容却跟 cwd 走

这两件事看似矛盾，但合在一起才是技能的取值口径：

- **按钮是全局的**（`sessionBound: false`）。没有选中会话时，Pi Work 自有技能（`~/.pi-work/skills/`）与 pi 的全局技能（`~/.pi/agent/skills/`）仍然有内容可显示，按钮不该置灰。
- **内容是跟当前选中会话的工作目录走的**。列表里多出一份项目级技能（`<cwd>/.pi/skills/`），每一条的启用状态也跟着那个 cwd 的禁用清单变化；没有选中会话时退回「新会话正在用的工作目录」，与模态框时代的取值逐字一致。

即「能不能打开」与「打开看到什么」是两回事：前者全局，后者绑定 cwd。会话绑定按钮（`sessionBound: true`）会因为没有选中会话就置灰，把技能归进去反而会让它在最需要「先看看有哪些技能」的场景下用不了。

## Considered options

- **保留模态框，只把入口挪到右侧按钮列。** 最小 diff，但遮罩仍挡住会话与文件、内层仍靠组件状态切页、关掉仍丢安装进度——用户报告的问题只解决了「找不到入口」一个。与 ADR-0012 否掉的那条同构。
- **引入草稿与保存栏，跟模型配置对齐。** 视觉统一，但要给一个布尔开关配上「已保存 / 未保存」状态，把即时生效项强行改成待保存项，与 ADR-0009 按输入形态分档的结论相冲突，还会让面板里显示的启用状态与盘上短时间不一致。
- **做成像终端面板那样的独立右栏区域。** 终端面板是附在工作区列上、独立于面板状态机的一块区域；技能若照做，就要再养一套开合 / 布局 / 持久化规则，与 ADR-0002 已经收口的规则重复，也让它不再和 Token 审计、翻译这些同级工具同类。

## Consequences

- 新增面板视图仍然只有 ADR-0002 的「注册表一条 + 表现一条 + body 一条」，技能落进去没有多出第四处；命令面板条目也由注册表声明生成，不再手写。
- 与 ADR-0012 同样的被迫后果：面板卡片只渲染当前激活标签的 body，切走标签会卸载视图，所以页栈、列表缓存与安装流必须提升到 shell 级模块 store（`lib/client/skills-panel.ts`）。若将来面板改为保留已打开视图的挂载状态，这部分责任可以回收，但不要现在赌。
- 右栏 descriptor 的 badge 钩子被第二次使用（模型配置是未保存改动，技能是安装进行中），两处共用同一个钩子、只换判据，不各存一份。
- `npx skills add` 由服务端路由持有，路由不监听客户端连接断开，所以关标签只丢日志、不停安装；这正是 `lib/shared/skills-close.ts` 那份确认文案承诺的内容（「安装继续在后台跑，日志会丢」）。
- 全屏技能模态与它的三条入口（命令面板手写条目、头像菜单项、外壳透传链）随收口一起删除，只剩面板这一条实现。
- 聊天输入框里的 `/skill:...` 选择菜单、SKILL.md 的文件 chip、命令面板之外的技能入口完全不动——那是「这次用哪个技能」，与「管理技能」是两件事。
- 判定被推到纯模块，在 `tests/unit` 里直接驱动：页栈 push / back / 收敛（原 `lib/shared/skills-pages.ts` 已删除，改由 `lib/client/panel-view-store.ts` 的契约测试统一钉住）、`lib/shared/skills-close.ts`（关标签确认的唯一判据）、`lib/shared/skills.ts`（按来源分组）。面板内的视觉布局、窄栏下的留白、划词翻译工具栏在面板里的定位、安装日志的滚动表现，以及服务端技能路由的契约本身，仍属人工清单（ADR-0003 规则 3）。

**参见**：ADR-0024「面板视图的生命周期是一个 module」——本文的面板视图状态（保活、释放、页栈与关闭确认）由那一个 module 拥有，本文只提供 adapter，Decision 不变。

## 修订 2026-10-18（频道面板 #138）

频道也迁成了右侧面板视图（ADR-0017）。它与本文同为「没有待保存项」的面板：面板内的输入全是即时生效项，关标签不存在 dirty 判据。但两者的守卫判据不同——技能是「安装进行中」，频道是「活着的扫码登录会话」；频道还是第一个不接角标钩子的面板。评审看到「频道没有角标 / 守卫不是 dirty」时，不要反推技能也应改。

**参见**：ADR-0017「频道是面板视图」。
