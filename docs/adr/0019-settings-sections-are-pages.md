# 设置分区就是页

设置弹窗此前是一条长滚动正文：十个设置分区首尾相接铺在同一列里，左侧那一栏只是滚动锚点——点一下把正文平滑滚到对应位置，滚到哪一区就由滚动位置反推高亮项。分区之间靠间距与分组标题分隔，但它们终究是同一条流：想改一个开关要先滚过一堆不相干的分区；滚到提示词之后再去看音效、再回来，人落在别处；「现在到底在哪一区」这个问题由测量 DOM 位置来回答，而不是由应用状态回答。

**我们决定**把设置弹窗改成「左侧导航 + 右侧单页」：左侧按分组列出全部分区，点一个分区右侧只渲染那一页，页面从页首开始；分组标题永远只是标题。导航的事实从此只存在于设置注册表里——分组的顺序、分区的顺序、分区属于哪个分组，都由同一份声明得出，导航与页映射都从它派生。当前页在导航里高亮并标成「当前页」，每页正文顶部再显示一次这一页的名字（名字同样取自注册表，所以导航与页标题不可能互相矛盾）。

**页的身份就是分区 id，不再是一个拼出来的 DOM 锚点。** 选中态从「滚到的位置」变成一个类型化的分区 id，页的渲染也从一串分支式 switch 改成以分区 id 为键的映射：注册表里多一个分区而没实现对应页，类型检查就失败。这条守卫刻意放在编译期而不是测试里——信息架构漂移应该在写代码时就撞墙，而不是在测试里补一条断言。

## 为什么锚点体系该删，而不是留着兼容

那套机制（正文上的滚动锚点属性 + 用交叉观察监听哪一区进入视口 + 平滑滚动过去）不是「还能用的旧实现」，它把信息架构寄存在 DOM 几何上：

- 「当前页」由视口交集算出，于是正文里同时出现两个分区、分区高度一变高亮就漂、窄窗口里一屏塞下三页，全都成了正常状态。
- 滚动位置是全局的，所以「切到某一页」这件事没有落点，只有惯性。
- 导航按钮的可点性、激活态与页标题三处各自去查 DOM，注册表只是三者的弱约定。
- 页面想调整内边距或顺序，实际是在改导航行为。

一旦分区变成一次只显示一个的单元，这层机制整体失去对应物：没有可滚到的锚点，没有需要观察的可见区，也没有需要平滑滚动的位置。留着它只会留下第二套互相打架的「当前页」判据，所以整层删除，不做兼容。

## 这些取舍是刻意的

- **分组标题永不可点击。** 分组不是内容，只是导航里的小标题；点它会得到「一次没有目的地的跳转」。既然没有「分组首页」，就不给它按钮语义，也不给悬停反馈。
- **切页不记忆每页滚动位置。** 每次切页从页首开始，落点因此可预测；「回到我上次读到的那一行」在单页设置里价值很低，却要求给每页各存一个滚动偏移，并让「切页」与「恢复位置」两个动作互相掩盖。
- **记住上次停留的分区。** 设置是反复进出的高频面板，每次重开都回到第一页等于让用户每次重新找路。存的是分区 id，读的时候必须对着注册表校验：分区被下线、值被手改成乱码、存储不可用，一律回落到默认页，绝不把「记住位置」变成「打开一个空白页」。这是浏览器本地的一层便利，不是配置。
- **有未保存改动的分区与关窗确认共用同一种形态。** 分区里可能有待保存的改动（按 ADR-0009，自由文本与密钥要显式保存）。切到另一页时如果那一页还有未保存改动，就先问一句「要丢弃未保存的改动吗」，用的是与关窗完全相同的确认框、完全相同的一句话；确认丢弃并跳转时顺手把那一页从登记表里清掉，否则关窗时会为一份已经不存在的改动再问第二次。点当前已经打开的那一页不算切换，即使它还有未保存改动也不问。只有一种确认形态，因为用户不该在同一个设置面板里见到两套「未保存」的机制。

保存语义本身一个字没改：即时生效项照样当场落盘，待保存项照样要显式保存，关窗确认的文案照旧。本次改的是信息架构与导航，不是写入路径。

## Considered options

- **保留长滚动正文，只把导航做得更像导航**（加高亮、加「当前区」圆点）。最小改动，但用户报告的正是「一屏里全是不相干的分区」和「切走再回来位置丢了」，这两条在单流布局里无解。
- **保留锚点体系，只用状态驱动高亮。** 两套判据并存：滚动仍会改变正文内容，状态又说当前只有一页。要么正文被强行截成一页（锚点失去意义），要么高亮与实际内容不一致。
- **把设置做成真正的路由页**：可深链、可前进后退。但那会把「关掉设置回到会话」从一个弹窗动作变成一次导航，也要重做权限与状态边界；本次只要「一页一件事」，不要路由。
- **窄屏把左侧导航折叠成横向 tab 或抽屉。** 可以以后再做；这次只给弹窗宽度加视口兜底，不改窄屏下的结构。
- **给切页加淡入动画、给导航加快捷键或图标。** 动画会让「点了就能操作」变成「等它出现」；快捷键会与外壳的会话标签切换争同一个键位。两者都不值得在这轮引入。
- **为切页另造一条内联的「保存 / 丢弃 / 取消」条。** 关窗已经是同一个问题，两套 UI 会让人以为保存规则变了。

## Consequences

- 导航与页映射只剩一个事实来源：注册表里的声明顺序。测试只需断言页映射的键集合等于注册表的分区 id 全集，以及 id 唯一、每页有合法分组、每组非空、标记为开发者的分组只有一个这些不变量；原来那条「扫描源码找分区包装」的守卫随锚点体系一起删除。
- 分区外壳的职责变了：它从「挂锚点属性 + 上下间距」变成「页的外壳」——页标题、可选说明、统一的内容内边距。各分区只需直接返回内容，不再自带外层包裹与重复标题。
- 「哪些分区可能有未保存改动」变成类型层面的清单（当前是个人资料、追加系统提示词、网络代理三页）。新增待保存页时必须在清单里声明；上报的 key 若不在清单内（例如页与 key 接错），编译器会拒绝。漏掉上报本身抓不到，这条守卫只覆盖「能报哪些 key」。上报接口的类型同时从裸字符串收紧到这套 id 联合。
- 「能不能离开这一页」下沉成纯判定：给定未保存改动的集合与目标分区，回答「可以走」或「先确认，并指出是哪个 key」；目标等于当前页永远可以走。组件只负责把「先确认」翻成确认框。清掉这个 key 复用已有的「已保存」动作，不新增动作类型。
- 沿用 ADR-0003 的立场：判定逻辑在纯模块里直接测（未保存改动、注册表不变量、上次停留分区的存储往返与非法值回落），弹窗自身的接线（切遍所有页、有未保存改动的圆点、切页拦截、丢弃后关窗不再二次确认、窄视口不溢出）仍靠人工 smoke。
- 子代理编辑器仍是独立的编辑弹窗，本轮不把它改成第三级页；子代理设置分区按「列表页 + 右上新建」排布，为以后收编留路。

**参见**：ADR-0009「设置页的保存语义由输入形态决定，写入口只送变更的 key」（即时生效项与待保存项的划分，本文不动）、ADR-0003（测试只测纯模块的外部行为，弹窗接线走人工清单）。
