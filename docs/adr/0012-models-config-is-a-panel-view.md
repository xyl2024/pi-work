# 模型配置是面板视图而不是模态框

模型配置（provider、API Key、OAuth 登录、模型条目）此前是一个 860×78vh 的模态框，从左下角头像的悬浮菜单打开，内部再叠着全屏弹层（添加 provider、输入模型名、从目录填充表单）。它在四处站不住脚：配 provider / 选模型名恰恰要对着会话与工具日志核对，而遮罩一挡就什么都对不上；右侧按钮列里已经有 Token 审计、翻译、Git Diff 这类同级工具，模型配置却藏在头像菜单；弹层里还叠弹层，关闭路径要靠猜；关掉即丢草稿。再加上「Models / Open models config / Models」三个名字，标签条与聊天里「选当前模型」的入口撞名。

**我们决定**把模型配置变成右侧按钮列上的一个**全局按钮**，点开后作为**面板视图**出现在右侧面板：

- 面板身份就是面板注册表里的一条 kind / 右栏按钮 id（同一个字符串，也是写进用户 `config.yaml` 的持久化键）：默认可见、`sessionBound: false`，排版上落在 Token 审计、LLM API 审计这类工具按钮附近。左下角头像菜单的入口删除；命令面板条目由注册表生成（复用既有的 "Open models config" 词条与 keywords），手写的 `modal.models` 命令随实现一起删除。按钮、标签条、命令面板共用同一个 provider 齿轮 glyph，符合注册表的既有不变式。
- 面板内部改成**页栈**（列表页 → provider / OAuth / API Key 详情页；provider 详情再进模型详情；详情页再进添加页），每级都是全宽页面加返回控件，返回到的永远是上一级（模型详情的上一级是它所属的 provider 页，不是列表页），而不是把 860px 双栏塞进窄栏。原来那几层全屏嵌套弹层降级为页栈的下一级页面，界面上不再出现第二层遮罩；Esc 退一级页栈，退到最后一级才走面板标签的关闭规则。
- 「模型目录」（All model data）是同面板视图内的**根页同级页**，带返回，不新增面板视图 kind、不新增按钮——避免它和「模型配置」被当成两个入口。
- 面板底部固定一条保存栏（保存 / 保存中 / 已保存 / 错误），不再需要滚到底找按钮。
- 草稿、页栈位置与 OAuth 登录状态活在面板视图之外的模块级 store：**收起面板、切标签都不算离开**，不丢草稿；只有关闭该面板标签时才可能丢弃，dirty 或授权仍在进行中时先确认一次。右栏 descriptor 上一直没接线的 badge 钩子接上未保存改动角标，面板收起时仍然可见。

**这次只换容器、不改保存语义。** 这批字段继续走 ADR-0009 的「待保存项」：显式保存、整份 `models.json` 写入，不改成即时生效；删 provider / 删模型 / 移除 API Key 也仍然只在保存时落地。唯一的信号变化是「新建会话使用新默认模型」的刷新从「模态框关闭」改为「保存成功」——原来的实现在「打开又取消」时也会白刷一次。

本文不复述打开 / 激活 / 收起 / 关标签这套面板规则，它们是 ADR-0002 的标签条状态机；模型配置只是它的一个新成员。

## Considered options

- **保留模态框，只把入口挪到右侧按钮列。** 最小 diff，但遮罩仍挡住会话与文件、内层仍叠着弹层、关掉仍丢草稿——用户报告的四个问题里只解决了「找不到入口」一个。
- **做成像终端面板那样的独立右栏区域。** 终端面板是附在工作区列上、独立于面板状态机的一块区域；模型配置若照做，就要再养一套开合 / 布局 / 持久化规则，与 ADR-0002 已经收口的规则重复，也让它不再和 Token 审计、翻译这些同级工具同类。
- **打开模型配置时强制把面板展开（expanded）。** 保住宽度，但抢走了面板的布局状态机：用户当前的 normal / expanded 选择会被一个面板视图改写，而页栈本来就能在约三分之一宽的窄栏里放下一整套 provider 配置。

## Consequences

- 新增面板视图仍然是 ADR-0002 的「注册表一条 + 表现一条 + body 一条」，模型配置落进去没有多出第四处；命令面板条目也由注册表声明生成，不再手写。
- 这是本次唯一被迫的架构后果：面板卡片只渲染当前激活标签的 body，切走标签会卸载视图，所以草稿、页栈、OAuth 登录流与 provider 列表必须提升到一个 shell 级模块 store（`lib/client/models-config-store.ts`）。若将来面板改为保留已打开视图的挂载状态，这部分责任可以回收，但不要现在赌。
- 右栏 descriptor 的 badge 钩子从「声明了但没人读」变成「dirty 就看得到」，角标与 store 共用同一个 dirty 判定，不另存一份。
- 删除模态框路径后只剩一条实现（外壳、底栏、遮罩、`useModalAnimation` 用法一并删除）；与它同构的 Skills / Prompts / MCP / 设置弹窗这次不动，交互与语义一点不变。
- 聊天输入区选当前模型的弹层完全不动：那是「这个会话用哪个模型」，与 `~/.pi/agent/models.json`（有哪些 provider / 模型、怎么接）是两件事。
- 判定被推到纯模块，在 `tests/unit` 里直接驱动：`lib/shared/models-config-draft.ts`（服务端载荷 → 草稿、dirty 判定、阻止保存的问题、保存提交的载荷）、`models-config-pages.ts`（页栈 push / back / 删除与保存后的收敛）、`models-config-close.ts`（关标签确认与重开是否重读盘）。面板内的视觉布局、角标渲染位置、OAuth 与 HTTP 胶水仍属人工清单（ADR-0003 规则 3）。

## 修订 2026-10-17（技能面板 #121）

上面「Skills 这次不动」这句话已不再成立：技能沿同一条路迁移成了右侧面板视图，全屏技能模态与它的三条入口已删除。按钮是 `sessionBound: false` 的全局按钮、内容跟随当前会话的工作目录、面板身份仍是 `config.yaml` 里的一个键（缺键即默认可见）——这三条与本文一致，不另解释。

**参见**：ADR-0014「技能是面板视图，且它是即时生效项」。它记录了这个面板与本文刻意不同的地方：技能的启用/禁用是 ADR-0009 的**即时生效项**，没有草稿与保存栏；本文的 provider / API Key / 模型条目则仍是待保存项。评审时不要反过来把保存栏补到技能面板上。

## 修订 2026-10-18（定时任务面板 #129）

上一条「Skills 这次不动」之外，定时任务也沿同一条路迁移成了右侧面板视图：两层全屏任务模态（外层任务窗口 + 内层表单窗口）与它的三条入口（命令面板手写条目、头像菜单项、外壳透传链）已删除。按钮是 `sessionBound: false` 的全局按钮、面板身份仍是 `config.yaml` 里的一个键（缺键即默认可见）——这两条与本文一致，不另解释。

**参见**：ADR-0016「定时任务是面板视图」。它记录了这个面板与本文刻意不同的两处：任务表单仍是 ADR-0009 的待保存项，但任务的启停是**即时生效项**（拨一下直接写盘，没有保存栏）；以及表单里的工作目录 / 模型 / 推理强度 / 工具四个选择器**保留为应用级对话框**，没有做成面板内页栈——本文把 provider / 模型做成面板内页栈，是因为那是「配置同一个实体」，而那里是「选一个值」，三个共享选择器被聊天输入区、命令与定时任务共用。

## 修订 2026-10-18（频道面板 #138）

上一条之后，频道（目前只有微信）也沿同一条路迁移成了右侧面板视图：全屏频道模态、左侧平台列与它的三条入口（命令面板手写条目、头像菜单项、外壳模态开合状态与渲染点）已删除。按钮是 `sessionBound: false` 的全局按钮、面板身份仍是 `config.yaml` 里的一个键（缺键即默认可见）——这两条与本文一致，不另解释。

**参见**：ADR-0017「频道是面板视图」。它记录了这个面板与本文刻意不同的两处：它是第一个**不接角标钩子**的面板（现有三个角标都表示「一次性动作还没结束」，频道没有对应物）；它面板内**没有任何待保存项**，关标签守卫的判据是「活着的扫码登录会话」而不是 dirty。评审时不要反过来把保存栏或未保存角标补到频道面板上。
