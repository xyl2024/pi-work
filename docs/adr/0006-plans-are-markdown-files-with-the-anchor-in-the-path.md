# 计划以 Markdown 文件为唯一真值，时间锚点写在路径里

2026-09-12 我们刻意删掉了完整的旧「待办」功能（用户待办 + Agent 待办，116 文件、-11352 行：SQLite `todos.db` + 标签表、Tiptap 富文本、标签、优先级、截止日期、月历、3 个 agent 工具）。三天后重新做这件事时，我们决定**不恢复它**：新功能叫**计划（Plans）**，一条计划就是一个 Markdown 文件，放在 `<数据根>/user-plans/` 下（默认 `~/.pi-work/user-plans/`，目录名沿用笔记 `user-notes/` 的 `user-` 前缀）；**时间锚点只存在于路径里**（`user-plans/YYYY-MM/YYYY-MM-DD-标题.md` 日锚点、`YYYY-MM-DD W-标题.md` 周锚点、`YYYY-MM-M-标题.md` 月锚点、`user-plans/inbox/标题.md` 无锚点），文件名前缀之后就是标题；frontmatter 只留 `done` / `created_at` / `done_at` 三个字段，正文是备注。改期 = 移动/重命名文件。面板只读文件（进程内 `mtime` 缓存，无持久化索引、不 `fs.watch`）。agent 通过 `agent-skills/pi-work-user-plans` 技能用现成的 `read` / `write` / `edit` / `bash mv` 维护同一批文件，Pi Work **不注册任何专用工具、不写系统提示词**。

理由：用户要的是「自己的东西」——能在文件管理器里看懂、能用任何编辑器改、能进 git、坏掉也不会被机器背着自己改写。把锚点编码进路径换来的是**「今天该做什么」= 一次 `readdir`**：不需要索引、不需要 schema、不需要迁移，也没有「文件与数据库不一致」这种状态。

## Considered options

- **恢复旧待办（`git revert e9d9f8e`）**：否决。它正是被刻意删掉的东西：富文本、标签、优先级、截止日期与 agent 工具带来的复杂度是删除的原因，而不是要修复的缺陷。
- **SQLite 存全部字段（或 SQLite 索引 + Markdown 正文）**：否决。两套真值必然出现「文件改了、库里没改」；且 agent 无法用 `read`/`write` 安全维护数据库，用户也不接受数据离开文件系统。
- **任意区间（如「最近 3 天」）与月内序号周（1–7 日为第 1 周）**：否决。前者让模型退化成日程软件，后者与直觉冲突；日历周（周一–周日）+ 三档锚点更符合用户对「本周」的理解，跨月的代价（读相邻月份目录）小于它换来的直觉。
- **`W3` 式周编号**：否决。跨月周的「第几周」有归属歧义，改用**周一日期**标识一周，歧义消失且文件名自描述。
- **一天一文件（日记式 `2026-09-15.md`）**：否决。周锚点与月锚点没有落点，改期等于跨文件搬运条目。
- **json 存放元数据**：否决。任何语义数据离开 Markdown，agent 就无法用 `read`/`write` 安全改动，整条路会自我断路；UI 偏好走 `localStorage`。

## Consequences

- 「今天」视图 = 读 `user-plans/<本月>/` 与 `user-plans/<上月>/`（跨月周）+ `user-plans/inbox/`；「过期未完成」= 遍历历史月份目录并按 `done` 过滤。
- 文件名就是标题，因此字符清洗与长度上限是硬约束（非法字符替换、约 80 字截断、重名加后缀）。
- 锚点唯一真值在文件名 ⇒ agent 改期必须 `bash mv`（`edit` 改不了文件名），技能里必须写明。
- 没有 `fs.watch`：agent 或外部编辑器改完文件后，面板要手动刷新（或窗口重新聚焦）才看得到。这是明确接受的代价。
- 面板**不注册 agent 工具、不进系统提示词**：agent 只会在用户明确要求或加载了该技能时才碰这些文件。
- 格式不符的文件收进「待整理」区并指出问题，**绝不自动改写用户的 Markdown**。
- 「面板只读文件」指的是**没有索引、没有 `fs.watch`、不猜时区**：面板打开/手动刷新/窗口重新聚焦时才读。面板确实会写，但只写**它自己创建的计划**（新建、备注、完成、改期、删除，见 #42–#47）——手写的与「待整理」的文件永不被序列化重写。
- 旧数据 `~/.pi-work/todos.db` 不被读取、不被迁移、不被删除；旧代码不复活。

## 修订 2026-09-16（计划面板 #44）

上面正文里的周锚点写法 `YYYY-MM-DD W-标题.md`（`W` 前有空格）是笔误，实际契约里 `W` 直接紧跟在周一日期后、**没有空格**：周锚点 = `YYYY-MM/YYYY-MM-DDW-标题.md`（例：`2026-09/2026-09-28W-整理书架.md`）。同时把正文已隐含、本切片才落地的两条规则写清：

- **跨月周归属**：周锚点的目录取**周一所在月份**（2026-09-28–10-04 的这一周归档在 `2026-09/`），路径用周一日期标识，因此「本周」分区与文件所在目录可能跨月。
- **月锚点前缀**：`YYYY-MM-M-标题.md` 里的 `M` 是字面标记（区分「月锚点」与「日锚点」的 `YYYY-MM-DD-`），不是月份数字。

三条前缀因此互斥且能唯一解析：`YYYY-MM-DD-`（日）/ `YYYY-MM-DDW-`（周）/ `YYYY-MM-M-`（月）。参见 #44。

## 修订 2026-09-16（计划面板 #47）

上面「UI 偏好走 `localStorage`」是默认做法，**mini 月历的收起状态是刻意的例外**：它放在 `sessionStorage`（`pi-work.plans.calendar-collapsed`），因为 #47 要求「收起状态在**本次会话内**保持」——只活到标签页关闭，不变成跨会话的持久偏好（外观模式 #48 才是 `localStorage` 的那类）。同时确认另一条 #47 的口径：月历的每天/每周/每月计数从**已加载的全部计划**派生（包含已完成），因此它回答的是「这段时间有多满」，与「隐藏已完成」过滤后的列表不要求逐条对应，且不产生额外的读取请求。参见 #47。

## 修订 2026-09-16（计划面板 #48）

面板头部一个三格切换器选择**外观模式**（`compact` / `cards` / `timeline`），选择写入 `localStorage`（`pi-work.plans.view-mode`），默认 `compact`。三条约束落定：

- **模式只改变分组与行形态，几乎不改变列出哪些计划**：`compact` 与 `cards` 共用同一套分区与同一份数据（都走 `groupPlans` / `hideCompletedPlans`），只有行容器不同；切换是纯重渲染，**不产生任何请求**（面板本就不轮询）。「隐藏已完成」与完成项淡化在三种模式下一致。唯一的例外是**过期分区的折叠规则**（“过期未完成”只列未完成项，见 #40 story 23）：`timeline` 没有分区概念，已完成的历史计划也在轴上淡化显示，而不是被折叠区吞掉。
- **`timeline` 是另一种排列，不是另一种过滤**：不分区，收件箱钉在顶部，其余按时间从过去排到未来。时间轴上的位置用 `orderPlansForTimeline` 的规则：**仍然覆盖「今天」的锚点画在「今天」**（否则月锚点会跳到 1 日、把「本月」读成过去），其余画在其起点；同位置再按锚点粒度（日 → 周 → 月）与 `created_at` / path 排序。于是轴读作 过期 → 今天 → 未来。
- **模式是浏览器本地偏好，不是计划字段**：不写入 Markdown、不影响文件名与锚点契约（锚点唯一真值仍在路径里）。参见 #48。
