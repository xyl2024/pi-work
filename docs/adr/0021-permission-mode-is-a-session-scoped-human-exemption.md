# 权限模式是人在某个会话里的一次显式豁免，自保护例外

危险命令确认网是进程级的一张网：`~/.pi-work/config.yaml` 里的用户规则加平台内置规则集，每次 agent 调用 shell 时在 `tool_call` 钩子上过一遍，命中就停下来等三值决定。它的粒度是**规则名**——「本次会话允许同类」记的是某一条规则，不是「这个会话不用再问我」。于是出现一个稳定的场景：用户已经信任这个会话（自己的机器、熟悉的仓库、刚看完了接下来要干的那几件事），他不想为第 17 条命令再点一次「允许一次」，而「允许同类」又不够，因为换一条规则又要问。今天唯一的出路是手改全局配置，那是个比弹窗更重的动作，且对所有会话、所有频道、所有定时任务同时生效。

**我们决定**在对话输入区加一个**会话级**的**权限模式**开关，两档：**确认危险命令**（`confirm`，默认，等于今天的行为）与**完全访问**（`full_access`，本会话内命中危险命令规则时不再中断询问）。新的不变量措辞是：

> 闸门在每一处，除非有个「人」在「某一处」显式声明他清楚代价；自保护例外。

## 为什么这条不构成 ADR-0020 那条滑坡

ADR-0020 明确否决了「让内置规则逐条可停用或整体可关闭」，理由是：「给出去的是便利，收回来的是『闸门一定在』这条唯一的不变量。」本文**取代**那一段，并给出一条更精确的不变量。理由不是「这次的需求更重要」，而是这条豁免在四个维度上都与那条滑坡不同：

- **per-session**：豁免的载体是单个会话，随 `AgentSessionWrapper` 存活，写进 `~/.pi-work/session-permission-mode/<session-id>.json`。它不改变任何全局规则集的语义，别的会话、频道会话、定时任务会话仍然是确认模式，冷启动也不会自动继承。
- **由人点出来**：开关只出现在界面上（工具条按钮、命令面板）。没有斜杠命令入口、没有 agent 工具、不注入系统提示词，所以 agent 不知道自己处在哪个模式，也就没有「劝用户切过去」这条路径。频道入站消息是外部可控内容，这正是这条约束的真实来源。
- **可见且常驻**：激活时输入区描边转红、工具条按钮转红、会话标签页与侧栏行各挂一枚红色盾牌徽章，Tooltip 写清它放过了什么、没放过什么。持久化 + 无人记得 = 一个被焊死的洞，所以徽章是持久化的配套义务，不是装饰。
- **默认关闭**：没有全局默认值、没有按 cwd 记忆、新会话一律回到确认模式。「我没设过，它怎么不问我就跑了」不会发生。

一句话概括差异：ADR-0020 否决的是**把网拆掉**，本文允许的是**人在一处把网临时掀开一角，并且这一角一直亮着**。

## 自保护在任何模式下都硬拦

完全访问只放过**危险命令规则的命中**。`lib/server/self-protection.ts` 那几条（`pkill node`、`kill $PPID`、`fuser -k <本服务端口>/tcp`、`shutdown`）仍然是硬拦截：无提示、无豁免、不可配置。

理由是这条风险与「命令危险」不是一个量级：pi CLI 被杀只死一个终端，Pi Work 服务端被杀会带走所有会话、SSE 流、终端 WebSocket、定时任务循环与频道循环。一条 `pkill node` 在完全访问下被放过，代价不是「删了一个文件」，而是「整个应用消失，且没有任何东西会告诉你为什么」。

判定顺序因此必须只有一处：`evaluateDangerousCommand` 先跑自保护、再看是否完全访问、最后才匹配规则。`AgentSessionWrapper` 的 `tool_call` 钩子只把当前模式传进去，自己不分叉。

## 完全访问不放过什么

- 自保护（见上）。
- `PermissionDialog` 的三值语义：`allow once` / `allow similar` / `deny` 一个字没改。
- 子代理会话的快速拒绝（ADR-0001）。子代理默认仍是确认模式，它们的命中仍然立即拒绝而不是等一个没人答的弹窗。
- 任何非 shell 工具的判定（今天也只有 shell 会进这张网）。

## 切换的语义

- **切换只影响之后的工具调用。** 切到完全访问不自动批准任何待批准请求，切回确认也不取消或拒绝任何待批准请求——正在等你看的那条命令还在等你。
- **切回确认模式时清空会话级备忘。** 「本次会话允许同类」与「完全访问」是同一层「这个会话的授权」，撤销后者时连带撤销前者，否则用户切回来会发现某些规则莫名其妙不再问他。完全访问期间不查也不写备忘：判定根本不进闸门，所以天然如此。
- **新会话页面的开关是同一个开关，只是提前了一步。** 草稿还没有 session id，按钮记下的是「即将创建的那个会话」将要使用的模式，随 `POST /api/agent/new` 在首条提示词之前下发，所以用户刚授权的那一轮里第一条危险命令就已经不再问。它不构成任何默认值：每张新的新会话页面仍从确认模式开始，也不记忆上一个会话或 cwd 的选择。

## Considered options

- **在确认弹窗里加第四种按钮「本会话内全部允许」。** 看起来最省事，实际上把这个决定藏进了「一条命令要不要放行」的对话框里：用户点它的时候正在看一条具体的命令，而不是在做一次对整段时间的授权；而且它只在你已经撞上第一条危险命令之后才出现。
- **全局开关（`config.yaml` 里的 `dangerous_patterns.enabled: false`）。** 就是 ADR-0020 已经否决的那条。
- **按 cwd 记忆。** 权限模式会跟着工作目录走，于是同一目录下新开的会话继承上一个会话的授权——授权扩散到了用户没有显式点过的会话上。
- **给 agent 感知（系统提示词里写「现在没人看着」）。** 等于给 prompt injection 提供一个可优化的目标，且会让 agent 把「现在是完全访问」当成劝用户切换的论据。
- **斜杠命令 / 环境变量入口。** 两者都让「只有人点」这条约束多出漏洞：斜杠命令和 agent 的输入框共用一个通道，环境变量则能被任何一次启动脚本带上一层。
- **把完全访问也做成一条规则**（写进用户规则列表、pattern 为 `.*`）。规则列表是「哪些命令要问」，不是「这个会话不问」，而且它会同时对所有会话生效。

## Consequences

- 协议多一条活事件 `permission_mode_changed`（照 `thinking_level_changed` 的模子接入归约），`get_state` 快照回传 `permissionMode`，RPC 多一条 `set_permission_mode`。RPC 参数必须显式枚举合法值：未知取值一律拒绝，不得默认当成 `full_access`——ADR-0008 记的「未知决定等价于放行」那个坑不要在这里重演。
- 客户端多一份按会话索引的权限模式：它驱动按钮、描边、描边下的徽章与命令面板条目。会话列表接口回传每个会话的模式，否则冷启动后侧栏无从判断。
- 侧车文件的形状照 `session-names` / `session-tools` / `session-notify` 的同形实现（原子 tmp+rename、文件名限安全字符集、走 `PI_WORK_DATA_DIR` 覆盖的数据根）。没有侧车文件的会话读出来就是确认模式，升级不改变任何既有会话的行为。
- 完全访问把**服务端进程自身**暴露给了 agent 的一部分动作，这是本次改动最实质的风险。它换来的是「用户不必在信任的会话里反复点允许」，代价由自保护那一条例外兜住。下一次有人问「能不能也放过 `pkill node`」时，答案在这篇里，不在弹窗里。

**参见**：ADR-0020（危险命令规则可配置，闸门的兜底不可配——本文取代其中「整体可关闭」那一段）、ADR-0008（闸门是一个 module；未知决定等价于放行的坑）、ADR-0001（子代理会话的闸门一律快速拒绝）、ADR-0007（会话事件是带类型的协议）。
