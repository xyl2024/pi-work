# 设置页的保存语义由输入形态决定，写入口只送变更的 key

设置弹窗里曾并存三种保存动作，且分工没有道理可讲：开关与枚举当场落盘、文本域与密钥各按自己的按钮保存、数值靠失焦提交。更糟的是三处持有本地草稿的分区里只有一处（追加系统提示词）把自己的脏状态报告给弹窗，「未保存改动」的关闭确认因此只覆盖三分之一：改完用户名或代理地址直接关窗，字被无声丢掉。同时写入口每次都把**整份** `PiWorkConfig` PUT 回去，服务端把请求体摊在磁盘快照之上——于是任何一次即时改动都在用「打开弹窗那一刻的快照」覆写配置，侧栏改的工作目录别名与图标、技能面板关掉的 Skill 都在这个窗口里被冲掉。

我们决定：**一个设置项属于哪一档保存语义，由它的输入形态决定，不由它住在哪个分区决定**——自由文本与密钥是**待保存项**（显式保存），开关、枚举、单选、复选与失焦提交的数值是**即时生效项**。未保存改动不再散在各分区，而是收进一份登记（纯归约器 + 薄 hook），「关窗前要不要确认」只有一处判定。写入口也只剩一个，只送**变更的那个 key**，两种模态（即时 / 表单提交）共用同一套乐观更新与回滚。

服务端契约随之写死：`PUT /api/settings` 的请求体语义是 patch，且**只拥有**它自己那几个 key（`right_side_bar`、`append_system.enabled`、`load_pi_docs`、`file_viewer`、`ui_sounds`、`web_access`、`subagent`、`network_proxy`）；不属于它的 key（`cwd_aliases`、`cwd_icons`、`disabled_skills`）一律忽略，逐 key 校验保持不变。这是**有意偏离常识**的一处：动词仍是 PUT，语义却是 PATCH——不改动词是为了不把升级瞬间打开的旧页面推进 405，代价是这个名字会长期误导人，所以记在这里。这样任何过期快照都无害：它不能再表达「把别的功能的键设成我记忆里的值」。

## Considered options

- **全部即时保存，删掉所有保存按钮。** 最少的心智负担，但对追加系统提示词（整文件替换）与代理地址是危险的：每次按键都落盘，且没有「我还没填完」的表达。
- **全部改成表单保存，每个分区一个保存按钮。** 统一得彻底，但把开关这种零成本操作变成「必须记住我点没点保存」，等于把今天已经工作的乐观更新与回滚丢掉。
- **保留三种语义，只统一外观与文案。** 改动最小，但脏状态与关闭确认的缺口还在，丢数据照旧。
- **仅由客户端只发变更 key，服务端继续保留「请求体覆盖磁盘」的合并。** 能修掉今天的冲写，但契约仍允许任何调用方整份提交；护栏留在每个调用方的自觉上。
- **引入 jsdom + testing-library，直接给弹窗写渲染测试。** 见 ADR-0003：不为这一层新增浏览器测试基建；判定往下推成纯 module，剩下的接线靠人工清单。

## Consequences

- 判定下沉后，这条规则可以被纯函数钉住：输入形态 → 保存语义是一张查表，未保存改动是一个归约器，两者都在 `tests/unit` 里直接驱动，不需要浏览器。
- 「失焦提交」被归入即时生效项，而不是第三种语义。理由是它本来就是「我填完了」的手势，且改成 onChange 落盘会把清空输入框那一刻的空值写下去。
- 服务端的写入面从「任意 key」收窄到「它拥有的 key」，因此 `PUT /api/settings` 不再是 `config.yaml` 的通用写口；按 cwd 的别名、图标与技能禁用各自由自己的接口负责。
- 三个资源弹窗（Models / Skills / Prompts）与设置分区从此共用同一份控件皮肤；它们的外观会跟着变一次，交互与语义一点不变。若皮肤要再变，变的是那一处定义，不再是十三个文件。
- 本文没有改动 `writeConfig`：它仍然直接 `writeFileSync` 到目标文件，没有临时文件 + rename，也没有与按 cwd 接口之间的互斥。今天四个写者都是「读-改-写」，丢更新在理论上是可能的；这是本次探索记下的发现，不在这一票里修。
