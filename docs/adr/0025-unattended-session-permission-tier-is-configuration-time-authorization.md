# 无人值守会话的档位是配置时刻的授权：只能完全访问或自动拒绝，两档都不放过自保护

子代理与定时任务跑的时候没有人坐在旁边。它们撞上一条危险命令规则时，前台那套「停下来问人」没有对应物：子代理的 `permission_request` 只送到打开那个子会话的浏览器，通常没人开；定时任务会把确认请求发出去，然后干等 `dangerous_patterns.timeout_ms`（默认 5 分钟）无人应答，再按拒绝收场。前一种被一条写死的 `source === "subagent"` 直接拒绝，后一种白烧一次任务寿命。两个方向都没有开关：子代理档案只有工具、模型、推理强度与超时，定时任务只有工具集、模型、生命周期与通知。

**我们决定**给无人值守会话一个危险命令执行档位，取值只有两个：`auto_deny`（默认）与 `full_access`。档位挂在**配置对象**上——每个子代理档案、每个定时任务各自一份，跟工具白名单、模型、超时并列，不存在全局默认加单任务覆盖的继承层；新建默认 `auto_deny`，存量记录读出 NULL 或非法值也落回 `auto_deny`。会话创建时档位固定，运行中不可切换。

## 为什么可以有完全访问，却不给确认档

`confirm` 在无人值守会话里不是一个档位，而是一段固定时长的等待：没有人会来点弹窗，它唯一的实际效果就是把一次注定被拒绝的工具调用挂满 5 分钟。把它作为一个可选值放出来，等于给用户一个「看起来更安全」、实际只是更慢的选项。

`full_access` 则是一个真实的、有意义的授权：用户创建这个档案 / 任务时就知道它要跑 `rm -rf .venv`、`git clean -fdx` 或夜间重建，他信任的是这次无人值守运行。于是无人值守会话的运行时档位只有 `auto_deny` 与 `full_access`；`confirm` 仍然只属于前台会话，`set_permission_mode` 的取值集合与 `session-permission-mode` 侧车文件也只认那两个前台档位，后台会话永远不读也不写那份侧车。

## 为什么默认是自动拒绝

默认值要回答的是「我没动过这个档案 / 任务时会发生什么」。自动拒绝让升级前后的行为一致：存量档案和任务读出 NULL 时同样落回自动拒绝，快照缺字段的旧子代理任务恢复出来也自动拒绝。反方向的默认（无人值守 = 完全访问）会把一次升级变成一次静默的权限放大，而且放大发生在没人看着的时候。

自动拒绝是**绝对拒绝**：命中规则立即拦下这一次工具调用，不开闸门、不发 `permission_request`、不注册挂起项、不查也不写会话级备忘。即使此刻恰好有人打开了那个后台会话，它也不会变成确认模式——行为只由配置决定，不取决于谁碰巧在看哪个标签页。拒绝只拦这一次调用，不终止整轮：agent 收到一句点名规则、说明这是配置而非故障的理由，可以换安全替代，或在最终报告里写明用户需要手动跑的命令。

## 为什么两档都不放过自保护

自保护（`pkill node`、`kill $PPID`、`fuser -k <本服务端口>/tcp`、`shutdown`）判在档位之前。完全访问的语义是「跑我的命令」，不是「杀掉承载所有会话、SSE、终端、定时任务与频道循环的进程」；无人值守会话自杀等于任务静默消失，且没有任何东西会告诉你为什么。自动拒绝虽然本来就会拒绝一切规则命中，也仍然先走自保护分支，这样判定顺序只有一条：空命令 → 自保护 → 完全访问放行 → 匹配规则，再由闸门按档位决定「拒绝」还是「问人」。

## 这是配置时刻的授权，不是运行时的豁免

ADR-0021 的权限模式是人在某个会话里点出来的一次运行时豁免：随 `AgentSessionWrapper` 存活、写在 per-session 侧车文件里、界面上常驻可见、默认关闭、新会话不继承。无人值守档位正好相反：

- **决定发生在配置时刻**：用户编辑档案 / 任务表单时选一次，存进 `subagent_profiles.permission_mode` / `scheduled_tasks.permission_mode`，之后的会话只是读取它。
- **没有运行时开关**：工具条按钮与命令面板的翻转只对前台会话有效；对后台会话调 `set_permission_mode` 直接报错，界面照实显示「自动拒绝」或「完全访问」，不提供切换。
- **不是侧车文件**：后台会话的档位不从 `session-permission-mode` 读，也不写它。那份文件的语义仍然是「人在某个会话里的显式豁免」，把后台档位塞进去会让同一条路径承载两种含义。
- **agent 不知道**：不进系统提示词、不给工具、不给斜杠命令，和 ADR-0021 一致。

一句话：ADR-0021 是「人在会话进行中把网掀开一角」，本文是「人在建这个无人值守运行时就已经决定这次运行要不要受这张网约束」。

## 与「给危险命令规则加一个直接拒绝动作」不是同一件事

ADR-0020 明确没有引入 `block` 这种规则动作：规则命中仍然只是「问」。本文也不往规则上加动作，规则集本身一个字不改，自动拒绝判的仍然是用户规则 + 平台内置规则的合成集（清空用户规则不等于关掉闸门）。

两者的区别在作用对象：规则动作改的是**规则的含义**，一旦标成 `block`，同一个规则对所有会话都不再询问；无人值守档位改的是**谁在听**，规则在前台仍然照常问人，只是在没有人能回答的会话里，会话配置决定「立刻拒绝」还是「直接执行」。把本文误读成「内置规则可以标 block」会让 ADR-0020 的边界失效，所以后续要加规则动作时必须另开一篇决策，不能拿本文当依据。

## 唯一一处既有行为变更

定时任务命中危险命令时，过去会打开确认闸门并干等 5 分钟超时，现在默认 `auto_deny` 会立即拒绝。这是本决策唯一的既有行为变更，不是「什么都没变」：省下的 5 分钟与 `max_lifetime_ms` 是修复，但拒绝发生得更早、更确定，读日志的人会看到不同的时序。子代理原本就是立即拒绝，行为不变；存量的完全访问只可能来自显式配置。

## Considered options

- **给后台也保留 `confirm`**：没有人能回答，它只是「等 5 分钟再拒绝」的别名，见上。
- **全局开关或「全局默认 + 单任务覆盖」**：授权会从用户点过的那一个档案 / 任务扩散到没点过的对象，与 ADR-0021 否决按 cwd 记忆是同一条理由。
- **把档位做成一条 `.*` 危险命令规则**：规则列表是「哪些命令要问」，不是「这个会话不问」，而且它会同时对所有会话生效。
- **运行中可切换**：后台会话没有可信的人在场，任何运行时的翻转入口都会重演「有人发过消息就能绕过配置」的路径。
- **让 agent 感知档位**：等于给 prompt injection 一个可优化目标，也会让 agent 拿档位当劝用户切换的论据。

## Consequences

- 协议与界面多一个三值：`SessionPermissionMode` 扩成 `confirm | full_access | auto_deny`，而可切换的 `PermissionMode` 仍然是前台两值；客户端遇到不认识的值按默认档位处理，后台会话的徽章与工具条不可翻转。
- 写入时显式枚举两个合法值：档案 / 任务 API 遇到未知值一律校验失败，不得默认成 `full_access`。读取时 NULL、空串、非法值一律落回 `auto_deny`。
- 拒绝理由只说规则名与「这个无人值守会话被配置为自动拒绝」，不按会话类型分表；`ask_user_questions` 在无人值守会话里仍然直接报错，策略不变。
- 定时任务的运行记录在触发时记下当时的档位；历史运行会话按运行记录显示档位，旧记录没有该字段时按 `auto_deny`，之后修改任务不会改写旧运行的档位。
- 自保护与危险命令规则集仍是 floor：档位不改变它们的内容，也不新增审计链；后台会话本身能在界面打开查看，拒绝现场就在会话记录里。
- 词条进 `GLOSSARY.md`：**权限模式**覆盖三个取值，并另立**无人值守档位**；ADR-0001 与 ADR-0021 里把子代理固定成「没有确认档」的旧口径按本文修订。

**参见**：ADR-0021（权限模式是人在某个会话里的一次显式豁免——本文说明它的边界之外还有配置时刻的授权）、ADR-0020（危险命令规则可配置，闸门的兜底与自保护不可配；本文不引入规则动作）、ADR-0001（子代理默认快速拒绝，档案可选择完全访问）、ADR-0008（闸门是一个 module；档位在调用点按会话判定）。
