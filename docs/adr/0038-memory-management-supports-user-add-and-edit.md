# 记忆管理允许用户新增与原地编辑

记忆管理页面原本只提供删除（ADR-0031）。它把「用户输入是否该过 agent 的注入扫描」这个问题挡在门外，代价是用户想补一条事实、改错一个词，仍只能去 `~/.pi-work/memory/MEMORY.md` 手改文件。手改正是漂移的成因，面板却没有能力在漂移态下把一条超长条目改短。

**我们决定**：把用户直接干预从「只减不增」扩展为「增、改、删」，仍然走与 agent 工具并列的独立函数：

- 新增 `addMemoryEntry(target, content)` 与 `updateMemoryEntry(target, index, hash, content)`，复用同一把 `.lock`、锁内重读与 `writeFileAtomic`。
- 用户写入不做注入/外泄扫描。用户已经是文件的主人，可以绕过 UI 手改文件；扫描不能提高安全边界，只会让「不要告诉用户」这类正常句子被误伤。ADR-0031 担心的输入来源问题因此以一个明确的答案落地：用户输入是可信来源，只校验空内容、`§` 分隔符与完全重复。
- 原地编辑沿用删除的「索引 + 哈希」钉扎：面板长驻，另一个会话的写入会让索引位移；哈希不匹配返回 `stale_entry`，索引越界返回 `out_of_range`。
- 用户写入保留预算闸门，但允许**不增长**的写入越过预算：当写后用量仍超上限、却小于写前用量时照样落盘。这样漂移态下用户可以把超长条目改短，而不是只能删掉它；新增在漂移态下会因用量增长被预算拒绝，agent 的漂移闸门一分未变。
- 编辑超长条目前先留 `.bak` 快照，与删除超长条目一致；普通编辑不备份。
- 新增时完全重复的条目被拒绝；编辑时只与其它条目比较，允许原样保存。

## Considered options

- **继续只允许删除**：用户已经能在文件里写任何内容，UI 却连改一个错别字都做不到；删除是唯一的自救方式，会逼用户丢掉整条记忆。
- **让用户写入复用 agent 的扫描**：没有安全收益，却会把正常用户句子挡在门外；扫描防的是模型被注入，不是文件主人写自己的记忆。
- **编辑也走漂移闸门**：超长条目正在库里时，用户正好需要编辑它；闸门会把这个最重要的恢复路径堵死。
- **编辑也严格按预算拒绝**：库已经超限时，任何缩短都仍然超限，用户只能删除。允许非增长写入让编辑成为真正的修复工具。

## Consequences

- 记忆管理页面的每个库都有新增入口，每条都有编辑入口；保存成功用写后快照原地刷新，失败保留编辑内容并按失败码提示。
- 用户路径的失败码表沿用 `stale_entry`、`out_of_range`、`busy`、`unreadable`，新增使用 `empty`、`invalid`、`duplicate`、`budget`。
- agent 路径的扫描、预算与漂移三道防线不变；用户路径依然不能替 agent 绕过漂移闸门，只能把库改到可解析状态。
- `.bak` 只覆盖超长条目的删除与编辑，不是撤销或历史栈。

**参见**：ADR-0031（本篇修订其「只减不增」边界）、ADR-0029（冻结快照、扫描、预算与漂移三道防线）。
