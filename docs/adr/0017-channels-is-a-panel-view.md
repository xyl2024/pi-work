# 频道是面板视图

频道（目前只有微信）是 Pi Work 里**最后一个还活在全屏模态里的「配置型工具」**：一个 720×82vh 的窗口，里面是「左侧 150px 平台列 + 右侧新建输入 + 频道列表 + 频道详情」的双栏，从命令面板或左下角头像菜单打开。它在多处站不住脚：频道到底连上没有、上次轮询是什么时候、刚才那条消息为什么没回、扫码卡在哪个相位，恰恰要对着会话与工具输出核对，遮罩一挡就什么都对不上；右侧按钮列已经有 Token 审计、翻译、Git Diff、模型配置、技能、定时任务这些同级工具，频道却不在那儿；左侧四个平台入口里三个点进去只有一句「暂未支持」；关掉就丢选中的频道、填了一半的名字，尤其是**正在进行的扫码登录**——二维码出来、拿起手机扫码、中间切去看一眼会话，回来二维码没了、相位丢了，得重新生成；面板之外也没有任何状态信号。模型配置（ADR-0012）、技能（ADR-0014）、定时任务（ADR-0016）已经沿同一条路迁成了右侧面板视图，频道是第四次同构迁移。

**我们决定**把频道变成右侧按钮列上的一个**全局按钮**，点开后作为**面板视图**出现在右侧面板：

- 面板身份就是面板注册表里的一条 kind / 右栏按钮 id（同一个字符串 `channels`，也是写进用户 `config.yaml` 的持久化键，标签 id 形如 `channels:global`）：默认可见、`defaultMode: "normal"`、`sessionBound: false`，声明顺序排在定时任务之后、对话树之前。按钮、标签条、命令面板共用命令面板原来那个地球 / 消息 glyph。命令面板条目由注册表生成（复用既有 "Open channels" 词条与中英文 keywords：channels / wechat / weixin / 微信 / 频道 / 消息），手写的 `modal.channels` 条目与命令上下文里的打开函数随实现一起删除。左下角头像菜单的入口删除。
- 面板内部是**两级页栈**：根页（顶部新建条 + 频道列表，每条带状态色点、频道名与绑定的微信用户）→ 详情页（带频道 id，一条纵向滚动：状态与操作、重命名、workspace、扫码登录卡、折叠在底部的活动流）。每级全宽加返回控件，Esc 退一级，退到根页再按才走面板标签的关闭规则。新建频道成功后**直接进入新频道的详情页**（下一步必然是扫码连接）；删除成功后页栈收敛回根页。
- 左侧平台列删除，只做微信；将来加平台时按分组扩展根页，而不是现在预留三个空壳，「暂未支持」与四个平台名词条一起删除。
- 列表、选中频道、页栈位置、新建名字草稿、**扫码登录的相位与二维码**都活在面板视图之外的模块级 store（`lib/client/channels-panel.ts`，迁移后为 `createPanelViewStore` 的一个 adapter）：**收起面板、切标签都不算离开**，不丢相位、不闪 loading；只有关闭该面板标签时才释放，重开一律回根页并重新拉一次列表（频道列表是活数据，status 会变）。
- 关标签时若扫码登录仍在进行中，先确认一次；确认后停轮询并丢弃相位（服务端登录会话自己会过期）。除此之外没有任何关标签确认——这个面板没有待保存项。
- 不加右栏角标，底部状态栏原有的 `Channels: n`（已连接计数）保持原样。
- 旧模态与它的三条入口（命令面板手写条目、头像菜单项、外壳模态开合状态与渲染点）一起删除；`components/channels/` 只剩活动流组件，详情组件搬进面板视图目录。

本文不复述打开 / 激活 / 收起 / 关标签这套面板规则，它们是 ADR-0002 的标签条状态机；频道只是它的一个新成员。保存语义由 ADR-0009 按输入形态分档，频道落位见下。

## 为什么它不接右栏角标钩子

这是四轮迁移里**第一个不接角标钩子**的面板，必须写清，否则评审会拿「为什么它和技能 / 定时任务不一致」来反推。

现有三处角标的语义是同一条：**「一次性动作还没结束」**——模型配置是未保存改动、技能是安装进行中、定时任务是有运行在跑。三者都是「用户发起了一个动作，它还在后台/本地进行，且这个事实在面板之外看不到」。频道没有对应物：扫码登录是用户盯着二维码发起的动作，登录相位就显示在详情页的扫码卡里；频道 worker 的轮询 / 退避是服务端常驻行为，不是「一个动作还没结束」。要用一个圆点表示「有频道不健康」，就得新增一个聚合健康接口去持续问遍所有频道——为装饰性圆点换服务端改动，不划算。状态栏的 `Channels: n` 也保持原样：它是一个计数，不改成入口，也不加健康聚合。

**已否决**：新增聚合健康接口 + 角标；用现有每频道 `wechat/status` 轮询在面板收起时点亮角标（那会把一个详情页级的轮询变成常驻轮询，成本换一个圆点）。

## 为什么关标签守卫的判据是「活着的登录会话」而不是 dirty

这是四轮迁移里**唯一一个守卫判据不是 dirty 的面板**，同样必须写清（ADR-0009 按输入形态分档，这里落位）。

频道面板里的四类输入**全部是即时生效项**：新建频道（名字 + 创建）是一次创建动作、重命名、切 workspace、启停都是写穿，扫码的配对码提交就是一次 RPC。**这个面板没有待保存项**，因此没有保存栏、没有未保存角标，守卫里也不存在 dirty 判据。这一点与技能一致（技能也没有草稿），与模型配置 / 定时任务表单不同。

真正的损失只有一处：**一个还活着的扫码登录会话**。二维码在屏幕上、相位还在等结果、配对码可能打了一半，用户点关标签就会把这一次扫码白费。所以守卫只问「当前相位是否属于 `waiting` / `scanned` / `verifying`」（`lib/shared/channels-close.ts`）：这三种相位下用户有未完成的动作、会话还能成功。确认后停轮询、丢弃相位，**不额外调服务端接口**——登录会话自己有有效期，会过期。

- `redirected`（服务端在切 IDC 节点）不拦：客户端对它无可操作，issue 的守卫规则也止于 `verifying`。
- `verify_blocked`（配对码错误次数过多）不拦：这个会话已经无法在不刷新二维码的前提下确认，关掉没有额外损失。
- `confirmed` / `already_bound` / `expired` / `error` 是终态，不拦。

**已否决**：给频道面板也引入草稿 + 保存栏（面板里没有一件需要「保存」的东西，会凭空造出与盘上不一致的本地状态）；把 `redirected` / `verify_blocked` 也算作「进行中」一并拦（终态/无法继续的相位拦下来只是噪音）。

## 为什么扫码登录的相位要活到面板之外

这是本次迁移的真正难点，也是模块级 store 存在的核心原因（ADR-0003 规则 1：一个 concern 只有在状态必须活过单次挂载时才配一个模块级 store）。

面板卡片只渲染当前激活标签的 body，切走标签就卸载视图。二维码、登录相位、`sessionKey`、配对码输入全部提升到 store，所以「扫到一半切去看会话，回来二维码还在」。轮询也跟着 store 走，只在**存在进行中的登录会话**时运行（`lib/shared/channels-login.ts` 的 `isLoginInProgress`：`waiting` / `scanned` / `verifying` / `verify_blocked` / `redirected`），保持 2 秒；相位进终态即停止。浏览器标签页隐藏时**不暂停**：二维码的有效期由服务端掌握，用户扫完码常常已经切到别处，暂停会错过 `confirmed`——而这条轮询只在确实有一个登录会话时才发生。

详情页另有一条每 5 秒拉健康状态的轮询与活动流的自身轮询，它们**不进** store：只在详情页挂载时运行，切走即停。活动流是易变数据，缓存一份只会多一份可能过期的副本（与定时任务的运行历史同一条理由）。

**已否决**：把扫码状态留在详情组件里（切标签即丢，回到最初的抱怨）；页面隐藏时暂停轮询（会错过 `confirmed`）；把健康状态 / 活动流也塞进 store（易变数据进 store 只会多一份过期副本）。

## Considered options

- **保留全屏模态，只把入口挪到右侧按钮列。** 最小 diff，但遮罩仍挡住会话与文件、关掉仍丢扫码相位、平台列仍占一条空栏——用户报告的问题只解决了「找不到入口」一个。与 ADR-0012 / 0014 / 0016 否掉的那条同构。
- **保留左侧平台列，为钉钉 / 飞书 / Discord 预留。** 保住「将来加平台」的视觉位置，但三个空壳入口点进去什么都没有，而且服务端本次只做微信；按分组扩展根页比预留空壳更省。将来真加平台时，根页按 provider 分组即可，不必现在付三个死入口的代价。
- **给频道加右栏角标 + 聚合健康接口。** 见上「为什么它不接角标钩子」。
- **把扫码进行中的所有相位都纳入关标签守卫。** 见上「为什么守卫判据是活着的登录会话」。

## Consequences

- 新增面板视图仍然只有 ADR-0002 的「注册表一条 + 表现一条 + body 一条」，频道落进去没有多出第四处；命令面板条目由注册表声明生成，不再手写。
- 与 ADR-0012 / 0014 / 0016 同样的被迫后果：面板卡片只渲染当前激活标签的 body，切走标签会卸载视图，所以列表、选中、页栈、新建草稿与扫码登录相位必须提升到 shell 级模块 store（`lib/client/channels-panel.ts`）。若将来面板改为保留已打开视图的挂载状态，这部分责任可以回收，但不要现在赌。
- 频道是第一个不接角标钩子的面板，也是第一个守卫判据不是 dirty 的面板：两处都写在上文，评审时不要拿「和技能 / 定时任务不一致」反推。
- 判定被推到纯模块，在 `tests/unit` 里直接驱动：页栈创建 / 打开详情 / 后退 / 删除后收敛 / 新建后落点（原 `lib/shared/channels-pages.ts` 已删除，改由 `lib/client/panel-view-store.ts` 的契约测试统一钉住）、`lib/shared/channels-close.ts`（九相位表的关标签确认）、`lib/shared/channels-login.ts`（轮询进行中判定与相位文案键）。面板内的视觉布局、窄栏里二维码的尺寸与清晰度、配对码输入框在移动端键盘弹出时是否被遮住、50 条活动流在窄栏里的滚动表现、展开模式下的留白、移动端全宽下的页栈，以及「关掉面板标签后扫码会话停止轮询」的 smoke test，仍属人工清单（ADR-0003 规则 3）。
- 服务端频道实现一行未改：worker 轮询、会话冷启动、回复、游标、凭证、活动记录、健康表、SQLite schema、`lib/server/channels/**` 与 `app/api/channels/**` 全部不动。
- 聊天输入栏 `…` 菜单里的「通知频道」子菜单、新会话页的通知频道选择器完全不动——那是「这条会话的回复发到哪」，与「管理频道」是两件事。状态栏的 `Channels: n`（已连接计数）保持原样。

**参见**：ADR-0024「面板视图的生命周期是一个 module」——本文的面板视图状态（保活、释放、页栈与关闭确认）由那一个 module 拥有，本文只提供 adapter，Decision 不变。
