# 记忆是冻结快照注入的 agent 可写持久库，预算、扫描与漂移保护三重防线

Pi Work 要让 agent 跨会话记住用户与环境的持久事实。这些事实必须进系统提示词才有用，而系统提示词的作者是 agent 自己——于是出现一条别处不存在的路径：**工具调用产生的内容，会在下一个会话被原样送回所有会话的提示词前缀里**。一条被 prompt injection 污染的记忆不是影响一个回合，而是持久地站在每个会话的最前排。

**我们决定**：记忆做成双库有界文件（MEMORY.md / USER.md，字符预算 2200 / 1375），注入采用**冻结快照**——会话创建时读一次进系统提示词，本会话内写入落盘但不刷新提示词，下个会话生效；写入路径上立三重防线：入库内容先过注入/外泄扫描、字符预算硬上限（含批量只看终态）、漂移保护（检测到外部手写的自由文本时拒绝覆写而非静默丢弃）。

## 为什么冻结，而不是热刷新

会话中途刷新提示词意味着每一轮的上下文前缀都不再稳定，pi 的前缀缓存全部作废、每轮重算重付；这是 Hermes 用生产事故换来的取舍（它注释里写得很直白：中途改提示词破坏前缀缓存）。而冻结的代价几乎为零：记忆本来就是低频写入的背景事实，「写了当下自己看不见」对 agent 的工作没有实际影响，工具返回里一句「已保存，本会话提示词不刷新」就消除了重复写入的冲动。pi 的系统提示词本来就是会话级固定的，冻结跟平台语义天然对齐，不需要任何额外机制。

## 为什么三重防线而不是审批

对 agent 写记忆做人工审批（Hermes 的 `write_approval` + 后台审查待审队列）是一条完整的子系统：审批存储、审批 UI、暂存重放、条目钉扎防审查后内容漂移。我们判断它防的威胁在 Pi Work 还不存在，而三条防线的成本低得多且各自独立生效：

- **扫描**挡污染：记忆进系统提示词，注入内容持久存在，所以入库扫描必须是入库路径上的闸门，不是事后审计；
- **预算**挡洪泛：上限按字符计（模型无关），批量预算只看终态，让「删旧腾位 + 加新」一次调用完成，不给 agent 绕过整合的空隙；
- **漂移保护**挡静默丢失：用户手改过文件后，工具拒绝覆写而不是把读不出的内容当空文件清掉。V1 只做「单条目超整库上限即整库拒绝」的简化版，.bak 快照与多态判定等第一次真实事故再升级。

三道防线共同的底层判断：记忆的破坏面是**有界**的（最多丢或污染这两个有上限的文件，不碰文件系统其余部分），所以不需要危险命令那套确认网络，闸门逻辑全部无交互、fail-closed。

## 写入权随工具集走，不做会话类型限制

早先设计里考虑过「写工具只给用户交互会话，子代理与定时任务是无人值守的，不该有跨会话写入权」。这个限制被推翻：无人值守档位（ADR-0025）管的是**危险命令**，那是文件系统级的破坏面，而 memory 工具有字符预算硬上限与入库扫描，破坏面天然有界；子代理档案的工具集本来就是用户亲手配置的授权清单，再由平台替用户挡一层没有意义。所以注入按 cwd 开关对所有会话类型一视同仁，`memory` 工具进普通工具选择面与子代理档案工具集，勾掉它只是失去主动写入（注入照旧，agent 仍被动利用已有记忆）。

## 与既有概念的分界

- 与**追加系统提示词**（APPEND_SYSTEM.md）：作者是用户而不是 agent，走 pi 自己的 loader，我们只读不写它的目录；记忆作者是 agent，文件在 `~/.pi-work/memory/`，Pi Work 自有存储域。
- 与**技能**：技能是流程性知识，索引进提示词、正文按需加载；记忆是跨会话事实，全量注入且有预算。「怎么做」进技能、「是什么」进记忆，边界靠 memory 工具描述的 WHEN/SKIP 段落执行。
- 与 `<cwd>/AGENTS.md`：项目级事实归项目自己的 context file，记忆全局一份，不按 cwd 分库。

## Considered options

- **热刷新提示词**：破坏前缀缓存，每轮重付；换来的只是 agent 当场看见自己刚写的内容，价值远低于成本。
- **写入审批 / 后台审查 fork**（Hermes 全套）：防的威胁（前台滥用、后台无人值守误删）在 Pi Work 尚无实证；审批子系统本身的复杂度（暂存、重放、钉扎）超过被保护对象的价值。等真实使用数据再决定。
- **按会话类型限制写入**：见上，破坏面有界使限制失去依据。
- **按 cwd 分库**：项目级事实已有 AGENTS.md 承接；分库翻倍存储、UI 与预算逻辑，只换来重复能力。
- **写进 `~/.pi/agent/AGENTS.md` 借 pi 的 context file 机制**：等于在用户的指令文件里混入 agent 生成内容，污染「追加系统提示词」的作者边界，且违反不动 `~/.pi` 用户数据的红线。

## Consequences

- 记忆 block 在三种系统提示词模式（default/prefix/override）下都注入、排在用户内容之后；空库不注入。
- 开关判定固定在会话创建时（与冻结快照同一时点）：全局 `config.memory.enabled` 默认关 + cwd 级只记显式关闭的覆盖项；切换开关不影响已存在的会话。
- 关闭开关只是不注入、不提供工具，记忆文件原样保留。
- 工具契约里批量是原子语义：任何一条 op 失败则整体不落盘；预算拒绝的返回带当前条目清单，引导一次性整合。
- 漂移保护 V1 简化版是刻意的欠工程：升级路径（.bak 快照、多态判定）在第一次真实事故前不建。
