# 记忆两级注入：会话冻结索引 + 运行时实时读明细

旧记忆机制把全部条目在会话创建时一次性注入系统提示词，要么全进要么不进：上下文成本随记忆总量线性增长，而「长会话里其实只用到一两个话题的事实」这一真实访问模式无从表达。**我们决定**：记忆分两级注入——**索引**（分类目录加高价值摘要，预算 2000 字符）在会话创建时读一次冻结进系统提示词，会话内改动不刷新；**明细**（按分类自由命名的 Markdown 文件）不进注入，由 agent 运行时经 read / write 实时读取与写入，只取当前话题相关的分类。

- **冻结语义只作用于索引**，理由承 ADR-0029 不变：中途刷新系统提示词破坏 pi 的前缀缓存，而索引是低频变动的目录，会话内写的新记忆下个会话自然出现在冻结的索引里。**明细不冻结**，因为它根本不在提示词里，agent 的 read 每次都拿磁盘上的最新内容——本会话刚写的事实立即可读，也不存在旧机制「写入落盘但本会话看不见」的空窗。
- **明细的格式与预算代码不管**：分类清单不预设，agent 按需新建文件并在索引里登记；索引超预算不强制截断，靠记忆管理指引约束。
- 注入装配沿用现有系统提示词追加位置：旧记忆块替换为「指引 + 索引」一段，记忆关闭时两者都不注入，默认 / prefix / override 三种模式下位置不变。

取舍的对手方案是「把明细也注入」或「索引也做成运行时读」：前者回到全量注入的老路，后者要求 agent 每个会话先花一轮探测文件系统才能知道记忆存在，破坏「开箱即知」；冻结索引恰好是两者之间最便宜的折中。
