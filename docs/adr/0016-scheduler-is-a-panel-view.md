# 定时任务是面板视图

定时任务（任务列表、单个任务的概览 / 运行历史 / 提示词 / 配置、新建与编辑表单）此前是 Pi Work 里唯一还活在全屏模态里的「配置型工具」，而且叠了两层：外层是 940×84vh 的任务窗口（左侧 280px 任务列表 + 右侧四个分块），新建 / 编辑时再叠一层 760×84vh 的表单窗口，两层各有一块遮罩，内部还靠 160px 左导航在三段之间切换。它在多处站不住脚：任务到底往系统提示里写了什么、上次跑出了什么结果、cron 到底会在几点触发，恰恰要对着会话与工具输出核对，遮罩一挡就什么都对不上；右侧按钮列已经有 Token 审计、翻译、Git Diff、模型配置、技能这些同级工具，定时任务却只能从命令面板或左下角头像菜单进入；表单三段导航让「错误藏在没打开的那一段」；关掉即丢筛选、搜索词、选中任务、填了一半的表单与正在看的运行历史；最后，任务在后台真跑，面板之外却没有任何信号。模型配置（ADR-0012）与技能（ADR-0014）已经沿同一条路迁成了右侧面板视图，定时任务是同一类工具。

**我们决定**把定时任务变成右侧按钮列上的一个**全局按钮**，点开后作为**面板视图**出现在右侧面板：

- 面板身份就是面板注册表里的一条 kind / 右栏按钮 id（同一个字符串，也是写进用户 `config.yaml` 的持久化键）：默认可见、`sessionBound: false`，声明顺序排在技能之后、对话树之前。左下角头像菜单的入口删除；命令面板条目由注册表生成（复用既有的 "Open scheduled tasks" 词条与中英文 keywords：scheduler / cron / timer / tasks / 定时 / 任务 / 定时任务），手写的 `modal.scheduler` 命令随实现一起删除。按钮、标签条、命令面板共用同一个时钟 glyph，符合注册表的既有不变式。
- 面板内部是**三级页栈**：根页（任务列表，带搜索、四个筛选、运行中提示条与新建入口）→ 详情页（带任务 id，保留概览 / 运行历史 / 提示词 / 配置四个横向分块）→ 表单页（带任务 id 或「新建」，把原来的三段左导航改成一条纵向滚动，滚动区外固定一条保存栏）。每级全宽加返回控件，Esc 退一级，退到根页再按才走面板标签的关闭规则。
- 列表、选中任务、搜索词、筛选、页栈位置与表单草稿活在面板视图之外的模块级 store（`lib/client/scheduler-store.ts`）：**收起面板、切标签都不算离开**，不丢草稿、不闪 loading；只有关闭该面板标签时才释放，草稿未保存时先确认一次，重开一律回根页并重新拉一次列表（任务列表是活数据，每次运行都会改上次 / 下次运行时间，没有「重读会丢东西」的问题）。
- 运行历史**不进** store：它是易变数据，本来就靠运行中每 2 秒重拉一次，缓存一份只会多一份可能过期的副本；详情页组件自己持有，切走再回来重拉。
- 右栏 descriptor 的 badge 钩子接上「有任务正在运行」角标，判据是任务列表里存在 `lastRunStatus === "running"` 的任务；角标是固定小圆点，不显示数字。调度器没有事件或推送通道，所以角标靠轮询，节奏按面板状态分三档：面板打开且停在运行历史页每 2 秒、面板打开其它页每 10 秒、面板收起每 30 秒；浏览器标签页隐藏时一律暂停。
- 旧的外层任务模态与内层表单模态，连同它们的遮罩、`useModalAnimation` 用法、以及外层把 Esc 优先级写死的处理一起删除；`AppShell` 里为它保留的模态开合状态、命令上下文 `openScheduler`、头像菜单回调链一起收口。只剩面板这一条实现。

本文不复述打开 / 激活 / 收起 / 关标签这套面板规则，它们是 ADR-0002 的标签条状态机；定时任务只是它的一个新成员。

## 为什么三个共享选择器保留成应用级对话框

表单里的工作目录、模型、推理强度、工具四个选择器**保持原样**，继续是聊天输入区共用的应用级对话框，允许它们盖在面板之上。这与「模型配置面板里把 provider / 模型做成面板内页栈」并不冲突：那篇决策否决的是同一件事被套两层模态（配置模型要边看会话边核对），要为此重做容器；而这里是「选一个值」，三个共享选择器被聊天输入区、斜杠命令、定时任务共用，把它们各自改造成面板页等价于第三次实现同一份模型 / 目录 / 工具列表。代价照实记：面板里点「选模型」会把面板整个盖住；这是为了不复制列表而接受的一次性覆盖，不是又一层常驻模态。

## 为什么角标按最后一次运行状态认，且不给卡死开例外

角标只回答一个问题：「现在有没有任务在跑」。判据是任务的 `lastRunStatus === "running"`，卡死不构成例外——一个超过单次运行上限仍在跑的运行，确实就是正在运行，掩盖它比误报更糟；如果角标把「可能卡住了」的运行摘掉，用户反而会以为后台什么都没发生。「可能卡住了」是详情页运行历史的长时警示（运行超过 10 分钟的那条提示）负责的事，两者分工不同：角标给「有没有」，长时警示给「是不是不对劲」。角标也只做固定小圆点、不显示数字，因为「n 个」对「有没有」这个判断没有增量，还要多维护一份计数。

## 为什么启停是即时生效项，而表单是待保存项

按 ADR-0009 的输入形态分档，同一面板里两种保存语义并存，这是全程最容易反推错的一点：

- **任务的启停是即时生效项。** 它是一个布尔开关，没有「改了一半」的中间态，拨一下直接写盘，没有草稿、没有保存栏、也没有对应的未保存角标。再补一条保存栏只是把「点一下」变成「点两下」，还会凭空造出一份可能与盘上不一致的本地状态。
- **任务表单是待保存项。** 它由名称、cron、工作目录、模型、提示词、通知等自由文本与选择组成，改动先停在本地，显式保存时一次提交整份表单（新建一次创建，编辑一次更新），不引入逐字段自动保存。保存后的落点是该任务的详情页（新建则是新任务的详情页）：定时任务最容易犯的错是 cron 写错而自己没发现，保存完立刻看到算出来的下次运行时间才算闭环。

因此它的关标签守卫只有「表单相对打开时的快照是否有改动」一个判据（`lib/shared/scheduler-close.ts`），空白新建表单打开即不算 dirty；运行历史里有任务在跑不构成守卫理由——任务在服务端继续跑，不该拿它当人质。

## Considered options

- **保留两层模态，只把入口挪到右侧按钮列。** 最小 diff，但遮罩仍挡住会话与文件、内层仍靠三段导航切、关掉仍丢草稿与筛选——用户报告的问题只解决了「找不到入口」一个。与 ADR-0012 / ADR-0014 否掉的那条同构。
- **把三个共享选择器也做成面板内页栈，彻底消灭覆盖层。** 面板里不再有遮罩，但模型 / 工作目录 / 工具列表就此有了第三份实现，且它们本是三个使用方共用的应用级对话框；改造成本是「第三次实现同一份数据」，收益只是少一次一次性覆盖。
- **启停也改成待保存项，表单与开关统一走一条保存栏。** 视觉统一，但要给一个布尔开关配上「已保存 / 未保存」状态，把即时生效项强行改成待保存项，与 ADR-0009 按输入形态分档的结论相冲突，还会让面板里显示的启用状态与盘上短时间不一致。
- **角标给卡死开例外（超过单次上限就不点亮）。** 少一次「假运行」的误报，但会把一个仍在消耗资源的运行伪装成「没在跑」；掩盖比误报更糟。长时警示已经是这条信息的正确出口。
- **给调度器加事件 / SSE 推送，角标不轮询。** 语义最直接，但服务端调度器本次不改（见 Out of scope），而 30 秒一轮的轮询对一个圆点足够；加推送要为一次纯客户端迁移引入新的服务端通道。

## Consequences

- 新增面板视图仍然只有 ADR-0002 的「注册表一条 + 表现一条 + body 一条」，定时任务落进去没有多出第四处；命令面板条目也由注册表声明生成，不再手写。
- 与 ADR-0012 / ADR-0014 同样的被迫后果：面板卡片只渲染当前激活标签的 body，切走标签会卸载视图，所以列表、选中、筛选、页栈与表单草稿必须提升到 shell 级模块 store（`lib/client/scheduler-store.ts`）。若将来面板改为保留已打开视图的挂载状态，这部分责任可以回收，但不要现在赌。
- 右栏 descriptor 的 badge 钩子被第三次使用（模型配置是未保存改动，技能是安装进行中，定时任务是有运行在跑），三处共用同一个钩子、只换判据，不各存一份。
- 轮询只在有订阅者时运行（形状对齐现成的运行中会话轮询 store `hooks/runningSessionsStore.ts`）；右栏角标永远是订阅者之一，所以面板收起时轮询仍以 30 秒低频维持「有任务在跑」这个信号，浏览器标签页隐藏时暂停。
- 运行记录里的「打开会话」打开对应会话但**不**收起面板：会话开在中间列，面板留着正好边看记录边看会话。
- 删除任务、启停等破坏性动作复用项目既有的应用级确认对话框（面板关闭守卫用的是同一套），不另造面板内的确认层.
- 服务端调度器一行未改：调度循环、运行器、并发链、超时、运行记录写入、SQLite schema、cron 语义、时区处理、通知渠道与危险命令确认全部不动；`lib/server/scheduler/**` 与 `app/api/scheduled-tasks/**` 零改动。
- 删掉的当前源码注释里那套从未实现的单键快捷键（新建、搜索、上下导航、运行、暂停、编辑、帮助）不迁移，只保留 Esc；运行记录行展开的 Enter / 空格切换与 role 标注保留。
- 判定被推到纯模块，在 `tests/unit` 里直接驱动：`lib/shared/scheduler-pages.ts`（页栈创建 / push / back / 保存与删除后的收敛）、`lib/shared/scheduler-close.ts`（表单快照的 dirty 判定与关标签确认）、`lib/shared/scheduler-cadence.ts`（面板状态 + 页面可见性 → 下一次延迟）。面板内的视觉布局、窄栏下 cron 构造器的换行、三个共享选择器盖住面板的观感、角标在面板收起时的可见性、移动端全宽下的页栈，以及「关掉面板标签后服务端任务照常跑完」的 smoke test，仍属人工清单（ADR-0003 规则 3）。

**参见**：ADR-0024「面板视图的生命周期是一个 module」——本文的面板视图状态（保活、释放、页栈与关闭确认）由那一个 module 拥有，本文只提供 adapter，Decision 不变。

## 修订 2026-10-18（频道面板 #138）

频道也迁成了右侧面板视图（ADR-0017）。它与本文的分工：定时任务有角标（有运行在跑）与 dirty 守卫（表单草稿），频道两者都没有——不接角标钩子，守卫判据是「活着的扫码登录会话」。这两处差异写在 ADR-0017 里，评审不要反推定时任务也应去掉角标 / 守卫。

**参见**：ADR-0017「频道是面板视图」。
