# MCP 服务器是面板视图

MCP 服务器配置（两份 `mcp.json`：全局 `~/.pi/agent/mcp.json` 与工作目录 `<cwd>/.pi/mcp.json`，条目作用域、条目覆盖、无效条目、显式保存）此前是一个全屏模态框（`components/settings/McpConfig.tsx`），入口只有两条：左下角头像的悬浮菜单，以及命令面板里手写的一条 `modal.mcp`（还带 `hasCwd` 守卫）。它在多处站不住脚：核对某个服务器到底配了什么、下个会话会以你的权限执行什么命令，恰恰要对着会话与工具日志看，遮罩一挡就什么都对不上；右栏已经有 Token 审计、翻译、Git Diff、模型配置、技能、定时任务、频道这些同级工具，MCP 却不在那儿；模态内部靠组件本地状态在「列表 ↔ 条目」之间切换，进得去出不来，没有「返回上一级」；关掉即丢草稿与页内位置。模型配置（ADR-0012）、技能（ADR-0014）、定时任务（ADR-0016）、频道（ADR-0017）已经沿同一条路迁成右侧面板视图，这是第五次同构迁移。

顺带钉正一处**术语漂移**：ADR-0010 通篇把当时这个东西叫「MCP 面板」，但它实际上是全屏模态框，不是 CONTEXT.md 里定义的**面板视图**（右侧面板里的一个工具界面）。本文把用词钉正，并把容器换掉；ADR-0010 的写盘规则一个字都不改。

**我们决定**把 MCP 变成右侧按钮列上的一个**按钮**，点开后作为**面板视图**出现在右侧面板：

- 面板身份就是面板注册表里的一条 kind / 右栏按钮 id（同一个字符串 `mcp`，也是写进用户 `config.yaml` 的持久化键，标签 id 形如 `mcp:global`）：默认可见、`defaultMode: "normal"`、`sessionBound: true`，声明顺序排在模型配置之后、技能之前。按钮、标签条、命令面板共用现成的 MCP glyph。标签 key 复用既有的 `mcp.title`（「MCP 服务器」），不新造短标签——「MCP」单独两个字在标签条里指代太窄（它也可能是「这个会话用哪些 MCP 工具」）。命令面板条目由注册表生成（复用既有 `mcp.open` 词条与关键词，**去掉 `hasCwd` 守卫**），手写的 `modal.mcp` 条目与它依赖的打开函数随实现删除；左下角头像菜单的入口删除。
- 面板内部是**两级页栈**：列表页（两份文件各一节，各自带文件级开关 `autoEnableCodemode` 与文件级解析错误）→ 条目页（表单 / 原始 JSON 双模式，新条目多一个作用域选择器）。每级全宽加返回控件，Esc 退一级，退到列表页再按才走面板标签的关闭规则。「+ 添加服务器」把新草稿追加进列表并直接进条目页，不新开独立页面。
- 面板底部固定一条保存栏（保存 / 保存中 / 已保存 / 错误），加上原有的 `mcp.applyHint` 与「新建会话」动作，不再需要滚到底找按钮。
- 保存前的那张确认（逐条列出将删除的条目、以及下个会话会以你的权限执行的命令）**保留为应用级对话框**，不降级成页面内提示：它是「一次不可逆写入前的最后一道闸」，塞进窄栏会丢掉「屏幕被遮住所以必须停下来读」的重量，而它要说的两件事（删条目、spawn 命令）恰好是面板里最危险的动作。
- 草稿、页栈位置与已读到的文件快照活在面板视图之外的模块级 store（`lib/client/mcp-store.ts`）：收起面板、切标签都不算离开；只有关闭该面板标签时才可能丢弃，dirty 时先确认。右栏 descriptor 的 badge 钩子接上未保存改动角标，面板收起时仍然可见。

**这次只换容器、不改保存语义。** 这批字段继续走 ADR-0010：一次提交 = 对每个受影响的 `mcp.json` 做一次保留式读-改-写，先整批校验再落盘，任何一条不合格就一条都不写；`~/.pi/agent/` 的写口仍然只有那个专用路由，不经过 `lib/server/file-access.ts` 的允许根。唯一的信号变化是「新建会话使用新的 MCP 配置」从「模态关闭」这件事上摘掉——模态不存在了，落点改为保存成功。

本文不复述打开 / 激活 / 收起 / 关标签这套面板规则，它们是 ADR-0002 的标签条状态机；MCP 只是它的一个新成员。参照对象是 ADR-0014「技能是面板视图」：容器那条路（按钮、注册表条目、模块 store 保活）完全一致，但保存语义刻意分道扬镳。

## 为什么它与技能 / 模型配置在两个点上刻意不同

这是全程最容易反推错的两处，尤其当评审认为「应该和技能逐字一致」或「应该和模型配置逐字一致」时。

### 一、为什么按钮是会话绑定的，dirty 判据却按 cwd 分桶

面板内容**确实跟 cwd 走**——多了 `<cwd>/.pi/mcp.json` 那一节，条目作用域与条目覆盖正是这个领域模型的核心。这与技能同构，所以 `sessionBound: true`、无会话时回退「新会话正在用的工作目录」（这个 flag 只驱动列分组，不禁用按钮），与 ADR-0014 的取值逐字一致。

真正的新问题是：**面板开着、草稿没保存、用户切到了另一个会话**时这份草稿算谁的。`PUT /api/mcp` 的 body 里必须带 cwd，而「本工作目录」那份文件是哪份完全由 cwd 决定；面板 body 拿到的 cwd 又跟着选中会话变。三个候选里：

- 「切换即重载，dirty 时先确认」把「切会话」这个主航道动作挡在确认框后面，太贵而且突兀；
- 「草稿钉住它读出来时的 cwd、面板继续显示旧 cwd 的内容」会让面板停止跟随会话，与上面刚确立的取值顶牛；
- 「按 cwd 分桶、只留 dirty 的」两个都保住：面板永远显示当前 cwd 的内容，离开一个 cwd 时把它的 dirty 草稿停在 store 里，回到那个 cwd 时原样恢复，干净的直接丢。

我们取第三条（`lib/shared/mcp-drafts.ts`）。它的代价是**两处判据随之扩大到「任一 cwd 有未保存草稿」**：右栏 dirty 角标，以及关标签守卫（关标签会释放整个 store，停在别处的草稿会一起没）。评审看到「角标在别的会话里也亮着」时，不要当成 bug。

### 二、为什么干净时重开要重读盘

房子的既有规矩是 reuse：模型配置的草稿活在模块 store 里，只有**关标签**才释放，下次打开才重读磁盘（`selectModelsConfigOpenAction`）；技能靠 list 缓存做到「不闪 loading」。MCP 有一条它们没有的事实——ADR-0010 白纸黑字写着这个文件**不止一个写者**（pi CLI / TUI、用户手改），而且每次保存都是**以磁盘当前内容为基底**的读-改-写，从不假设自己的快照是最新的。写路径已经承认「我看到的可能不是最新的」，显示层却假设「我看到的就是最新的」，这两半自相矛盾。

所以 MCP 的规则是：面板没有 dirty 草稿时，每次重新可见都重拉一次 `/api/mcp?cwd=`；dirty 时保留草稿不重读（`lib/shared/mcp-close.ts` 的 `selectMcpOpenAction`）。代价只是本地一次文件读取和一次可能的 loading 闪动；换来的是「面板不会拿一份可能是昨天的手改内容骗你」，而且不需要新增「刷新」按钮——house rule 下想刷新就得关标签重开，很反直觉。

**已否决**：跟模型配置完全一致地 reuse（显示层会落后于磁盘，且与 ADR-0010 的 RMW 前提相悖）。

## Considered options

- **保留全屏模态，只把入口挪到右侧按钮列。** 最小 diff，但遮罩仍挡住会话与文件、页内仍是组件本地状态切换、关掉仍丢草稿——用户报告的问题只解决了「找不到入口」一个。与 ADR-0012 / 0014 / 0016 / 0017 否掉的那条同构。
- **借这次机会把 MCP 拆成条目级即时写入**（点一下条目就落盘，像技能开关）。看似更自然，但等于放弃 ADR-0010 的批次校验与原子性（一次提交 = 一次读-改-写、任一不合格就一条都不写），也把「保存」从 ADR-0009 的待保存项里挪出来。本次不做。
- **`sessionBound: false`，跟模型配置归到全局按钮族。** 可辩（主内容其实是全局那份，工作目录文件默认还被 `mcp.project_servers` 关着），但面板内容确实有一节随 cwd 出现/消失，参照 ADR-0014 的字面判据没有理由反推。
- **草稿钉住旧 cwd、面板继续显示旧内容 + 横幅。** 见上「为什么按 cwd 分桶」。
- **把保存前确认降级成页面内确认区 / 页栈的一页。** 见「我们决定」第四条。

## Consequences

- 新增面板视图仍然只有 ADR-0002 的「注册表一条 + 表现一条 + body 一条」，MCP 落进去没有多出第四处；命令面板条目由注册表声明生成，不再手写。
- 与 ADR-0012 / 0014 / 0016 / 0017 同样的被迫后果：面板卡片只渲染当前激活标签的 body，切走标签会卸载视图，所以草稿（按 cwd 分桶）、页栈位置与文件快照必须提升到 shell 级模块 store（`lib/client/mcp-store.ts`）。若将来面板改为保留已打开视图的挂载状态，这部分责任可以回收，但不要现在赌。
- 角标钩子被第四次使用（模型配置是未保存改动、技能是安装进行中、定时任务是有运行在跑、MCP 是未保存改动且跨 cwd），四处共用同一个钩子、只换判据，不各存一份。
- `PanelBodyCtx` 需要新增一个「新建会话」回调（底部栏的 `mcp.newSession` 要用），这是本次唯一的 shell 接口变化。
- 服务端 MCP 实现一行未改：`lib/server/mcp-config.ts` 的镜像 loader / 校验器、`lib/server/mcp-entries.ts` 的第二读取器与读-改-写、`app/api/mcp` 的 GET / PUT、`lib/server/config.ts` 的 `mcp.project_servers` 全部不动。CHANGELOG 意义上「容器换了、写盘规则没换」就是本文与 ADR-0010 的关系。
- 判定被推到纯模块，在 `tests/unit` 里直接驱动：`lib/shared/mcp-drafts.ts`（按 cwd 分桶、park / restore、任一 dirty）、`lib/shared/mcp-pages.ts`（页栈 push / back / 保存与删除后的收敛）、`lib/shared/mcp-close.ts`（关标签确认与重开是否重读盘）；既有的 `lib/shared/mcp-draft.ts`（草稿、dirty、校验问题、待提交载荷）规则不变，只补它的分桶外壳。面板内的视觉布局、窄栏下两节列表与原始 JSON 编辑器的高度、`autoEnableCodemode` 开关在窄栏里的排布、空态与加载态文案，以及「原始 JSON 编辑到一半切走再回来内容还在」的 smoke test，仍属人工清单（ADR-0003 规则 3）。
- 聊天输入栏、会话工具选择器里与 MCP 工具相关的一切完全不动——那是「这个会话用哪些工具」，与「管理 MCP 服务器」是两件事。

**参见**：ADR-0010「Pi Work 自己读写 pi 的 mcp.json，而不是调 SDK 的配置写入接口」（保存语义，本文不动）、ADR-0012「模型配置是面板视图而不是模态框」（容器那条路）、ADR-0014「技能是面板视图，且它是即时生效项」（同一个参照对象，保存语义相反）、ADR-0009（保存语义按输入形态分档）、ADR-0002（标签条状态机）。

## 修订 2026-10-18（加载、简化与遮蔽条目 #155）

「二、为什么干净时重开要重读盘」那段论证**仍然成立**——`mcp.json` 不止一个写者（pi CLI / TUI、用户手改），写路径从不假设自己的快照是最新的——但**刷新口径改了**：干净时重开不再阻塞在首帧的读取上。面板先渲染上一次读到的快照，同时在后台向磁盘核对，核完悄悄替换，只留一个「正在核对」的轻微指示。新鲜度语义一个字没改：干净时依然每次核对磁盘，未保存的草稿依然不被覆盖，变的只是首帧不再等这次核对。

因此「**已否决**：跟模型配置完全一致地 reuse」依然成立——reuse 根本不会核对，而这里必须核对。这次只是把「必须核对」与「必须阻塞首帧」解耦。每个 cwd 的快照各自保留，切回上一个目录不必重新等待；只有关闭面板标签才释放整张桶表。

同一次修订还做了三件事，都不改 ADR-0010 的写盘规则（一次提交 = 一次保留式读-改-写、先整批校验再落盘、任一不合格就一条都不写）：

- **遮蔽条目生效**：项目里一条只含 `enabled` / `exposure` / `toolExposure` 的条目，pi 的 loader 会把它合并进同名全局条目，而 Pi Work 的镜像漏了这条 `isOverride` 分支，把它当无效条目静默丢掉。现在 loader、面板读写半与草稿校验都与 pi 对齐，面板把它显示为「遮蔽」而不是「无效」，并新增「在本工作目录停用」这个一键动作。这是**补齐镜像**，不是新语义。
- **配置面收窄**：条目表单只留名称、传输方式、命令或 URL，其余进默认收起的高级区；原始 JSON 从并列模式降级为「编辑原始 JSON」动作；同一类错误只在列表页的一条可展开汇总里说一次。
- **服务端成本下降**：允许根缓存的 TTL 从 5 秒提到 30 秒并加并发去重、启动时后台预热，`config.yaml` 增加进程内缓存（写后即失效 + mtime/size 守卫）。允许根的授权答案与失效语义未变，变长 TTL 是朝 fail-closed 方向。
