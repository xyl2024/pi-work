# 定时任务是主视图，不是面板视图

会话列里只有一件东西：会话卡片。所有配置型工具都被挤进右侧面板那条窄条——定时任务、频道、技能、模型配置共用一条 420px 上下的容器，装任务列表加三级页栈时只能横向打架；而右栏按钮那一列同时背着入口、开关与角标三种职责，一个图标要回答三件事。定时任务恰恰是「需要整块区域、且与某个会话没有关系」的那类内容：它自己的列表比被它挤窄的会话更值得占地方。ADR-0016 把它从两层模态迁到右栏面板，解决了「找不到入口、遮罩挡住会话」，没解决"它本来就该有一块完整区域"。

**我们决定**在会话列里引入**主视图（Main view）**，定时任务从右侧面板整体搬到主视图：

- **主视图是会话列里与会话卡片互斥的主内容**，状态是一个单一枚举：`{ active: "chat" }` 或 `{ active: MainViewKind; returnPanelMode: PanelMode }`。它不是栈，没有历史，`back()` 恒回 `chat`；`toggle` 在同一 kind 上等价于 `back`。`returnPanelMode` 是进入主视图时对右栏 mode 的快照，返回时还原。
- 主视图与面板不是同一种容器，也不是同一个词的两种形态：`MainViewKind` 与 `PanelViewKind` 是互不重叠的两个集合，定时任务从面板注册表里整条移除（右栏按钮、右栏标签条、右栏设置里的那一项开关、面板的 kind 与 icon 映射一起下线）。`GLOSSARY.md` 的「面板视图」定义随之收窄成右栏专属。
- **两侧都常驻挂载**：会话卡片在主视图前台时只是 `display: none` + `flex: 0 0 0%`，与终端全屏早就走通的那条路一致。理由是聊天草稿只住在组件本地 state 里，卸载即丢；这条红线不接受任何「反正用户看不见」的简化。
- **返回不等于关闭**：定时任务的状态（表单草稿、页栈位置、筛选、搜索词、选中任务）在主视图隐藏期间全保留，下次进来还在原处；它的轮询也继续跑，因为侧栏那条运行中角标存在的唯一理由就是「你没看的时候告诉你」。相应地，主视图没有「关闭」动作，store 在页面存活期间不 release，随刷新一起清空。
- **进入主视图收起右栏，返回时还原原样**。右栏是跟会话强绑定的区域，会话卡片不在旁边时它已经失焦；但那次收起是系统替用户做的，系统就该还回去。终端不受影响——它是用户自己开的、与会话无关的东西。
- **入口搬到左侧边栏导航区**，与既有的两条并列；它按面板标签条既有的 toggle 语义工作（点已激活的入口即退出），因此 `SidebarNavButton` 长出 `active` 与 `badge`。运行中角标从小圆点右栏按钮搬到这条导航项上。命令面板里那条命令保留，但只负责进入、不做 toggle——命令面板没有「你已经在这里面」的可见反馈，toggle 会变成盲操作。
- **会话专属的快捷动作需要一个新的判据**：`Ctrl+F` 会话内搜索的现有门禁只有「该标签页是激活标签页」，与可见性无关；主视图把「激活」和「前台」拆成两件事之后，它会去打开一个藏在 `display: none` 里的搜索框。因此「会话卡片是否在前台」显式定义为 `mainView.active === "chat"`，用它关掉 `Ctrl+F` 与空格聚焦输入框；其余全局键（`Ctrl+B`、`Ctrl+K`、`Ctrl+` `、`Esc`）照旧有效。
- **任何切换当前工作的动作都退主视图**：点任一会话行、新建会话、从运行记录打开会话、命令面板打开某个会话。这一条挂在既有的「切换当前会话」钩子处，不散落到各入口。
- **主视图不持久化**，与右栏一致，刷新回会话卡片。表单草稿本来就在组件 state 里、刷新必丢，所以「刷新后还停在表单页但表单被清空」比直接回会话更让人失去信任。
- 生命周期仍由 ADR-0024 的那个 module 拥有：定时任务只提供 adapter，页栈、保活、加载策略、`guard` 关闭确认一字不改；把 adapter 的 `kind` 从 `PanelViewKind` 放宽为 `PanelViewKind | MainViewKind` 是本次唯一的 interface 改动。

## Considered options

- **保留右栏按钮，两个入口共享同一状态。** 看起来只是多一个入口，代价是同一个视图两种宿主：`panel-view-store` 的契约是围绕窄面板设计的，保活、可见性、脏态提示的语义都跟着那片区域走；两个入口并存后「收起面板」到底算不算离开、角标按哪套可见性判、`usePanelViewLifecycleSync` 的「标签不存在即释放」会不会在切到主视图时把状态清掉，三处都要额外回答。一个视图两个家，是这次最想避免的形状。
- **主视图做成右栏的一个 `expanded` 档。** 零新概念，但右栏标签条、它的按钮、它跟会话的绑定关系全都会跟着走进一块整区域；用户看到的是「一整块宽面板，顶上有标签条」，于是下一次又会想在里面开第二个标签，互斥的模型保不住。
- **主视图做成会话标签页的一种 kind。** 与「草稿」「助理」并列，天然获得标签条与关标签规则；代价是定时任务会变成一个可以被关掉、可以被拖拽排序、与某个会话上下文并列的东西，而它与会话没有任何关系，也没有「关闭」这个动作。
- **进入主视图时卸载会话卡片、返回时重建。** 省内存、省隐藏状态，但聊天草稿、输入历史本地状态、流式回合并发全部随之丢失——这是功能回退，不是简化。
- **返回时把定时任务 store `release()`。** 「离开即清理」看起来更干净，但与「返回不等于关闭」直接冲突：填了一半的任务表单会在来回看一眼会话时被清空。丢掉草稿的代价远大于常驻一份列表。

## Consequences

- 新增一条主视图只需要一张注册表（kind、labelKey、commands）加一条渲染分支；侧栏导航项、命令面板、卡片渲染三处都从同一张表读，不需要再改外壳接线。这是为后续迁移留的形状，本次只有一个成员。
- 面板注册表收缩后，`PANEL_TAB_KINDS`、右栏按钮 id 列表、命令生成的断言都要跟着改；这是既有测试的必然变动，不是新增覆盖。
- 定时任务从「面板收起」变成「没人会关闭」，轮询因此从页面打开过主视图之后一直跑。它本来就是 30 秒 / 10 秒 / 2 秒分档且标签页隐藏时暂停的形状，代价可控；换来的是角标真正实时。
- 继承自 ADR-0016 的局限没有消失：store 只在主视图被打开过之后才有任务数据，所以「服务端任务在跑、但本次页面从未进入过定时任务」时侧栏角标不会亮。
- `config.yaml` 里既有的 `right_side_bar.scheduler` 布尔不会被清理、也不再被读取；设置界面里那一项随之消失。用户配置不因信息架构调整而被系统悄悄改写，代价是一枚无主的键留在盘上。
- 左侧边栏导航区变成三条并列，动词不一致（「造一个新东西」与「去一个地方」混排）。这是刻意接受的现状，导航区的整体重命名不在本次范围。
- 「会话卡片在前台」成为聊天组件的一个入参，`Ctrl+F` 与空格两个动作据此失效。它是一个实现判据，不进 `GLOSSARY.md`，但下一个往聊天里加快捷键的人必须知道它存在。
- 后续迁移（频道、技能、模型配置等）会逐个把右栏按钮变成侧栏导航项，右栏面板的成员数将持续下降。这件事要不要最终收回右栏，本篇不作判断。

**参见**：ADR-0016「定时任务是面板视图」（本文废止其中"定时任务是右栏面板视图"这条 Decision，容器与页栈的其余规则不变）、ADR-0024「面板视图的生命周期是一个 module」（本文只放宽 adapter 的 `kind` 约束，保活 / 释放 / 页栈 / 关闭确认仍由它拥有）、ADR-0002「面板标签条是面板开合的唯一状态机」（右栏的 toggle 与关闭规则，本文只在侧栏导航项上复用它的一条语义）。
