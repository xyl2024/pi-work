# 危险命令规则可配置，闸门的兜底与自保护不可配

危险命令确认网此前只有一个入口：手改 `~/.pi-work/config.yaml` 的 `dangerous_patterns.rules`。于是有两个失败面叠在一起——想配规则的人要会写 YAML 和正则；写错了也没有任何反馈，因为 `parseDangerousPatterns` 只校验形状，正则编译失败要到匹配那一刻才 `log.warn` 跳过（`lib/server/dangerous-patterns.ts`）。现在要在设置弹窗里给它一页可视化配置，于是这个配置项的**边界**必须一次说清，否则页面上每多一个控件，都是在给「闸门可以被静默关掉」开一条新路。

**我们决定**：设置里新增一页，可编辑的是**用户规则列表**与 `timeout_ms`；平台内置规则集在页面上只读展示；`lib/server/self-protection.ts` 那套硬红线不进这个页面（连只读列表都不放）。同时这一轮**不**引入「直接拒绝」这个动作——规则命中仍然只是让那次工具调用停下来问人，三值决定（allow once / allow similar / deny）不变。

这条边界的依据是三份既有立场，本文把它们合并成一条可引用的决策——代码里按项目约定不写注释，因此本文是这三份立场的唯一载体：内置集是 floor 而不是默认值（`lib/server/config.ts` 的 `DEFAULT_DANGEROUS_PATTERNS.rules` 是空列表，内置集仍然生效，「没有用户规则」绝不等于「闸门关闭」）；内置集存在的原因就是补用户规则的漏，它的来源是一次「默认零规则 = 闸门静默关闭」的事故；自保护是代码级红线而非配置，`lib/server/self-protection.ts` 不读 `dangerous_patterns`，也不由它驱动。

## Considered options

- **让内置规则逐条可停用**（`disabled_builtins: string[]`）或**整体可关闭**。给出去的是便利，收回来的是「闸门一定在」这条唯一的不变量。（修订 2026-10-26：会话级的**权限模式**允许人在单个会话里显式跳过确认，见 ADR-0021——那是 per-session、由人点出、可见常驻、默认关闭的一次豁免，不把这张网拆掉；本条否决的仍然是**全局**层面的整体可关闭。）内置集只有 9 条 bash + 6 条 PowerShell，且 pattern 特意收窄到只覆盖灾难性操作、放过同一工具的只读形态（`fdisk -l`、`Get-Partition`），误报窗口极小。真撞到误报，正确的动作是收窄规则本身。
- **把自保护也放进页面，标成只读**。只读标签挡不住误读：出现在设置页里的东西，用户默认它会变成可开关。它一旦看起来可配，「关掉它」就会成为一个迟早被提出的需求。
- **每条规则可选 `confirm` / `block`**。这是一次权限模型扩张，会把三值决定、会话级备忘、拒绝文案与 ADR-0001 的子代理快速拒绝全部牵进来，值得单开一篇决策，不该藏在「加个 UI」里。
- **纯可视化预设**（选命令 + 参数组合，不让人碰正则）。shell 语法无法用表单表达，而内置规则的形状恰恰是「同一工具放过只读形态」这类正则细节，表单表达不出来。
- **把 `dangerous_patterns` 加进 `SETTINGS_OWNED_KEYS`**，走 `PUT /api/settings` 的 patch。这样写入口能保持「只有一个」，但 owned key 的语义是「客户端持整份 config，diff 出变更的顶层 key」，而这页要展示的是**服务端算出来的生效集**（含平台分叉、含编译失败的那些规则），patch 形状给不了。独立路由另有先例：`/api/append-system`、`/api/profile`、`/api/subagents`、`/api/cwd-aliases`。

## Consequences

- **保存前必须全量编译，任一失败即拒绝提交并标红那一行。** 手改 YAML 时「一条坏正则只打一行 log」是对的（typo 不能把闸门或整轮对话搞挂）；一旦有了 UI，同样的行为就变成「用户以为配上了，其实从来没生效」。这个差异是本文最实质的一条约束。
- **规则名就是会话备忘的 key**（`InteractionGates.allowedRules` 存的就是它）。因此名字必须唯一、非空、且不得与内置规则同名：重名会让一次「总是允许」同时放行两条规则，也会让确认弹窗显示的规则名和用户以为的那条对不上。
- **规则顺序有语义，但只有一点点。** `matchDangerousCommand` 顺序遍历、首个命中者胜，而所有规则的动作都是同一个确认，所以顺序唯一可观察的效果是「同一命令命中时弹哪条规则的名字」，也就是用户点「总是允许」时记下哪个 key。UI 给上移 / 下移，并把这句话写进页面。
- **保存即生效，不涉及新建会话。** 匹配发生在每次工具调用的钩子里，`readConfig()` 按 mtime + size 失效，`effectiveRules()` 按 `平台 + rules 内容` 做缓存键。这页不该出现任何「需新建会话」的暗示。
- **「试一条命令」必须走服务端。** 结果分三档：不可配置的硬拦截 / 命中某条规则（标明是用户的还是内置的）/ 不命中。自保护那一档需要本进程的 pid 与监听端口，客户端算不出来；而一档在服务端、一档在客户端就会长出两份「什么叫命中」的真相。
- **测试框判的是生效集，不是正在编辑的那一条。** 用户的问题是「我这条命令会不会被拦」，答案取决于用户规则 + 平台内置 + 自保护三者的合成，放到编辑器里会诱导他以为在测单条正则。
- **用户规则清空时，页面必须直说内置集仍在生效。** 这是本页最危险的误读，也正是 `DEFAULT_DANGEROUS_PATTERNS.rules` 为空时内置集仍生效这条边界要被反复说出的原因（本文是这条边界的说明载体），UI 有义务说同一句话。
- 空 pattern 一律拒绝保存：`new RegExp("")` 编译通过且匹配一切，存进去等于每条命令都弹窗。灾难性回溯（ReDoS）则明确接受——命令串通常不到 1KB，而能改这份配置的人本来就能直接改规则本身，这个威胁模型里没有「攻击者塞入恶意正则」这一档。这个「接受」记录在本文（代码里不写注释），不要留成沉默的决定。
- 词条进 `GLOSSARY.md`：**危险命令规则**与**自保护**，且前者明确 `_Avoid_: 命令拦截`——规则本身只负责匹配，拦不拦由会话档位决定（无人值守档位见 ADR-0025）。

**参见**：ADR-0008（闸门是一个 module，配置不进 module）、ADR-0001（子代理默认快速拒绝）、ADR-0025（无人值守会话的档位是配置时刻的授权，不往规则上加动作）、ADR-0009（设置页的保存语义由输入形态决定；规则列表是自由文本，属待保存项）、ADR-0019（设置分区就是页）。
