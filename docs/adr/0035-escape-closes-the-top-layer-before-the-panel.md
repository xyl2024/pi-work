# Esc 先关弹层，再退面板

模型配置的图标网格、目录搜索等弹层都挂在面板内部。Esc 原本由面板的退栈守卫独占：用户在图标网格里按 Esc，被关掉的是整个提供商表单，网格还留在原地；用户以为「按了取消」，实际丢掉了刚填的内容。反过来，只要弹层打开，面板守卫又必须让路，否则一次按键会同时关掉弹层和面板。

**我们决定**把 Esc 做成一个显式的分层栈，并让所有面板守卫共用同一套判定：

- **一个栈**：`lib/client/escape-layer.ts` 提供 push / pop / active 三层接口，弹层挂载时 push 自己的 id，卸载时释放；栈顶即「当前最上层」。
- **先关弹层**：栈非空时，面板退栈守卫直接放行，Esc 交给弹层自己处理。
- **再退面板**：栈为空、焦点在面板内或 body 上时，守卫才 `preventDefault` + `stopPropagation` 并执行面板自己的动作（表单页返回、主从页清空详情、关闭面板）。
- **判定是纯函数**：`panelEscapeApplies` 只吃 `visible` / `focusInsideOrBody` / `layerOpen` 三个事实，面板只负责提供事实，不重新推导优先级。
- **焦点在别处就不抢**：焦点落在面板外的输入框时，面板守卫不动作，避免在聊天输入框里按 Esc 却关掉侧栏面板。

## Considered options

- **每个弹层自己监听并 stopPropagation。** 监听顺序取决于挂载顺序，弹层嵌套时谁先收到事件不可预测；`stopPropagation` 也挡不住在同一节点上先注册的守卫。
- **面板守卫自己判断「有没有弹层打开」。** 每个面板各写一份 DOM 查询，弹层换实现就会漏判；把事实收敛成一个栈才能一处修好。
- **Esc 永远只做一件事（只关弹层，或只退面板）。** 用户对 Esc 的预期是「退一步」；固定成单义动作会让另一半场景没有快捷键。

## Consequences

- 新增弹层必须 push id 并在卸载时释放，否则 Esc 会穿透到面板；这是新增弹层的固定成本。
- Esc 的语义从「面板自己的事」变成「面板与弹层共享的事」，所有面板都经由 `usePanelEscapeGuard` 接同一套判定，不再各自监听键盘。
- 焦点在面板外时 Esc 不生效，面板的「一键退出」需要在焦点位于面板内时才可用。

**参见**：ADR-0024「面板视图的生命周期是一个 module」（守卫挂在面板生命周期上，本文只决定按键的分层归属）、ADR-0034「跟会话有关进右栏，跟会话无关且要整块进主视图」（主从页的返回同样走本守卫）。
