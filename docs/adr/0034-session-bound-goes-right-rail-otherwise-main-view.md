# 跟会话有关进右栏，跟会话无关且要整块进主视图

主视图机制落地之后，下一个视图该放哪仍然靠临场争论：模型配置、技能、频道、记忆、Token 用量五个配置型工具继续挤在 420px 上下的右栏里，多级表单、长列表与三张图表都只能横向将就；而它们又跟上下文洞察、Git 差异这些真正随会话变化的面板共用同一条标签条、同一套按钮。与此同时，主视图的接线仍然只够装一个成员：离开守卫叫定时任务、角标表只有一项、导航区没有行数上限。结果是每搬一个视图都要把定时任务的接线抄一遍，或者干脆不搬。

**我们决定**用一条判定规则划开右栏与主视图，并把主视图机制做成可增长的形状：

- **判定规则**：跟当前会话有关、只需要一列 → 右栏**面板视图**；跟会话无关、需要整块区域 → **主视图**。会话绑定不是判据本身，而是结果的标记：搬完之后右栏的会话绑定集合覆盖全部剩余面板，MCP 作为既有例外仍留右栏。
- **主视图注册项带导航顺序**：`navPriority` 升序即侧栏顺序，定时任务排第一。侧栏导航项、命令面板命令、角标与渲染分支都从同一张注册表读。
- **导航区固定两行加三行主视图**：前两行固定为「新建会话」「助理」，其后最多三行主视图；主视图条目超出这三行时，最后额外接一行「更多」，就地展开、再点收起，展开状态不持久化。因此没有溢出时导航区是五行，有溢出时是六行。固定两行永不进溢出；激活项若落在溢出里，上浮替换可见区末位并把被顶掉的那条放回溢出。
- **导航排布是一个纯模块**：输入 kind 集合、激活项与可用行数，输出 `visible` / `overflow` / `expandedActive`。侧栏只负责画，不重新推导顺序。
- **唯一的离开入口**：一次询问带着「哪个视图」与「何种意图」（回会话、切到另一个主视图、视图内切换任务、二级页返回），视图把自己的判据注册进一张表，未注册的视图直接放行。命中「切换当前工作」的所有入口先过同一套确认；二级页返回不弹确认。
- **状态与挂载解耦**：主视图只挂载当前 kind 的 body，跨视图保留状态由面板视图状态容器保证；轮询挂在 store 的 `start` / `stop` 上，离开视图后角标仍实时。
- **公共外壳只抽一层**：主从双栏 + 按容器宽度在既有 720px 断点以下退化成单栏，抽成 `MainViewMasterDetail`；标题与返回仍走主视图头部注入。表单页占满整块的形状不预先抽成通用页栈。

## Considered options

- **继续按「配置型工具 / 会话型工具」划分。** 记忆与 Token 用量是只读仪表盘，模型配置是编辑表单，它们之间没有共同的交互形状；用「配置」当判据会把即将新增的只读主视图排除在外。
- **把会话绑定当判据。** 会话绑定描述的是「内容是否随选中会话变化」，不是「需要多宽」；MCP 会话绑定但只需要一列，正好是反例。把它当判据会先把 MCP 判错。
- **导航区不设上限，主视图多了就继续往下加。** 会话列表还要占地方，入口变成一列图标墙之后扫读成本比多一次点击更高。
- **「更多」弹浮层或独立菜单。** 浮层挡住会话列表，也丢掉「我现在在哪」的上下文；就地展开让导航区高度变化可见、可回退。
- **主视图也常驻挂载所有 body。** 每新增一个主视图就多一份常驻数据与轮询，且让「只挂当前」这条资源边界失守；跨视图保留状态本来就该由状态容器负责。
- **为五个视图预先抽通用页栈 DSL。** ADR-0033 已明确拒绝；本次只抽双栏外壳，页栈形状留给各视图自己的适配器。

## Consequences

- 新增主视图只改注册表的一项与一条渲染分支；导航顺序、命令、角标、离开守卫都从表里读。
- 排在第四位往后的主视图要多一次「更多」点击才能到达；顺序由注册表决定，用户不可调。
- 激活项上浮会临时改变「更多」里的内容与被顶掉的那条位置；这是为了让「你现在在哪」始终可见所付的代价。
- 主视图从「全部 body 常驻」变成「只挂当前」，刷新与切换不再多挂一份数据；跨视图的状态保留完全依赖各视图的状态容器不被释放。
- 定时任务轮询改由 store 生命周期拥有，离开视图后仍跑；`back_to_browse` 不再弹放弃确认（表单页的「放弃」按钮仍是明确动作），回会话、切换主视图与切换任务仍走同一套确认。
- 右栏与主视图的词条按判定规则收窄，后续迁移直接改写各自视图的描述，不再重新定义两个上位词。
- 导航区高度上限是刻意接受的限制：动词仍混排（造一个新东西与去一个地方），整体重命名不在本次范围。

**参见**：ADR-0032「定时任务是主视图」（本文细化其判定规则，并修订其「两侧都常驻挂载」与「入口与既有两条并列」两条）、ADR-0033「定时任务是主从双栏」（本文抽出它承诺不预先抽的公共外壳，并修订二级页返回的确认语义）、ADR-0024「面板视图的生命周期是一个 module」（状态保留与轮询仍归它拥有，本文只把启动时机与 body 挂载解耦）、ADR-0016「定时任务是面板视图」（判定规则回答了它当年为何放错容器，该篇的容器决策已由 ADR-0032 废止）。
