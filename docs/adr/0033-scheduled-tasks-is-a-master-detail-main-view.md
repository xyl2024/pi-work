# 定时任务是主从双栏，表单是唯一的页

定时任务在 ADR-0032 里获得了主视图这块整区域，但它带着右栏面板的形状搬过去：三级页栈（列表 / 详情 / 表单）一次只显示一屏，详情被切成四个 tab 且其中「概览」与「配置」内容大面积重复，运行记录被挤在最后、回复展开高度写死。主视图的宽度因此只换来更宽的空白，没有换来结构。同时，「有没有填了一半的表单」这条脏态确认挂在「关闭面板标签页」上——定时任务已经没有面板标签页，那条规则成了死代码，Esc 会静默清空草稿。

**我们决定**把定时任务主视图定为主从双栏，并把页栈压到两级：

- **左列是任务列表，右列是选中任务的详情**。任务列表是全局数据、本来就该常驻；任务详情与列表是主从关系，不是「点进去再退出来」的两个屏。选中任务因此从「页」降为视图状态（`selectedTaskId`）。
- **详情没有 tab**。上半是常驻摘要条（状态、cron、下次 / 上次、启停 / 编辑 / 立即运行 / 删除），下半整块是运行记录，运行记录内部再分「紧凑列表 + 选中那次的输出面板」。理由是运行记录才是打开一个任务时真正要看的东西，它需要一个稳定的位置和稳定的高度；而「概览」本来就是扫一眼的事，用一条摘要解决比用一页解决更对。原「配置」tab 整块删除——它的内容是表单的只读副本，「编辑」直达表单之后它没有存在理由。
- **编辑表单独占整块主视图**，内部两栏，只有「保存」和「放弃」两个出口。表单需要宽度才能两栏摊开，而「必须专心填的一块区域」这个语义与主视图的互斥模型天然一致。
- **页栈只剩 `browse` 与 `form` 两层**：`{ kind: "browse" }` 与 `{ kind: "form"; taskId: string | null }`。原来的 `root` / `detail` 两页与「同级页替换」（`isSiblingPage`）一并删除，因为「切换任务」不再是页栈操作。
- **离开表单只由一条规则判定**：`selectSchedulerLeaveConfirm({ intent, dirty })`，`intent` 是 `back_to_browse` / `select_task` / `new_task` / `leave_main_view`。脏就确认放弃，干净就放行；当前四种意图给出的是同一条确认，把 intent 写进签名是为了让这条规则有一个唯一的挂载点，而不是散在四个调用方里各写一次。
- **表单草稿不跨屏保留**。这废止 ADR-0032「表单草稿在进出主视图之间保留」这一条；列表筛选、搜索词、选中任务、选中的运行记录仍然保留。一段「存在 store 里的草稿」与「详情页显示的旧值」并存的第二真相，用户下次进来分不清哪个是真的。
- **退化按容器宽度**：主视图卡片自身宽度小于 720px 时退成单栏（列表占满 → 详情占满 + 返回），不看视口——侧栏折叠与终端分屏都会改变主视图的实际宽度。断点与列宽是一个纯模块，`useContainerWidth` 提供输入。

## Considered options

- **保留三级页栈，只把根页列表拉成宽表格**：横向跳屏的问题原样保留，用户扫一批任务、改一个任务仍要在两屏之间来回。
- **保留详情四个 tab，只换成下划线样式**：把重复内容搬宽，`Overview` 与 `Config` 的两份副本都要继续维护。
- **详情做三栏（列表 / 详情 / 运行记录）**：主视图在侧栏展开加终端分屏之后常常只有 900–1100px，三栏各自都太窄。
- **表单占右列、左列保留可见**：右列只剩 700px 上下，两栏表单调不开；且「边核对列表边改表单」在定时任务里并不是真实需求（核对的是运行结果，不是任务名）。
- **离开表单时静默保留草稿，下次进入表单恢复**（ADR-0032 原方案）：需要维护 `formBaseline` 跨层级存活，且与详情页展示的磁盘真值构成两个真相。
- **按视口宽度做 media query 退化**：主视图的实际宽度由侧栏与终端决定，与视口无关，会判错。

## Consequences

- 定时任务主视图内不再有 tab 组件，`TaskOverviewTab` 与 `TaskConfigTab` 两份重复内容随之消失；提示词与执行配置收进摘要条下方的可展开区。
- 「立即运行」从两处收敛到一处（摘要条）；运行记录区顶部那个删除。
- 脏态确认第一次真正会触发。ADR-0032 里「guard 一字不改」留下的空档被填上：guard 的宿主曾是面板标签页，而定时任务的宿主已经不是它。
- 运行记录的分档轮询判据（`runsVisible`）语义改变：从「运行记录 tab 是否可见」变成「当前页是 `browse` 且有选中任务」，因为运行记录现在是常驻主体。
- 主视图顶栏的返回文案从 `← 定时任务`（指目的地，动作是出发点）改成 `← 会话`；侧栏那条造会话草稿的导航项从「新建任务」改名「新建会话」，`New task` 一词从此只属于定时任务。
- 同一套组件要维护两种布局（`split` / `stacked`），代价换来的是窄窗口下不出现互相挤压的两栏。
- 后续把频道、技能等搬进主视图时，可以直接沿用「主从双栏 + 表单独占」这个形状，但本次不为它们预先抽公共容器。

**参见**：ADR-0032「定时任务是主视图」（本文细化其容器内的信息架构，并废止其中「表单草稿在进出之间保留」一条）、ADR-0024「面板视图的生命周期是一个 module」（页栈、保活、脏态仍归它拥有，本文只收缩页的种类）、ADR-0016「定时任务是面板视图」（窄面板形状的来源，已被 ADR-0032 废止）。
