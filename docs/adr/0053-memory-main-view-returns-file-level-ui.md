# 记忆管理主视图回归，但只做文件级操作

ADR-0051 决定移除记忆主视图，理由是旧 UI 与旧双库条目模型绑定，且认为「人直接用文件系统或让 agent 展示」即可。**我们决定**：为新的两级记忆模型重建一个**记忆主视图**，但形态刻意收窄：列出记忆目录下的文件（索引与各分类明细），点开按 Markdown 全文查看与编辑，支持新建分类明细文件、删除分类明细（删除时同步清理**记忆索引**中的对应行）。

## 为什么改判断

不是 ADR-0051 的论据错了，而是产品判断变了：旧 UI 被删是因为它绑在旧双库与条目 API 上，而「人不需要界面」是当时顺带接受的结论。实践表明对大多数人来说「直接用文件系统」门槛过高，记忆又是 Pi Work 少数由 agent 自主增长、用户无法从其他界面感知的数据——没有界面，用户连记忆里有什么都看不到。因此重建 UI，同时守住 ADR-0051 真正的核心：**写入路径不设防线**。

## 界面不做什么（与旧 UI 的分界）

- **不做条目级增删改**：不引入行级条目概念、条目 API 或格式约定，编辑就是编辑 Markdown 全文。
- **不复活防线**：不做保存前扫描、不做索引预算校验、不做漂移检测——这些是 ADR-0051 明确移除的东西，UI 的存在不改变「信任 agent」的立场。
- **不加锁**：agent 在会话里实时读写记忆，UI 不做文件锁或自动合并；只在保存时若文件 mtime 晚于打开时刻，用双栏只读比对对话框（用户版本 vs 磁盘版本）让用户二选一：覆盖保存或放弃改动——人不看差异无法做决定。
- **UI 保证一致性**：agent 靠注入的**记忆管理指引**自觉同步索引，UI 是人的工具，不走自觉约定——删除分类明细时由 UI 顺手清掉索引中对应行。

## Consequences

- 主视图注册表新增 `memory`，与 scheduler / modelsConfig / skills / channels / tokens 并列。
- 新增文件级读写 API（列表、读、写、新建、删除），只操作 `~/.pi-work/memory/` 目录，路径不逃逸。
- 未启用记忆时入口仍显示：空态页引导去设置开启，API 一律拒绝——入口消失会让功能不可发现，空态更诚实。
- GLOSSARY 的「记忆主视图」条目记录其边界；ADR-0051 中「人直接用文件系统或让 agent 展示」的部分由本 ADR 取代，其余（通用工具、防线移除、迁移）继续有效。
- 参见 ADR-0051（写入交还通用工具）、ADR-0052（两级注入语义）。
