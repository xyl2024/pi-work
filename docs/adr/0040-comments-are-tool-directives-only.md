# 注释只剩工具指令，CSS 也不例外

`d7dc9c97` 把全仓注释从 15.2% 降到 0.04%（766 个文件、约 2.4 万行），并把「代码里不写注释」写进了 `AGENTS.md`。它当时只清 `ts/tsx/mts/js/mjs`，CSS 没动：`app/globals.css` 仍是 1,564 行里的 310 行注释（约 20%），`ask-user-questions-panel/constants.ts` 与 `LoginForm.tsx` 的 CSS 模板字符串里还有 6 块散文。规则因此有两个洞：CSS 算不算代码没写清，模板字符串里的 CSS 又靠「字符串是数据」的豁免绕过。

更要紧的是这条约定**无法执行**：`eslint.config.mjs` 里没有任何与注释相关的规则，全靠人和 agent 自律。purge 之后 345 个提交只回潮了 2 条注释（都是 `eslint-disable`），说明自律当下有效，但这不是机制。

**我们决定**把边界定成可执行的两条：

- **注释许可名单只有四类工具指令**：`eslint-disable` / `eslint-enable`、`@ts-ignore` / `@ts-expect-error` / `@ts-nocheck` / `@ts-check`、`@vitest-environment`、`/** @type */`。名单之外的一条注释即失败，不存在「这行注释很有价值」的例外——有价值的决策进 `docs/adr/`，有价值的行为进 `tests/`。
- **CSS 与模板字符串里的 CSS 同样零注释。** 「为什么这行样式长这样」不属于样式数据：它要么由全局约束承担（ADR-0041 收了那批非显然的），要么由命名、变量名与设计本身承担。CSS 也不再是「唯一可以写理由的地方」。
- **边界由 `tests/unit/code-comments.test.ts` 执行。** 它用 TS 解析器把字符串、模板字面量、正则字面量与 JSX 文本抹成空白，再在剩下的文本里找注释语法（所以 `http://`、`/* */` 这类字符串内容不会误伤）；模板字面量里形如 CSS 的片段（含 `{` 与 `;`）单独再扫一遍块注释；`.css` 文件直接扫块注释。报错精确到 `文件:行`。

这次清理本身是纯删除：`app/globals.css` 删 311 行、两个模板字符串删 16 行，用 postcss 对比删除前后的 selector / at-rule / declaration 序列，1098 条完全一致。

## Considered options

- **只留在 `AGENTS.md` 里。** 这正是缺口的成因：一条没有执行者的规则，在 agent 换代时等同于不存在。
- **用 ESLint 自定义规则。** 要为「禁止注释」写一个本地插件，比一份源码守卫测试重，且守卫测试与本仓既有的测试路径一致（`tests/README.md` 里那些 Electron 外壳源码守卫）。
- **CSS 保留注释（本文的上一版）。** 结果是同一份代码里两种相反的规矩并存，而 CSS 里的事实（Chromium 把全透明 thumb 当作不存在、CodeMirror 的选区层压在内容之下）恰恰是最值得搬进 ADR 的那类——它们当时散落在 89 个块里，读哪段样式才知道哪条约束。
- **用注释摘要把 ADR 引到代码里。** 这正是 `a4eb63ed` 反向做掉的事——每一行 `// 见 ADR-00XX` 都是会过期且无人维护的指针。

## Consequences

- 新增 JS/TS/CSS 注释必须同时改许可名单，等于强制一次显式的「我要破这条规矩」的决策；`pnpm test` 会拦下来。
- 守卫只看语法层：写在字符串里的散文（CSS 之外的 SQL、内联 HTML）不被拦截，那属于数据，判断仍靠人。
- 样式里的非显然约束从此只有 ADR-0041 一个家；新增这类约束时先看能不能并进去，而不是就地写一行注释。
- `AGENTS.md`、ADR-0041 与本守卫必须同时更新，否则规则的多份载体互相矛盾。
