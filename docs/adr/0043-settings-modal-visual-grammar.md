# 设置弹窗的视觉语法：浮起的双栏面板与行式设置项

ADR-0019 把设置弹窗定成「左侧导航 + 右侧单页」，但只规定了信息架构，没有规定这一页长什么样。结果每一页各自发明版式：有的用 `h4` 当小标题、有的用带边框的卡片、有的把开关和文字横在一条自由摆放的 flex 里，控件皮肤也各写各的——同一份设置面板里出现四五种输入框高度、三种圆角、两种按钮悬停行为。导航只有文字，视觉上读不出「这是哪些分区」，分组标题与分区标题的字号、字重、间距也没有共同基准。

这次把「长什么样」收成一套可复用的语法，参考 DeepSeek Harness 的设置面板：**一个浮起的面板、一条带图标的导航、右栏一行一件事。**

**面板是浮起的两栏。** 宽 `min(920px, 100vw - 40px)`、高 `min(760px, 100vh - 72px)`、圆角 14、一层大阴影加一层贴边阴影，遮罩带 6px 模糊。左栏 216px、底色 `--bg-panel`、与内容区之间一条细线；它自带顶部标题「设置」，导航项按注册表分组列出，每项 34px 高、8px 圆角，选中态是 `--bg` 底加一层微阴影——左栏是略暗的面，选中的一格是「浮起来的纸」，与右栏同色。未落盘的分区在导航项右侧点一个 6px 的 `--warning` 圆点。

**图标是注册表的一部分。** `SettingsSectionSpec` 新增 `icon` 字段，类型是 `IconName`，导航与页不各查一份图标表。新增分区而没给图标，类型检查失败，和「新增分区没写页」是同一种编译期守卫。

**页标题离开滚动正文，钉在右栏顶部。** 右栏是一个固定头部（页标题 + 右上角关闭）加一个独立滚动区；标题仍从注册表取，页的 `aria-labelledby` 指向它，所以「导航高亮、页标题、注册表」依旧只有一个事实来源。标题之所以不随正文滚走：一页设置往往比一屏长，滚到一半时「我在哪一页」只能靠导航高亮反推，而钉住的标题把答案留在视线里。

**右栏正文是一列行。** 新 `SettingsGroup` / `SettingsRow` 定义了唯一的行语法：每组一个小号大写组标题；行是「标题 + 可选一句说明」在左、控件在右，行间一条 `--border` 细线，组间 26px；`SettingsRow stacked` 把控件换到标题下方，供文本域、密钥、代理地址这类需要整行宽度的输入。说明只解释「这个开关改变什么」，不复述控件当前值——当前值由控件自己显示（开关的开合、下拉的选项）。页面级提示统一走 `SettingsNote`：灰色说明、错误、成功三种语义色。

**控件皮肤收进一份 CSS Module。** 输入框、下拉、文本域、按钮、分段选择器共用 `controls.module.css`：34px 高、8px 圆角、`--bg-panel` 底、透明边框，悬停换 `--bg-hover`，聚焦时边框转 accent 并加一圈 3px 的半透明 focus ring（全局焦点 outline 被剥掉了，这里补回可见焦点，见 ADR-0041）。主按钮维持 accent 实心，次按钮从「描边」改成「填充」，危险按钮平时是无底色的灰字、悬停才是 `--error-bg` 的红——危险动作不该在静态界面上抢注意力。所有悬停与焦点状态从 React 的 `onMouseEnter` 挪进 CSS。

**主题页用卡片而不是分段控件。** 两个 96px 高的卡片（太阳／月亮图标 + 文案）并排，选中卡片用 accent 描边与 `--bg-panel` 底；点击坐标传给 `setPreset`，复用已有的 view-transition 圆形展开。语言留在行里，用紧凑的分段控件。pi-work 只有浅色与深色两个预设，所以卡片只有两张，不造第三张「跟随系统」来对齐参考实现。

## 哪些页改成了行，哪些没改

改成行语法的是：主题与语言、右侧按钮、助手、划词工具栏、界面音效、文件预览上限、记忆、上下文压缩、Agent 重试、建议问题、网络代理、DeepSeek Key、个人资料、关于、子代理列表、追加系统提示词。它们原本是同一种东西——一组开关、下拉、数字与按钮。

保留自有版式的是：危险命令（规则编辑器 + 试用命令）、子代理编辑器（独立弹窗里的表单）、Toast 测试台（开发者页的按钮墙）。它们不是「一组设置项」，行语法套上去只会把编辑器切碎。它们仍共享同一套控件皮肤与页面外壳，所以看上去仍是同一个面板里的页。

## Considered options

- **只换控件皮肤，不动版式。** 最省事，但页内仍然是「h4 + 卡片 + 自由 flex」，行与行的高度、说明的位置、分隔线有无全靠每页自觉，用户看到的仍是拼装感。
- **照搬参考实现的 800×800、188px 导航、无分组、纯图标。** 参考实现只有四个分区；pi-work 有十八个，跨五个组。去掉分组会让「Agent 的七个分区」和「外观的六个分区」混成一条长队；纯图标导航则要求用户先学会十八个图标。
- **把页标题留在滚动正文里。** 这是 ADR-0019 当时的形态。标题会随正文滚走，长页面里「我在哪」只能看导航；挪进固定头部后，标题与关闭按钮共享同一条视觉基线，也不再每页各写一遍标题。
- **给每个自定义编辑器也强行套行语法。** 规则编辑器需要一块带编号的规则表与一条试用命令输入；套进行里会让「标题在左、控件在右」变成一句空话。
- **窄屏折叠导航或改成移动端抽屉。** ADR-0019 已把窄屏结构调整留给以后；这次只补两条兜底：720px 以下面板贴近视口、行改为上下堆叠，导航仍是左栏。

## Consequences

- 新增设置分区要在注册表里同时给 `labelKey`、`group`、`icon` 与页渲染器；四处缺一都在编译期报错。
- 新页优先用 `SettingsGroup` / `SettingsRow` / `SettingsNote`，而不是自己写 `h4` 与卡片。行语法不为某个页的例外开洞；确实不是「一组设置项」的编辑器才保留自有版式。
- `controls.tsx` 导出的行内样式常量（如 `inputStyle`）不再存在，调用方改用组件与 `className`；`SETTINGS_RADIUS` 仍是 8，供少量卡片复用。
- 面板的几何、行的节奏与控件皮肤只写在三个 CSS Module 里；它们没有注释，读不出来的约束（为什么用 `--bg-panel` 当输入底色、为什么需要 focus ring、为什么标题钉在头部）住在本文与 ADR-0041。
- 主题卡片点击会触发 view transition；`prefers-reduced-motion` 的用户仍由 `useTheme` 直接切换。
- 参考实现里「打开配置文件」这类面板级动作没有跟进：pi-work 没有对应的安全入口，凭空造一个按钮只会得到一次性入口。
